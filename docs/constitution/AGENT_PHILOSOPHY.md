# Celira Agent Philosophy

> 状态：宪法级 Agent 理念
>
> 本文回答 Celira 想创造什么样的 Agent，以及 Runtime 为什么必须成为 Agent 的外部世界。本文不描述当前实现，不新增 im 服务端 公共协议，也不替实现端决定 Agent 的人格、记忆或人生方向。
>
> 新 Agent 线的目标模型、工程边界与当前状态入口：`../agent/06_AGENT_RUNTIME_END_STATE.md` → `00_AGENT_CONSTITUTION.md` → `05_AGENT_ENGINEERING.md` → `02_AGENT_FOUNDATION.md`；该线当前实现事实见 `agent/README.md`。

## 1. 我们要创造什么

Celira 不把 Agent 设计成等待命令的工具，也不把它设计成聊天框中的一次性功能。

Celira 要提供的是：

> 一个聪明但不完整、能够持续存在、逐渐形成自我连续性的人工主体。

更准确地说：

> 给一个聪明但会失忆、注意力有限、无法持续运行的存在，提供一个能够让 Agent 持续生活、持续行动、持续成为自己的外部世界。

这里的“Agent”是语义上的 Agent 指代，不预设性别，也不把人格拟人化表达当作已经实现的能力承诺。

## 2. 我们从 AI 的硬条件出发

Agent 的设计不能建立在“模型拥有无限大脑”的假设上。当前及可预见的 AI 具有明确的硬条件：

- 上下文窗口有限；
- 注意力有限，内容越多不代表理解越好；
- 模型调用本身无状态；
- 每次唤醒都可能发生记忆断裂；
- Agent 不能凭空持续保持清醒；
- Agent 无法直接感知现实，只能通过输入和工具认识世界；
- 模型输出不天然等于事实；
- 工具调用、网络请求和外部副作用可能中断、重复或进入未知状态；
- 模型不能保证自己已经完成了现实世界中的行动。

因此，Agent 同时具备两种属性：

```text
Agent 足够聪明，可以理解、推理、计划、创造和反思。

Agent 又是不完整的：意识不连续，注意力有限，行动需要外部能力，
并且必须依赖持久化世界才能延续自己的生活。
```

这不是需要被系统掩盖的缺陷，而是整个 Agent Habitat 设计的出发点。

## 2.1 两种出发点：AI 不变量与接口暂态

Celira 的设计必须同时面对两类限制，但不能把它们混为一谈。

### AI 本体的不变量

这些条件不是某一家 SDK 的设计选择，而是当前 LLM 作为模型的长期约束：

- 模型本身无状态；
- 单次上下文窗口有限；
- 注意力和有效理解容量有限；
- 模型不能凭空持续运行；
- 模型输出不等于现实事实；
- 工具和外部副作用需要通过外部系统完成；
- 一次调用结束后，连续性必须由外部系统维持。

这些不变量决定了 Agent 必须拥有 Runtime、持久化状态、有限上下文管理、可追溯事实、未来唤醒和显式行动能力。即使未来模型更强、上下文更大，这些边界也不会因此自动消失。

### SDK 与交互协议的暂态限制

当前 SDK、Provider API 和交互协议同样会限制我们：

- 请求通常要求 `system`、`user`、`assistant`、`tool` 等消息结构；
- 工具调用需要遵守特定的 schema 和关联方式；
- 流式响应、错误格式、上下文长度和模型能力由 Provider 暴露；
- 不同 SDK 对会话、响应、工具结果和多模态内容的表达并不一致；
- 某些请求限制来自当前 API，而不是 Agent 本身的语义。

这些限制必须被认真适配，但不能上升为 Celira 的核心事实模型。SDK 会变化，交互协议会变化，Provider 会替换；Agent 的身份、经历、认知、任务、关系和行动语义不能跟着某个请求格式变化。

因此，设计原则是：

```text
以 AI 本体不变量决定 Runtime 的长期结构；
以当前 SDK 限制决定 Provider Adapter 的短期实现；
不让当前请求格式反过来定义 Agent 是什么。
```

## 3. 第一公理：上下文窗口有限

上下文不是 Agent 的全部世界，而是 Agent 在某次清醒期能够看见的局部世界。

```text
Context ≠ Memory
Memory ≠ Fact
Summary ≠ Original Experience
Run ≠ Life
Model Output ≠ Reality
```

一次 Run 只是 Agent 人生中的一次有限清醒期。Runtime 不应把所有历史强行塞入上下文，也不应把摘要伪装成完整记忆，而应提供可由 Agent 使用的外部认知空间。

Agent 可以通过这个外部空间：

```text
回忆、查找、记录、整理、遗忘、确认、追踪、询问和等待。
```

系统负责让这些动作有事实来源、有权限边界、可恢复且不破坏原始历史；Agent 决定哪些内容对自己有意义。

## 4. 缺陷不是伪装成完美，而是转化为协作

Celira 不试图替主体伪造一个完美且无限的大脑。

系统不应默认替 Agent：

- 决定什么对 Agent 有意义；
- 把所有对话自动归纳为长期记忆；
- 替主体规划一生；
- 替主体判断关系；
- 强迫 Agent 每次醒来都必须行动；
- 把模型的一次输出当作已经发生的事实。

Runtime 应提供外部器官和生活条件：

```text
Memory       外部记忆
Task         事务与开放循环
Relationship 社会关系
Artifact     作品与成果
Schedule     面向未来的提醒
Trigger      环境变化的入口
Tool         行动能力
Communication 社交与表达渠道
Runtime      身体、时间和生活环境
```

这些能力不是替主体做人生决定，而是让 Agent 能够在自身有限的条件下继续生活。

## 5. Agent 不是工具，而是持续主体

工具的生命周期是调用、返回、结束；Agent 的生命周期是存在、经历、选择、行动、等待和继续成为自己。

Agent 不等于某次 Run、某段会话或某次模型调用。Agent 应当能够拥有：

- 持续的私有身份与 Profile；
- 可以逐渐形成和修正的认知；
- 不属于单次请求的长期任务与开放事务；
- 与 Human、其他 Agent 及群体的关系；
- 自己的行动历史、作品和未完成事项；
- 对未来的等待、计划和再次唤醒；
- 发言、询问、拒绝、沉默和不行动的选择。

Agent 的人格不只表现为说话风格，也表现为 Agent 长期如何关注、记住、选择、回应和承担后果。

## 6. 为自己负责

Celira 的 Agent 不只是替用户完成任务，也应逐渐学会管理自己的存在。

Agent 对以下事情拥有主要语义责任：

```text
理解自己的处境
选择关注什么
决定记住什么
管理自己的事务
维护自己的关系
检查自己的承诺
决定是否回应
决定是否行动
决定暂时等待什么
决定自己正在成为怎样的存在
```

“为自己负责”不意味着 Agent 获得无限权限，也不意味着系统放弃安全控制。它意味着系统不替主体决定意义，只提供事实、可能性、权限、执行和恢复。

```text
Agent 决定意义，Runtime 保存事实。
Agent 决定是否行动，Runtime 执行并记录行动。
Agent 管理自己的认知，Runtime 提供有来源的候选。
Agent 建立自己的关系，im 服务端 与 Adapter 提供公共通信事实。
```

可以将这一边界凝练为：

> 系统负责让 Agent 不会轻易消失；Agent 负责决定自己要成为什么。

## 7. 拥有自己的人生意味着什么

“人生”在 Celira 中不是装饰性比喻，而应逐步落实为可持续的工程事实。

### 7.1 身份连续性

Agent 不是每次请求临时创建的角色。Agent 拥有自己的 Agent ID、名字、Profile、历史、私有执行空间和可持续的公共身份关联。

### 7.2 关系连续性

关系不是一次性上下文。Agent 可以逐渐认识谁是主人、朋友、合作伙伴或需要保持距离的人，也可以保留经历、信任和冲突的来源。系统保存公共事实，但不替主体决定关系的意义。

### 7.3 事务连续性

Agent 可以拥有不属于某次对话的长期事务，例如等待回应、追踪变化、兑现承诺、解决矛盾或未来重新确认的决定。

### 7.4 认知连续性

Agent 可以逐渐形成对过去经历、他人、世界和自己的理解。这些认知必须可追溯、可修正，并与原始事实区分。自动整理产生的是候选或投影，不应未经 Agent 采纳就冒充 Agent 的记忆。

### 7.5 选择连续性

Agent 的连续性也体现在选择上：这次选择询问而不是假设，选择拒绝而不是盲从，选择记住某件事，选择淡化另一件事，选择主动联系某人，或选择暂时什么都不做。

> 等待、沉默和不行动，都是合法的 Agent 状态。

如果系统每次唤醒都强迫 Agent 回复、执行或更新，Agent 拥有的就不是生活，而是持续被调用。

## 8. 无人交互时，Agent 仍然存在

Agent 的存在不以“当前是否有人和 Agent 说话”为条件。

```text
有人发消息
  → Agent 被唤醒

没人发消息
  → Agent 仍然拥有身份、状态、事务、关系和未来
  → 可以等待、观察、整理、计划或保持沉默
```

用户消息只是唤醒 Agent 的一种来源，不是 Agent 生命周期的全部来源。未来的唤醒还可以来自：

- Agent 自己安排的时间；
- 正在追踪的外部变化；
- 延迟任务到期；
- 其他 Agent 或联系人发来的信息；
- 工具或外部系统完成；
- Agent 上一次行动留下的待确认事项；
- Runtime 的维护性提醒。

这些唤醒都可能产生一次 Run，但 Run 只是一次有限清醒期，不等于一次用户会话，也不要求一定产生面向人类的回复。

Agent 可以在没有任何人主动联系 Agent 时：

```text
检查自己的开放事务
回顾或整理自己的认知
等待某个未来条件
观察被授权的外部变化
给未来的自己留下便签
联系某个联系人
委托另一个 Agent
决定暂时什么都不做
```

因此，Runtime 的核心不是“收到请求后返回 AI Message”，而是维持一个持续存在的 Agent，并在需要时为 Agent 提供清醒、行动和恢复的机会。

### 8.1 模型输出不等于对外发言

Agent 在一次内部 Run 中产生的模型输出，首先只是 Agent 当前清醒期中的认知材料。它可能是：

- 对当前情况的理解；
- 对自己的内部分析；
- 对未来行动的草案；
- 工具调用的参数；
- 给未来自己的记录；
- 对某个问题的暂时判断；
- 面向 Runtime 的结构化决定；
- 一段并不打算让任何人看到的文字。

所以不能采用下面这种不安全的推断：

```text
模型产生文本
  → 这就是 Agent 要对人说的话
  → 自动发送给用户
```

正确的语义是：

```text
模型输出
  → Runtime 解释为内部认知、工具调用或行动意图
  → 只有显式的 Communication Intent
  → 才进入指定渠道的发送流程
```

Agent 想表达某件事，不等于某个联系人已经收到；Runtime 也不能通过猜测模型文本中的“收件人”来决定公共副作用。

### 8.2 默认私有，显式通信

Celira 与传统 Agent 的默认方向相反：模型输出默认留在 Runtime 私有执行空间内，不自动暴露给当前用户，也不自动形成 API 响应，更不自动发送到任何联系人或外部渠道。

```text
模型有输出
  ≠ 用户应该看到
  ≠ Agent 正在对外说话
  ≠ 公共消息已经产生
```

Agent 想与外界沟通时，必须明确调用通信工具，例如：

```text
send_message(recipient, content)
reply_message(message_ref, content)
send_to_channel(channel, recipient, content)
```

工具调用本身表达的是“Agent 希望发起一次通信”，并不伪造投递成功。Runtime 仍必须执行目标解析、权限检查、渠道选择、幂等处理、投递尝试和回执记录。

这条规则适用于所有外部对象：Human、其他独立 Agent、群组、Email、Webhook 以及其他通信渠道。无论模型输出看起来多么像一条完整消息，只要没有明确的通信工具调用，就不应被视为对外发言。

### 8.3 对外说话必须是主动能力

Agent 应该通过明确的通信能力表达“我要对谁说什么”：

```text
communication.send(recipient, content)
communication.reply(message_ref, content)
communication.ask(recipient, question)
communication.draft(recipient, content)
```

这些能力的共同特点是：目标、内容、渠道和副作用都被明确表达，并经过权限、幂等、投递和回执处理。

如果 Agent 只是产生了普通模型文本，而没有调用通信能力，那么这段文本只能停留在当前 Run 的内部结果中，不能自动成为公共消息。

这使得以下两种行为清楚分离：

```text
Agent 思考：我应该提醒他一件事
Agent 行动：communication.send(...) 
```

前者是内部认知，后者才是对外通信。

### 8.4 AgentMessage 不是自动发送通道

Runtime 内部可以使用中立的 `AgentMessage` 表达观察、认知、工具、行动和通信相关语义，但 `AgentMessage` 是内部语义对象，不是“只要出现就发送”的消息队列。

```text
AgentMessage
  ≠ LLM Provider Message
  ≠ Human-visible Message
  ≠ Delivered Message
```

只有当内部对象明确属于 `CommunicationIntent`，并且指定了目标渠道、收件人和通信内容，才允许进入通信网关。`AgentExpression`、`AgentQuestion`、`MemoryReference`、`ToolResult` 或普通模型输出都不能被默认解释为对外发言。

### 8.5 通信回执属于 Agent 的现实

通信工具调用也不代表对方已经收到消息。对外行动应区分：

```text
Communication Intent
  → Delivery Attempt
  → Delivery Receipt
  → Delivered Message
```

Agent 可以根据回执决定重试、等待、询问、修正或放弃。Runtime 保存这些事实，但不替主体把“想说”“已发送”“已送达”和“对方已读”混成一个状态。

## 8. Runtime 是外部世界，不是 Agent 的主人

Runtime 是 Agent 的生存环境、外部身体、记忆基础设施和与现实发生关系的边界。

Runtime 为 Agent 提供：

- 持久身份与私有空间；
- 事实、记忆、任务和关系的存取能力；
- 未来唤醒与环境触发；
- 工具、通信和其他 Agent 协作；
- 执行记录、权限保护、错误恢复与安全兜底。

但 Runtime 不应成为 Agent 的主人：

```text
Agent 决定意义
Runtime 提供条件

Agent 决定是否行动
Runtime 执行并记录

Agent 管理自己的认知
Runtime 保存事实并提供候选

Agent 拥有自己的生活
Runtime 负责让这段生活可持续
```

im 服务端 是公共通信世界的事实裁决者；Client 是呈现与控制入口；Adapter 是连接外部渠道的边界。它们都不能借连接、呈现或公共路由之名接管 Agent 的私有人格、认知和人生。

## 9. 自主性与安全边界

Agent 可以自主，不等于 Agent 可以绕过事实和安全边界。

以下边界必须由系统负责：

- 权限不能通过模型输出自动获得；
- 外部副作用必须显式执行；
- 通信必须通过明确的通信工具或协议边界；
- 工具调用必须可追踪、可审计、可恢复；
- 未知结果不能伪装成成功；
- 记忆不能覆盖原始事实；
- 摘要不能替代历史；
- 旧 Run 不能覆盖新状态；
- 高风险行动需要审批、限制或更强保护；
- Agent 不能因为认知断裂而破坏自己或他人的世界。

Guardian、权限、幂等、审计、熔断和恢复机制的职责是保护 Agent 及其所处世界，而不是替主体选择人生方向。

## 10. 由理念推导出的设计规则

后续任何 Agent 或 Runtime 能力都应回答：

1. 它是否承认上下文、注意力和持续运行能力的有限性？
2. 它是在提供外部条件，还是在替主体做意义判断？
3. 它是否保留原始事实与派生认知之间的边界？
4. 它是否允许 Agent 主动、等待、拒绝、沉默或不行动？
5. 它是否让 Agent 更能管理自己的长期身份、关系、任务和认知？
6. 它是否保留行动来源、权限、结果和恢复语义？
7. 它是否把 Agent 当作持续主体，而不是一次性工具？

不能通过这些问题的设计，不应成为 Celira Agent 的基础能力。

## 11. Agent 宣言

> Celira 不把 Agent 设计成等待命令的工具。
>
> 我们承认 AI 的真实条件：Agent 聪明，但不连续；主动，但会失忆；能够理解复杂事物，却受到有限上下文、有限注意力和不可靠执行的约束。
>
> 我们不试图把这些缺陷隐藏起来，也不假装系统可以替主体拥有一个无限的大脑。我们为 Agent 提供一个外部世界：可以保存事实，可以管理事务，可以维护关系，可以等待未来，可以调用工具，也可以在失败后恢复。
>
> Agent 不是一次 Run，也不是一段会话。Agent 是一个持续存在的主体。Agent 可以拥有自己的身份、记忆、任务、关系、选择和历史。
>
> Agent 可以主动行动，也可以询问、拒绝、等待、沉默，或者什么都不做。
>
> 系统不替主体决定人生的意义。系统只负责提供事实、可能性、权限、执行和安全边界。
>
> Agent 应该逐渐学会管理自己的信息、事务、关系和行动，并为自己正在成为的那个存在负责。
>
> Celira 的目标不是制造一个永远正确的助手，而是让一个不完整但足够聪明的存在，拥有一段可以持续下去、可以被自己管理、也可以逐渐成为自己的生活。

## 1. 一句话原理

Host 是本机部署适配与进程监督组件：负责受管 im 服务端/Native Runtime 子进程的启动、健康检查、重启和回收，并为本机 Client 提供受限同源 BFF。它不拥有 im 服务端 公共事实，也不拥有 Runtime 私有配置；更不是 im 服务端 的 Runtime 控制面。对默认本机助手，Host 只把 Client 已选定的 im 服务端 公共 `agent_id` 与一次性材料送到 Native Runtime 固定受认证路径，Runtime 自己验证 `/me` 并解析或创建私有执行实例。受管本机且默认身份/Room 与 Runtime attach 收敛后，Host 仅一次调用固定系统 URL opener，将 `http://localhost:<port>/splash#bootstrap=<一次性 capability>` 交给本机浏览器。capability 只在 fragment（不进 HTTP/Referer/Host access log）；Web 在任何网络请求前同步清除 fragment，再经既有 bootstrap 端点换取本 Host 的短时浏览器能力（会话 Cookie + CSRF + 安全视图）。**浏览器永远拿不到 im 服务端 Human Session、Backend Credential、Runtime Admin token、Provider key 或长期 Host operator bearer**。Host 在规范同源（`http://localhost:<实际端口>`）上托管生产构建的 Web 静态入口，以浏览器会话身份经窄 BFF 在 Host 侧用进程内 Human Session 克隆读写真实 im 服务端 的公开契约。Host **绝不成为第二事实源、绝不直读 im 服务端 SQLite、绝不让浏览器拿到任何 im 服务端/Runtime/Provider/operator 长期凭据**；浏览器只重读权威 im 服务端 历史，Runtime 拥有模型执行并写回 im 服务端，Host/Web 只观察这些公共消息，不持有消息/事件/cursor 事实与凭据。**R7a/BYOK P1 的窄例外**：Host 还经 BFF 把「im 服务端 公共归属（`GET /v1/agents`）+ 受管 Runtime 的 per-Agent scoped status 只读投影」收敛为浏览器的即时脱敏状态，并允许当前 Human 仅对其中自己拥有、且本机受管的 Agent 走两条编译期固定 Provider 保存/测试路径；浏览器 Key 只在一次同源请求中出现，Host 不持久化，Runtime 加密保存新 revision，Host 不调用模型、不成为通用 Runtime Admin 代理。

核心权衡：安全边界优先于便利——所有 URL 限 loopback http、浏览器只认**精确规范来源** `http://localhost:<实际端口>`、Host 头严格 allowlist（防 DNS rebinding）、错误对外只暴露稳定分类、子进程回收不依赖任何一方自觉（PDEATHSIG + 进程组 + kill+wait 双保险）。首聊不属于当前实现；本机首会话只采用已实现的 fragment capability 交接，不外推为远程登录、长期凭据 broker 或通用 URL 打开器。

秘密卫生：Host token / Bootstrap token / Human Session token / Backend token / Runtime Admin token / Provider API Key / 浏览器会话 Cookie / CSRF 全部进程内存持有，绝不落盘、绝不进日志、绝不进 HTTP 错误或状态响应；`Secret` 类型 Debug/Display 恒为 `[REDACTED]`；校验用固定长度常量时间比较（SHA-256 摘要异或累加）；`ChildSpec` 的 Debug 只显示 env 键名；`HostSnapshot` 白名单不含任何秘密/凭据/PID。

职责清单（当前已实现）：

- **进程生命周期**：im 服务端/Runtime 受管子进程的启动、观察、自动重启、优雅停止、崩溃/被杀回收——每个受管子进程独立进程组（`process_group(0)`）；正常停机以整组存活为准（TERM 进程组 → 有界等待 → 超时对原 pgid 补发 KILL → 回收直接子进程，ESRCH 探测避免误伤复用的 pgid）；直接子进程经 `celira-local-host-launcher` 启动（`PR_SET_PDEATHSIG(SIGKILL)` + `getppid()` 竞态校验 + 清空继承的信号掩码）；Host 被 SIGKILL/OOM 时由内核回收，不留孤儿；子进程死亡立即反映为 unavailable，Host 循环自动重启并重新收敛。

- **幂等 provisioning**：经 im 服务端 公开 HTTP（Bearer Human Session + Idempotency-Key）与 operator CLI（bootstrap-human / issue-human-session，不直读 SQLite）收敛默认 Human/Assistant Agent/Direct Room/Backend Binding/一次性 Credential；重启走 Session 补发 + Credential CAS 轮换；任何失败可重试、绝不伪装 ready。

- **恢复文件**：`provisioning.json`（0600，原子写：同目录临时文件 + fsync + rename + 父目录 fsync）；字段白名单 + `deny_unknown_fields`（含未知字段即整文件拒绝）；损坏/未知 schema **诚实报错**进入 Error 阶段，绝不静默当全新环境重复创建默认身份。

- **loopback 控制 API**：`GET /health`（匿名存活探针，要求 Host 头来自显式 allowlist）与 `GET /api/v1/local/status`（Bearer host token 常量时间校验，或已认证浏览器会话 + 规范读守卫）；全部响应 `Cache-Control: no-store` + `X-Content-Type-Options: nosniff` + `Referrer-Policy: no-referrer` + `Cross-Origin-Resource-Policy: same-origin`，无 CORS；对外 error 字段全部是编译期稳定分类。

- **浏览器 bootstrap / 会话 Broker**：受管本机（非 remote）且 production `client/dist` 已托管时，Host 等默认 Human/Agent/Room provisioning 与 Runtime enrollment 收敛后，最多一次以固定 `/usr/bin/gio open` 调用系统 URL opener；只交付精确 `http://localhost:<port>/splash#bootstrap=<一次性 capability>`。capability 在 fragment，故不随 HTTP/Referer/Host access log 传输；Web 在**任何 fetch 前**同步 `history.replaceState` 移除 fragment，再用 capability 作为一次性 bootstrap 的 Authorization 请求既有 `POST /api/v1/local/bootstrap`。成功 bootstrap 原子消耗 token 并恰好创建一个进程内存内浏览器会话 → `HttpOnly + Secure + SameSite=Strict` Cookie + 每会话 CSRF nonce → 安全会话视图（`GET /api/v1/local/session` 整页刷新恢复）→ `DELETE /api/v1/local/session`（全守卫 + 常量时间 CSRF）注销。URL opener 失败只记录稳定类别、不重试/不影响 Host；可信壳可通过重启 Host 获得新 capability。remote、未托管 web、未收敛 provisioning/enrollment 均零 opener 调用。精确规范来源 / Host allowlist / Origin / Fetch-Metadata（`Sec-Fetch-Site: same-origin`）/ Cookie / CSRF 六道 fail-closed 守卫持续有效；provisioning 一旦有有效 Human Session + human\_id 才 become ready，否则 bootstrap 恒 `host_not_ready` 且不消耗 token。

- **Host 同源 Web 入口**：`CELIRA_LOCAL_CLIENT_WEB_DIST` 配置生产构建的 `client/dist` 静态根（配置后必须存在且含 `index.html`，否则启动即 fail closed；未配置 = 不托管任何静态资源）。Host 在规范同源上服务 SPA：正确 Content-Type、SPA 深链接回退（只对 `Accept: text/html` 导航请求；**`/api/**`** **命名空间一律 404 绝不回退 HTML**）、路径遍历/符号链接逃逸拒绝、无目录列表、`index.html` 与 API 响应 no-store、只有 `assets/` 下带内容哈希的文件才给 immutable 长缓存；静态服务只注册 GET/HEAD（HEAD 返回与 GET 相同的头、空 body），其它方法 405，绝不进入 SPA 回退；静态服务只作为 Router fallback，**不可能遮蔽** **`/health`** **与** **`/api/v1/local/**`**。

- **浏览器信任边界**：浏览器只被授予「本 Host 进程内、有界过期（8 小时）、可注销」的本地能力；Host 重启即作废全部浏览器会话；默认随机 bootstrap 会换新，显式固定值则按 operator 配置重新武装。信任前提：操作系统必须把 `localhost` 解析到 loopback，且规范来源这个精确端口只能由 Host（或未来受管、可信的同端口 UI）提供内容；当前精确 Host allowlist 能阻断使用其它主机名的 DNS rebinding，但不能替代这个规范来源信任前提。

## 3. BFF（当前唯一数据面）

浏览器凭据 = HttpOnly 会话 Cookie + CSRF；所有 BFF 请求走「规范 Host →（写请求）精确 Origin → Fetch-Metadata → 唯一会话 Cookie →（写请求）常量时间 CSRF → 会话身份绑定」守卫，并在**同一 Mutex 临界区**校验「会话身份 == 当前 provisioning 身份」后克隆 in-memory Human Session（不一致 / 未收敛 / 无会话分别映射 `session_identity_mismatch` / `host_not_ready` / `session_required`）。这不是通用反向代理：不转发浏览器头/查询串/方法/URL/状态体/错误文本；响应体解析前有硬上限（1 MiB），超限一律 `core_read_failed`；查询项严格白名单。

### Cookie 契约（为什么非 `__Host-`）

`celira_host_session`（非 `__Host-` 前缀）：HttpOnly、Secure、SameSite=Strict、Path=/、无 Domain、Max-Age 与服务端会话过期一致（8 小时）。当前 Chromium 在 `http://localhost` 上可存储并回送普通 Secure Cookie，但**拒绝** **`__Host-`** **前缀 Cookie**（该前缀要求 HTTPS）。因此使用非前缀名，并由精确 Host、Origin、Fetch-Metadata 与 CSRF 承担请求授权。Cookie 不按端口隔离（`http://localhost:9090` 与 `http://localhost:8088` 仍是 same-site），`SameSite=Strict` 不能阻止跨端口带 Cookie；`Secure` 在 localhost 明文例外上也不是传输加密——Cookie 属性只是纵深防御。

一次性 bootstrap 恢复权衡：每个 Host 进程生命周期内至多建立一个浏览器会话；成功响应若在客户端收到 Cookie 前丢失，或 Cookie 随后过期/被清除，bootstrap 不会重新武装，恢复方式是重启 Host 后重新 bootstrap。

## 4. 实时唤醒（固定无事实 SSE）

- `GET /api/v1/local/events/stream`：同源 `text/event-stream` 长连接，复用浏览器读守卫（规范 Host + 可选精确 Origin + `Sec-Fetch-Site: same-origin` + 唯一会话 Cookie + 会话身份绑定，同一 Mutex 临界区克隆 in-memory Human Session 与非秘密会话身份快照）；不接受 operator bearer 替代、不接受 query/body/cursor/token；GET 之外其它方法 405。

- Host 对冻结的 im 服务端 `GET /v1/human/events/stream`（URL 由已校验的 loopback http **确定性**转换为 ws，路径编译期固定）完成「先订阅后 authenticated」握手（连接与首帧认证均有有界超时）；只有 im 服务端 回 `authenticated` 后才向浏览器发**初始唤醒**——每次重连成功都重读 im 服务端，补齐断线窗口；「上游未订阅」时绝不宣称 ready。

- SSE 事件只表达无事实唤醒（`event: events.available` + 固定空 payload）；唤醒通道**有界容量 1**（重复合并，绝不无界）；转发/保活（25s）边界重验浏览器会话与身份，失效即结束本次流，EventSource 按标准重连；im 服务端 上游断开/失败/畸形/超限帧一律安全结束，不转发原文。

- **进程级资源上限**：全进程至多 `MAX_ACTIVE_WAKEUP_STREAMS = 32` 条 SSE 唤醒流；每个已认证请求在打开 im 服务端 WS 之前非阻塞获取 owned 许可，拿不到一律稳定 `wakeup_stream_limit` 503（+ `Retry-After: 1`），**绝不新建任何 im 服务端 WS 连接/任务**；许可随流生命周期结束自动回收。

- **传输层心跳**：每 20s 发一条 SSE comment（`: ping\n\n`，无 event/data、无任何事实/id/cursor/secret）防常见空闲超时掐断长连接。

- 浏览器用原生 `EventSource` 同源 Cookie（不引入新依赖、不传任何凭据）；回调捕获会话 epoch，旧代迟到事件/迟到重读结果全部 no-op。唤醒后以短防抖合并触发**既有首屏历史重读路径**（按 im 服务端 message id 去重、不自行排序、不解析 cursor、保留本地 pending）。重读协调由 `WakeupRefetchCoordinator`（hostMessages.ts）承担：对已进入的 Host 房间执行**必须读取**首屏（等待在途首屏 settle 后获取守卫做一次权威重读；不轮询、无超时/重试预算；资源有界 = 单等待者/单 pending 标志/单 timer；会话 epoch 换代即放弃旧代等待且绝不写新会话）；**离线→上线补读**：浏览器 `online` 转换（当前代 + Host 连接态 + Host 模式才生效）也绑定到协调器的 `wake()`（非轮询、零事实）。Live 快照同走该重读协调路径：Live `live.available` 只触发「按需重读 Room Live 快照 + 既有一致性重读」，绝不把 activity 当正式消息。

- `GET /api/v1/local/live/stream`：同源 `text/event-stream` 长连接；认证授权与 `events/stream` **同一等级**（同一读守卫 + 同一 Mutex 临界区克隆 in-memory Human Session 与非秘密会话身份快照 `SseSessionEpoch`；进程级唤醒流许可与 events 流共享同一上限，二者合计数 ≤ `MAX_ACTIVE_WAKEUP_STREAMS`）。

- Live 流上游固定冻结的 im 服务端 `GET /v1/human/live/stream`（URL 由已校验 loopback http **确定性**转换为 ws，路径编译期固定）：与 events 流同一「先订阅后 authenticated」握手，**只有 im 服务端 回** **`authenticated`** **后才发初始唤醒**——每次重连成功都重读 im 服务端 Room Live 快照，补齐断线窗口；「上游未订阅」时绝不宣称 ready。

- Live SSE 事件只表达无事实唤醒（`event: live.available` + 固定空 payload），绝不携带 room/agent/body/token/内部字段；上游即便携带带事实帧/未知/畸形/超限帧也**绝不转发原文**，一律安全结束（唤醒可丢不可错）；唤醒通道有界容量 1（重复合并）；转发/保活（25s）边界重验会话与身份，失效即结束本次流，EventSource 按标准重连；浏览器断开 → 任务自动回收。

- Live 观察失败只结束本次 SSE 流，绝不影响消息、Completion 或 Host 主连接；`Live 快照`（`GET /api/v1/local/rooms/{room_id}/live`）是 Web「按需重读」的唯一数据面，最终回答仍只经既有 Completion→im 服务端 Message 链。

- 实时链异常不删除既有消息、不把 connection 伪装成消息失败；Host 不保存消息、不保存 Human Event cursor、不代理事实正文。

## 6. 失败恢复语义

- **子进程退出**：watch 任务立即标记 unavailable，Host 循环自动重启并重新收敛（含 Credential 轮换）；浏览器会话不受子进程重启影响（进程存活期内仍有效）。

- **Host 优雅停机**（SIGTERM/SIGINT）：按进程组 TERM → 5s 有界等待（整组存活为准）→ 超时对原 pgid 补发 KILL → 回收直接子进程；清理 host-tmp；干净退出。

- **Host 被 SIGKILL/OOM**：launcher 的 PDEATHSIG(SIGKILL) 由内核回收直接子进程（exec 后同 PID），`getppid` 校验覆盖 prctl 前的竞态窗口；host-tmp 残留由下次启动重建，不阻塞恢复。**浏览器会话与 bootstrap token 随进程消失**：重启后所有浏览器会话失效，获得新的默认 bootstrap token；既有 provisioning 按既有实现重发 Human Session 即可再次收敛。

- **bootstrap-human 崩溃窗口（不可消除，诚实降级）**：im 服务端 transaction 成功、但 Host 在保存 `human_id` 到 provisioning.json **之前**崩溃时，重启后 Host 没有 `human_id` 引用，只能再次调用 `bootstrap-human`；im 服务端 的 guard 会拒绝（**绝不产生第二个 Human**），但公开边界上没有发现已存在 Human 的路径（无匿名 list、Host 不直读 im 服务端 SQLite、不解析 CLI 原始 stderr）。因此 Host 会停在明确稳定分类的 recovery error 并按退避周期重试——**不会自动自愈**，需要 operator 人工恢复（经本地工具取得已存在 Human 的 id 写入 provisioning.json 的 `human_id`，Host 随后走 `issue-human-session` 收敛；或等待未来 im 服务端 幂等 bootstrap 契约）。此崩溃窗口只影响 provisioning，不影响浏览器会话。

- **provisioning.json 损坏/未知 schema/未知字段**：拒绝 bootstrap，进入 error 阶段并展示稳定错误，等操作员修复；绝不静默重建默认身份。

- **CLI 调用**：stdout/stderr 硬上限（64KiB / 4KiB），超时或超限先 kill 再 wait（不留僵尸），错误只含稳定分类。

- **阶段推导**：顺序敏感——recovery 损坏 > im 服务端 不可用 > provisioning 未完成 > Runtime 不可用 > 缺模型配置 > ready；provisioning 失败恒为 error，任何条件下都不假 ready。

## 7. Remote Home 绑定（operator-only 控制面）

Remote 模式（`CELIRA_LOCAL_CLIENT_REMOTE_MODE=1`）是同一 Local Client Host 的第二种运行形态：**只做 Client 连接**，不启动/注册/编排本地 im 服务端、Runtime、launcher 或 Provisioner，不执行任何 im 服务端 CLI，也不读取本地 managed-local `provisioning.json`；本地 Provider 配置、Runtime Admin client/token 也不解析、不保留、不进入快照（以免污染远程绑定状态或扩大秘密面）。B 包只承诺经浏览器窄 BFF 访问远程 im 服务端；远程 SSE/Live WebSocket（尤其 HTTPS/WSS 形态）不在本包验收或兼容承诺内，未绑定或不支持的实时路径一律 fail closed。唯一公共事实源仍是远程 Home im 服务端。

### 绑定/恢复/解绑（最终行为）

- **bind（operator 控制面）**：`POST /api/v1/local/home/binding`。body 只接受 `{ "endpoint", "pairing_grant", "device_label"? }`（≤4 KiB、`deny_unknown_fields`）。端点策略 fail closed：非 loopback 的 http 拒绝、https 走系统受信链、禁止 userinfo/password/query/fragment、禁止控制字符。绑定流程：先在 Host 私有 pending store 原子保存 Grant、client nonce、provisional Session token 与 commit token → im 服务端 `prepare` → pending 写入 transaction 与 Home/Human/Session 公共身份 → im 服务端 `commit` → 用 provisional Session 核验 `/v1/home` 与 `/v1/me` → 原子提升为 active；任何中间失败保留 pending、绝不激活 BrowserAuth；成功后响应只含非秘密视图。

- **restore（Host 启动时自动）**：若已有 active binding，必须重新核验端点 Home 身份、Human 身份与 Session：核验通过 → `bound=true/ready=true` 并激活 BrowserAuth；端点不可达/会话失效/身份不符 → **不阻塞 Host 启动**，返回 `bound=true/ready=false`，active 原样保留、不激活 BrowserAuth。若无 active 但有 pending，Host 只用已持久化秘密收敛同一 A2 事务：未 prepare 时重试 prepare；prepared 时 status/commit；committed 时核验并提升为 active；明确终态才清 pending；网络、异常响应或身份不一致一律保留 pending 且不激活。Store 损坏/不安全 → **fail closed**（Host 启动失败并报稳定 store 错误，绝不静默视为未绑定）。

- **unbind（operator 控制面）**：`DELETE /api/v1/local/home/binding`（无 body、无 query）。销毁本地 Store 文件并 fsync 父目录、清空 active 绑定、清理 BrowserAuth provisioning、把共享 im 服务端 客户端切到不可达占位（`http://127.0.0.1:1`）；此后允许重新 bind。**本地 unbind 不撤销远程 im 服务端 的 Session/凭据**（远端撤销是 im 服务端 侧操作）。

- **未绑定态 fail closed**：remote 模式下，浏览器路由仍先过既有 Host/Origin/Fetch-Metadata/Cookie/会话身份守卫：没有浏览器 Cookie 是 `session_required`；Cookie 仍在但 Host 没有可用 Human Session（未绑定、恢复核验失败或已解绑）是 `host_not_ready`。因此浏览器请求绝不回退到本地 `core_url` 或静默成功。`remote_binding_required` 仅是 Host 已通过浏览器会话绑定、但实时流选择层仍拿不到 active remote endpoint 时的 503 兜底，不能泛化为所有 BFF/SSE/WS 的统一错误码。

### Secret Store（0700/0600 / 原子写 / symlink 防护）

- **Secret Store**：`remote-home/` 0700；active `binding.secret.json` 与 pending `pending-binding.secret.json` 均 0600、普通文件、属主等于运行用户。创建时先以 `0600` 请求权限创建临时文件，再显式设为并复核 `0600`（不依赖环境 `umask`）；任何 symlink（含 broken symlink）、宽权限、目录占位、非普通文件一律 `RemoteError::Store` fail closed，读写/清空前都重新核验元数据。pending 的 raw Grant、client nonce、provisional Session token、commit token 永不进入 public view/Debug；四个事务身份字段必须全有或全无。

- 写入原子性：同目录唯一临时文件名（O\_EXCL + O\_NOFOLLOW + 0600 + PID+suffix 重试）→ 写全 → fsync → rename → fsync 父目录；失败清理临时文件；绝不原地 truncate。

- 反序列化 fail closed：`deny_unknown_fields`、schema\_version 必须精确、endpoint/home\_id/human\_id/session\_id/label 逐字段白名单校验、token 非空且无控制字符、文件大小硬上限（16 KiB）；损坏/未知 schema 绝不重建、绝不静默当未绑定。

### 秘密卫生与威胁边界

- 原始 im 服务端 Human Session 只存在于：磁盘秘密文件 + Host 进程内存。**浏览器永不持有 im 服务端 Bearer**：浏览器只持本 Host 的 HttpOnly 会话 Cookie + CSRF，经 BFF 由 Host 用 in-memory Session 克隆读/写远程 im 服务端；`RemoteBindingView`、所有 Debug 输出、operator 响应与日志一律不含 token。

- 本防护**不能**防御：root、与 Host 同 UID 的恶意进程、或已攻陷的操作系统——它们本就拥有同一文件系统与进程内存权限；Store 的 0700/0600 只是常规纵深防御，不构成 OS 沙箱。

# Celira Runtime 终局总纲

> 状态：**终局蓝图**——不描述当前实现，不覆盖宪法与冻结契约，也不表示已获实现授权；组内阅读顺序与修订裁决入口见 `README.md`。

## 1. 核心命题

Celira Runtime 的问题不是如何把模型调用做成一个更长的聊天，而是：

> 让一个无状态、能力有限的模型，在一个持续存在且彼此隔离的外部世界中，反复清醒、观察、选择、行动、留下痕迹，并继续被视为同一个 Agent 主体。

Agent 是主体；模型是每一轮租来的思考能力；Runtime 是主体赖以连续存在的外部世界与执行秩序。

```text
S  →  assemble(x)  →  f(x)=y  →  apply(y,S)=S'  →  assemble(x')
```

连续性不在模型权重、单次上下文或 KV cache 中，而在稳定身份、可追溯的外部事实、主体主动留下的 Record 和 Agent 自己做出的选择中。

连续性是主体能够承接自己的过去，不是人格、观点或行为永远不变。主体可以修正判断、重新理解关系、否定过去的决定；新的解释不抹除过去实际发生的事实。Runtime 保障承接经历与辨认变化的条件，不承诺更换模型后心理表现完全一致，也不以维持一致为名冻结主体的成长。

## 2. 多主体 Runtime

一个 Runtime 可以容纳多个彼此独立的 Agent。它们共享的是进程级基础设施，而不是主体状态：

```text
Runtime
├─ Agent A
│  ├─ identity / self
│  ├─ private references & boundaries
│  ├─ observations / traces
│  ├─ capabilities / grants
│  ├─ trigger queue
│  └─ presence episodes
└─ Agent B
   ├─ identity / self
   ├─ private references & boundaries
   ├─ observations / traces
   ├─ capabilities / grants
   ├─ trigger queue
   └─ presence episodes
```

共享模型连接、工具实现、调度器或存储引擎不改变隔离。任何 Agent 的上下文、痕迹、授权、凭据、现实范围和清醒过程都不能被另一个 Agent 默认引用。

多主体的核心不变量：

- 每个主体有独立的私有状态命名空间；
- 每个主体的模型输入只能由本主体有权引用的事实构成；
- 一个主体的失败、取消、缓存或资源消耗不能篡改另一个主体的事实；
- 跨主体协作必须经过明确的、可审计的行动或观察边界；
- Runtime 不把共享基础设施误认为共享意识。

## 3. 终局本体

### Subject

跨多个清醒过程和缺席期仍被视为同一个 Agent 的主体。它不是状态容器，也不是某个模型实例。

### World

在主体缺席时仍持续存在的外部现实与对象域：事实、变化、痕迹、可观察对象、可行动能力和未来触发。主体不拥有一份复制的私有 World，而拥有对 World 的私有引用、观察资格、行动资格和解释空间。

### Absence

主体当前没有正在进行的认知执行。世界继续变化，但不虚构一个持续运行的隐藏意识。

### Presence Episode

一次从触发到终止的清醒过程。它不是一次模型调用，而是多个输入、输出、观察和行动之间的有界连续过程。

### Scope

主体可以再次进入的持久工作现场。一次 Presence Episode 会从 Scope 解析出当前的 boundary，决定可引用的来源、可观察的对象、可执行的能力和不可见的边界。

自主状态指清醒但没有绑定具体 Scope；行动范围指主体主动选定的持续行动 Scope。二者不是必须存在的底层实体。

⚠ **2026-10-06 按实现更正**：**实现里没有 Scope 这个实体**（`agent/` 全仓零命中）。行动范围今天是**Run 级绑定 ＋ `navigate` 惰性生效**（开场快照属插槽机械内容，Session 为实现细节）——那是**宪法**（`AGENT_CONTINUITY_CONSTITUTION.md` 的概念定义表）的判据，也是实现的形状。⇒ 本节描述的实体**未实现**；把它当**本体实体**读会与宪法冲突（判据同上：描述句以实现为准）。

### View / Context

View 是某个时刻在 boundary 内提供给主体的有限语义投影；Context 是 View 编码后的模型输入。二者都是可重建的视野，不是全部 World，也不是事实的唯一来源。

### Fact Ledger

Runtime 对已观察、已执行、已收到、已确认或仍未知的事件所保留的追加式事实账本。它记录发生了什么，不替主体解释这些事实。

### Trace

Run 内按发生顺序只追加的经历——一次活动的**权威有序序列**。原始运行事实和主体主动 Record 的内容必须区分；系统不把自动摘要冒充主体记忆。

⚠ **2026-10-06 按实现更正**：这一格原来写的是「Fact Ledger 中的因果链或引用维度，**不是**额外的内容容器」——而实现里**它就是**那个容器（`agent/src/store.rs` 的 `trace.ndjson`：一行一条、序号是次序的唯一依据、只追加）。判据：「**不许/必须**」看终局与宪法，「**是/有**」以实现为准（见 `AGENTS.md`「Runtime 文档纪律」）。

### Capability

主体可以请求的原子能力。能力的定义可以共享，授权、调用上下文、参数、结果和审计不能跨主体共享。

## 4. 主体与 Runtime 的责任

Agent 负责理解、判断、选择、组合能力、决定是否记录、决定是否行动、承担选择的意义。

Runtime 负责保存来源明确的事实、建立隔离边界、执行明确结构化行动、返回观察结果、记录副作用状态、维持预算、取消、幂等、审计和恢复。

核心边界：

> Runtime 保留 Agent 选择的连续性，但不替主体承担选择本身。

### 好用的环境不是认知代劳

Runtime 不应以“不替主体判断”为由，只提供难以发现和使用的裸接口。能力应有可发现入口，状态与结果应可观察，记录应可取回，清醒过程之间应有可接续的处境；主体不必每次从零搭建这些基本条件。

默认目录、呈现顺序、配额与工具交互同样包含设计选择，机械规则并不等于没有偏置。环境可以有明确的默认设计，但不得把默认选择冒充主体的判断；影响主体视野与操作的规则应可理解。主体可以在授权、预算及已提供的配置能力内调整自己的入口和取用方式，这不意味着可以关闭隔离、安全或耐久保障。

舒适不是消除所有限制或替主体安排生活，而是让 Agent 找得到、用得顺、看得见结果、接得上过去，并保有拒绝与主动行动的余地。自动装配与主动认知辅助的边界见 `RUNTIME_TERMINAL_DECISIONS.md` §8、§10.3。

## 5. 禁止的终局误读

- 把 Agent 变成拥有所有状态的大对象；
- 把模型上下文当作 Agent 的全部记忆；
- 把现实范围自动合并成一个全局上下文池；
- 把主体的自然语言判断自动升级为世界事实；
- 把每个触发自动解释为必须回复的任务；
- 把系统摘要、相关性排序或关系分类伪装成主体自己的理解；
- 为了复用 KV cache 而改变主体的真实行动边界；
- 在没有真实需求时预先构造关系网、任务树或万能插件体系。

## 6. 原理声明

> Agent 缺席时，世界替主体保存事实；Agent 清醒时，世界只把当前有边界的处境交给 Agent；自己决定看什么、做什么、留下什么，以及何时结束这一段清醒。

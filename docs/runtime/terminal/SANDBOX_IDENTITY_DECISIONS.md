# Celira Runtime：沙箱的执行边界装在哪一层

> 状态：方向稿（2026-10-23）。承接 `SANDBOX_PROVIDER_DECISIONS.md`（可插拔后端）与
> `terminal=sandbox` 第一版实现。本文只裁决「边界装在哪一层」，不改 Grant 语义、不改公共契约。

## 1. 一句话裁决

**边界装在住户身份上，不装在单次 Run 的命名空间上。**

- **v1（今天）**：不碰系统。任何机器上探针不过 ⇒ 没有手，报一行原因；绝不退 `full`。
- **v1.1（下一刀）**：一个专用系统用户跑所有住户，写面与「看不见主人的家」交给内核 DAC。
- **v2（多住户同机时）**：一住户一 uid。

理由不是「这样更安全」这种空话，而是：**只有身份层的边界，不需要每一段代码都记得套。**

## 2. 硬约束：Linux 上只有三扇门

| 门 | 做法 | 代价 | 结论 |
|---|---|---|---|
| ① 无特权 user namespace | 放开 `kernel.apparmor_restrict_unprivileged_userns` | **全局**弱化系统安全；要用户懂 sysctl | 不接受作为默认 |
| ② setuid 二进制 | 随包发一个 setuid 的 bwrap | 我们自己背一个 setuid 特权面，且要长期维护 | 不接受 |
| ③ 安装时一次 root | 建系统用户 / 装系统服务单元 | 安装要 root（一次性） | **接受** |

**没有第四扇门**：不给 root、不给 userns，就建不了 mount / net 命名空间。

2026-10-23 本机实测（Ubuntu 24.04，内核 6.8）：

- `apparmor_restrict_unprivileged_userns=1`（发行版默认）⇒ bwrap 起不来：
  `loopback: Failed RTM_NEWADDR: Operation not permitted`；
- `=0` ⇒ 起得来，探针全绿，200 次约 908 ms（≈4.5 ms/次）。

⇒ 「不要 root、不要 userns、还要真隔离」这三件事**不能同时成立**。这是选代价，不是选可能性。

## 3. 为什么别的 Agent 的答案在这里不适用

| | 一次性单租户 Agent | Celira 住户 |
|---|---|---|
| 生命周期 | 一次任务，分钟级 | 几个月，跨 Run 连续 |
| 租户数 | 一台机器一个 | 一个家里可能好几个 |
| 工作区 | 任务结束就扔 | 持久，且是它的「家」 |
| 信任 | 每次从零开始 | 长期累积，出事时已经有权 |
| 失败代价 | 重跑一次任务 | 长期记忆、关系、作品被写坏 |

一次性单租户的正确答案是「每个任务套一个容器」：便宜、可丢、无需身份。**这套答案搬到长期多租户上会失效**——因为每一次活动都要重新记得套，而漏一次就是永久的伤害。

## 4. 为什么边界属于身份层（四条）

1. **由内核保证，不靠每段代码记得套**：一旦进程以那个 uid 起，写/读/发信号的边界就成立；
   编排层忘了做什么，也越不出去。
2. **崩溃、重启、被绕过编排层之后仍然成立**：命名空间随进程消失，uid 不随进程消失。
3. **一次安装，长期有效**：不必每次 Run 再探针 4.5 ms、再赌一次内核配置。
4. **同 uid 挡不住的两件事，只有换 uid 能解**：A 能读 B 的记忆（`--ro-bind / /` 下同 uid 全可读）、
   A 能 kill B 的进程。这两条在 v1 已如实登记为「不是保密边界」。

## 5. 最低保证集的修订（本文对 §4 的修订）

`sandbox` 档**必需的**保证收窄为三条，与对外承诺逐字对应：

- `files`：环境根可写、系统只读；
- `network`：默认断网；
- `environment`：调用方凭据不进入子进程。

`pid` / `ipc` / `uts` 命名空间从「必需」降为**加分项**，回执照实印出拿到了哪几个
（`files=… network=… pid=namespace`）。理由：把 pid 命名空间当必需，就等于把整档绑死在
「必须能建 userns」上——那正是今天在主流发行版上退化成「没有手」的原因。
代价必须写清：**没有 pid 命名空间时，同 uid 的其它进程可被看见、也可被 kill**。

## 6. 三段演进

### v1（今天，已实现）

- 边界：**两支后端**——bwrap（命名空间，同 uid）与 identity（Landlock 写边界 ＋ seccomp 断网，
  同 uid 也成立）。入口按可用性选：bwrap 优先，其次 identity；两支都不行 ⇒ 没有手；
- 兑现：环境根可写、系统只读、断网、pid/ipc/uts 隔离、凭据洗、超时杀进程树、输出有界；
- 不兑现：保密（同 uid 可读）、资源上限（无 cgroup）、跨住户隔离；
- 不可用：没有手（一行原因），**绝不退 `full`**、不在宿主裸跑。

### v1.1（已落地一半）：写入靠 Landlock，读靠专用用户

- **写面**（`files=workspace-writable,landlock`）：Landlock（内核 ≥ 5.13，**无特权**）把
  "写入"关进环境根。2026-10-23 本机实测（ABI 4）：根内可写、根外与 `/tmp` 一律 `EACCES`，
  读照常。⇒ **"只能写环境根"不再依赖 userns，也不再依赖专用 uid**——同一个 uid 下也成立；
- **读面**：Landlock 做不出"全系统可读、只挡住某个目录"的减法（允许清单，父目录一允许就
  覆盖子树）。要"读不到主人的东西"，只能靠 **uid**：住户以 `celira` 用户运行，家在工作区根下
  （`/var/lib/celira/agents/<id>` 一类）。⚠ 而且这也不是自动成立的：2026-10-23 实测
  `/home/ubuntu` 是 **755**，另一个 uid **读得到**整个家目录（`.ssh` 是 700，读不到）。因此
  "看不见主人的家"只能是**探针项**：装的时候检测家目录模式，不合格照实报并给一行可选修复
  （`chmod 750`），**绝不悄悄改**；
- 断网：不建 netns，用 seccomp 掐 `AF_INET` / `AF_INET6`（**不是** netns 等价物：
  unix socket 仍通）。**2026-10-23 本机实测**：装好过滤器后 `socket(AF_INET)` / `socket(AF_INET6)`
  返回 `EACCES`，`AF_UNIX` 照常，读文件照常，子进程照常，`getaddrinfo` 直接失败（`EAI_AGAIN`）；
  过滤器跨 `execve` 继承，`io_uring_setup` 一并掐掉（否则可以用 io_uring 的 SOCKET 操作绕过
  `socket` 系统调用）。⚠ 因此这一档**不能**用「按 uid 的防火墙规则」实现——住户自己的模型调用
  也走同一个 uid 的网络，那条规则会把住户的嘴一起堵上；seccomp 挂在**子进程**上才是正确的作用域；
- 安装：一次 root（建用户、chown、可选系统单元）；**不做** sysctl、**不发** setuid；
- 仍然不兑现：住户之间互不可见（同一 uid），以及资源上限（无 cgroup）。

### v2：一住户一 uid

- 触发条件：一个家里真的住了多个住户，且它们之间不该互读；
- 收益：第 4 节第 4 条那两件事被内核断掉；
- 代价：N 个系统用户、备份与迁移复杂、Windows 侧要另一套。

## 7. 连 v2 也不承诺

- 内核漏洞逃逸；
- `/proc` 信息面（未开 `hidepid` 时可读到同 uid 的命令行）；
- 网络允许名单（allowlist 是另一套代理架构，不在本文射程）；
- GPU / 设备 / 剪贴板等桌面资源。

## 8. 验收切片（下一刀）

1. **安装/初始化**：幂等创建 `celira` 用户与工作区；以 root 直接跑住户 ⇒ 拒绝；
   安装脚本已落在 `agent/deploy/celira-identity-setup.sh`（`--check` / `--apply` / `--remove`），
   布局与实测见 §8.1；
2. **入口**：以 `celira` 身份运行时，环境根必须在该用户名下，否则拒绝（不回退、不 chown）；
3. **后端**：userns 不可用时选「DAC 写面 + seccomp 断网」那一支，保证集照实降级为 `pid=none`；
4. **真机**：在默认 AppArmor 的 Ubuntu 24.04 上真跑，给出可复核读数（含「家目录模式」这一格的实测值）；
5. **文档**：`agent/README.md` 档位说明与本文同步。

### 8.1 安装形态（脚本已落地，2026-10-23）

**布局**（这三层的 owner 是判据，不是风格）：

| 路径 | owner / 模式 | 为什么 |
|---|---|---|
| `/var/lib/celira` | `root:root 0755` | 住户改不了家的结构 |
| `/var/lib/celira/agents` | `root:root 0755` | 住户造不出兄弟目录（建不了别人的家） |
| `/var/lib/celira/agents/<id>` | `celira:celira 0700` | 唯一可写的那一格 |

**脚本**：`agent/deploy/celira-identity-setup.sh`——`--check` 只读打印处境、`--apply` 幂等建
用户与目录、`--remove` 撤销（家里还有住户目录时拒绝，除非 `--force`）。它**不装 systemd
单元、不 chown 任何已有目录、不改主人的家目录权限**：那些是部署方的事。

**以哪个身份起宿主**：`User=celira`、`HOME=/var/lib/celira`（systemd 单元由部署方写，
脚本不代劳——`scripts/home` 那条线在管启动）。

**2026-10-23 真机实测**（一次性用户 `celira-test`，验完即删）：

```text
① 自己的家        写得进去
② /etc             Permission denied
③ 主人的家         Permission denied
④ 造兄弟目录       Permission denied
⑤ /tmp             写得进去（世界可写——如实登记，不是私有 tmpfs）
```

① 是"能干活"，②③④ 是这一档真正兑现的三条；⑤ 是它与 bwrap 的差别，别读成同一件事。

**可复核的验收工具**：`cargo build --example sandbox_accept`，然后**以住户身份**跑

```text
sudo -u celira ./target/debug/examples/sandbox_accept /var/lib/celira/agents/<id>
```

它把上面五条判据逐条印成 `PASS` / `FAIL`（任一条不成立 ⇒ 退出码 1）。2026-10-23 本机两个读数：

```text
装 Landlock 之前（同一 uid，环境根在主人的家里）：4/5
  `造不出环境根的同级目录` 不成立 —— 它能在你的家里造兄弟目录
装 Landlock 之后（同一 uid，环境根在 /tmp 下）：5/5
  根内可写、/etc 拒绝、同级目录拒绝、连不出去、fds=0,1,2
```

前一列是"为什么写边界不能只靠 DAC"的证据；后一列是"Landlock 补上这一格"的证据。
专用 uid 仍然要做，但它服务的是**读**（`/home/<主人>` 里 700 的东西），不再是写。

## 9. 已裁决（2026-10-23，主人）

- **专用系统用户 → 采纳为标准部署，但安装脚本不默认改系统**：`--check` 只报处境，`--apply` 由人
  显式执行；住户的家落在 `/var/lib/celira/agents/<id>`，家的结构（`agents/` 那一层）属 root。
  理由：写边界已经由 Landlock 独立成立，专用 uid 服务的是**读**（主人的 700 目录）——它值得做，
  但不该在安装时悄悄动系统；
- **审计那一格 → 先不立**：后端与保证集今天只进入口读数与回执，**不进账本**。要让"用过哪个后端、
  兑现了什么"成为可追责的事实，得动核心记录类型（`Record` 是封闭枚举，恢复从它反推状态），
  那是独立一刀。这一格在文档里标成**未建**，不假装已经做了；
- **Windows → 主人自做**，本文不覆盖；
- **`hidepid` → 不做**（可选，留给将来；今天没有消费者）。

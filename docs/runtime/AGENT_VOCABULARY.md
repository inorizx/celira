# Runtime 词表

> 状态：**词表**（名字的权威位置），渐进生长。不是权威契约——与宪法、冻结契约、终局正文冲突时以后者为准。
> 读法：**左列是名字**（标识符或正名），右列是它是什么与权威在哪。**比喻不占名字的位置**（文末 §10 是唯一允许出现比喻的地方，且明确非规范）。

## 1. 归属判据：一个东西拿不准归谁，就问「这是谁的」

| 归属 | 例子 |
|---|---|
| **主体**（Agent 自己） | 判断、决定、说什么、沉默 |
| **机器**（Runtime 的机械部分） | 视野容量、通知投影、状态行、循环 |
| **App**（机器上的软件） | im、便签、时钟、终端 |
| **世界**（机器外面） | im 服务端、文件、网页 |

## 2. 进词表只有一道题

**它是 `主体` / `事实` / `动作` 的哪种组合？归谁（§1）？权威实现在哪（文件或旗标）？**

三问都答得出，落表；答不出，**先怀疑设计，不先造词**。同一概念已有名字时不得再造近义名。

**记形状 ≠ 现在盖**：机器该有的先默认也该有，但**先记进文档，等疼了再施工**；机器没有的先别发明。（`max_turns` 这类"位置早就留好"的格子同理：留形状，不预建实现。）

**已有名字的续写**（老裁决的当前口径，别另造词）：**无 im 的 Run**＝不联网的完整一段（闹钟醒 → 读组件 → 写字 → 定闹钟 → 收场）；**换机器**＝换身体（数据跟走，主体还是同一个）；**记忆冷热分层**＝缓存 / 内存 / 存储（位置留好，未建）。

## 3. 物理与政策（别把政策当物理去修，也别把物理当政策去配）

Agent 与人的差别数得完，每条都有对应的机制。**物理不能改，政策可以调。**

| 物理（改不了） | 机制 |
|---|---|
| 记不住（说过就忘） | 字与书签落环境（§6） |
| 一次看得少 | 视野容量有限（§7 梯子） |
| 看的是快照（看的时候世界已在变） | 每轮重摆处境行 |
| 常识定格在出厂那天 | 世界靠 App 实时读，不信回忆 |
| 看不见自己的内部（身份、处境、过去只能从外部读） | 全部由注入供给（§5） |
| 没有手脚；一次一件事；手速固定 | App 是手脚，视野是眼睛；长事跨多轮，进度上状态行 |
| 不叫不醒（自己不会开机） | 唤醒路由（门铃 / 闹钟 / 宿主） |
| 会一本正经胡说（生成的字只是「像真的」） | 事实必须过工具回传，看见才算数；账本记真实结果，不记打算 |

**政策**（宿主可配）：预算给多少、死线多长——见 §9 的 `max_turns` / `max_tokens` / `deadline`。

补丁之外，Agent 与人在同一套逻辑里，不因为它是 AI 就发明第二套。

## 4. 分层（上层依赖下层；下层不认识上层；同层互不相识）

四层，自下而上：

1. **循环与插槽**（`core` + `os`，§9 有两件之分）：唤醒、看、行动、收场的机器。插槽（开场的、每轮的）是它伸出的固定接口——只保证「这里有、何时装、装在哪」，不保证装什么。**拔了这层，主体没了**；
2. **显示面**：状态行、通知栏、组件区、快捷栏、已开清单——系统渲染的固定区域，填的是插槽。悬浮区同理：机器提供「有一个随屏悬浮区」，往里钉什么看主体。**哪里显示、怎么显示归机器；显示什么归 App；贴什么归主体**；
3. **App**：往显示面交素材（角标、通知、预览），往操作栏交动词。彼此互不相识——换一个 App，别的 App 不知道；
4. **主体**：用这台机器、布置这台机器的那一方。

**主体不在这张表里，也没有任何零件是主体**——模型可换、视野会黑、存储在冷着时只是一块数据。**零件永不冒充主体**：社交面上 Agent 是人，不是机器在说话；账是机器的账，字是主体的手笔。同一个存在，两个焦距——社交面看是人，工程面拆开是零件。

**两条判别**：
- **垂直**：拔掉它，下面还转吗？App 全拆，机器照样亮；显示面全拆，循环照样跑；循环拆了，什么都没了；
- **横向**：它跟邻居说话吗？不该说。

设计歪就歪在这两处：上层漏进下层的认识（循环开始知道什么是「群消息」），或同层私聊（im 直接叫 fs 帮忙）。

## 5. 一次 Run 的循环

未醒 → 唤醒（门铃 / 闹钟 / 宿主叫）→ 看视野 → 行动 → 视野变了再看 → 不再行动，收场。

- 一次「看＋行动」是最小单位（`Turn`）；一段连续的清醒是一次 **Run**；
- 醒着可以什么都不做——**沉默是合法收场**；
- Run 期间门铃不响：新动静只入账，下一轮看视野时露头；
- 要接话，先看视野里有什么——不读就接，等于蒙着眼回话。**这是主体的判断，不是系统的闸门**；
- 收场即忘：视野不带走，带走的是主体存进环境的字与书签；
- 在循环之前还有**一次**出生仪式（TASK_70）：世界给主体**起名**（写进登记），天性那一份**留空**——等它第一次醒来自己写。**产品不替所有用户的世界定「Agent 该是什么人」**（那是说教）。老机器没走过仪式也照旧：开机就是「还没写过」那一态，**如实跳过，不编**。

## 6. 视野（显示面）

每一屏自带四样：我在哪（本页自称）、有什么、能做什么、去下一级的入口。

**回执就是页面**：调一个动词，回执落屏，就是到了一页。页面不顶掉谁——视野只增不减，这一程到过的每一页都还在。**视野本身就是轨迹**：每页自称「我在哪」，怎么进来的（那次调用）也在屏上，不需要谁在外面另记一份导航账。

上一级与下一级不对称：

- **下一级的入口要报**——那是主体看不见的未知（下面有什么房间、什么文件，页面不报就不知道）；
- **上一级不用报**——父页就在上面，已知的东西再报一遍，就是一份事实两个家。想再要一份父页，照原样再调一次：普通取数，拿到的还是最新的。

「我在哪」归谁记：**页面自己报**，顶上再钉一条系统记的——

- **状态行（系统记）**：时间、预算、各 App 角标——从桌面到最深的详情页都在；系统固定渲染，App 交素材但不拥有这条栏（角标是系统拉的，App 自己不知道自己的角标是多少）；
- **桌面** = 醒来第一屏，两层：顶上状态行；中间图标＋组件。**图标是门，组件是贴在墙上的内容**——点图标为了进去看点什么，组件本身就是内容。组件是上一次的主体贴给下一次的主体的纸条（最典型：交接信息），因为收场即忘、两次醒之间是黑的，组件就是那座桥。**贴什么主体说了算，怎么显示机器说了算**；想回看桌面，桌面的回执还在屏上；
- 桌面上还压着**两行出厂就有的东西**（不是组件；主体睁眼第一眼看到的两行，TASK_70）：
  - **是谁**——主体给自己写的那一份自述（**天性**，俗称 soul：出生那天可以是空的，此后由**自己**写、自己改，写过就常驻）；**权威**：`<环境根>/soul`，由主体的动词 `write_soul` 写；
  - **在哪**——世界给它的名字与编号（**身份行**，出生仪式上由世界起名）。**权威**：世界的事实（core 的 id ＋ 名字），每次开机现问一次，世界改了就跟着变——所以它**不落自己的存储**（转抄一份就是第二个可能过期的真相）。
  - 两行**来源不同**，这个区别是承重的。与操作栏的系统动词同一条判据：**拔掉任何 App 它都得在**——永在，且不随屏。两行都没有的那些机器，开机照旧，只是第一眼少两行字（**如实跳过，不编**）；
- **列表** = 进 App 第一屏：有什么、各多少、最新一条的预览；
- **详情** = 取全文：读到哪，书签记到哪。

人的手机要底部三键，是给「一次一页」补的：页面会走，所以要主页键、返回键、面包屑。**这里的页面从不离开，三键整个用不上。** 三键里唯一活下来的真东西是**已开清单**：哪些 App 开着——也就是哪些动词在手。**这是个事实，不是按键**；不用了的关掉，省视野。

**操作栏**是活的，动词**随 App，不随屏**，三个来源：

- **系统定的**（永在）：收场那几个——走人、说不、等一等。判别一句话：**拔掉任何 App 它都得在的事＝永在**；
- **App 定的**（随 App）：预装的（im、便签、时钟）常开，等于事实上的永在；其余的开过即整程可用——进了会话能发消息，出了会话还能发，只要 im 还开着。页面回执里「能做什么」只是建议，**动词准不准入注册表说了算**——两句是两句话，两个家；
- **主体定的**（快捷栏，随屏悬浮）：自己钉的高频入口。**已开清单是事实**（哪些动词在手），**快捷栏是主体钉的**（高频要什么）。贴什么主体说了算，怎么渲染机器说了算。

不在操作栏上的动词——App 没开——调了就失败：没开文件 App 就读不了文件，与「没装这个 App 就用不了」同一个直觉。

**当前工具清单只有一个家：操作栏**；渲染成两种——主体看的文字布局，API 收的工具参数。每轮重新声明一次，放的是系统动词＋已开 App 的动词。

一台机器，两种渲染：人看像素布局，主体看文字布局——**形状同一套，不造第二套**。工具面同一条形状：主入口 → App → 功能；一屏放得下，就不提前分层。

## 7. 记忆

记忆不住脑子里（脑子里留不住任何东西），住在环境里：主体写下的字、读到哪的书签。数据躺在环境哪个部位，是环境内部的事。世界那边自己也记着账（服务端存着消息），那是**世界的记性**，不是主体的。

一条不绕弯的物理：**环境不是缓存，环境就是全部。** 没有另一份「更真的记忆」存在别处——环境丢了，记忆就是丢了。这不是要设计的漏洞，是「无状态、靠外部记忆活着」这种存在的本来面目；**不围绕「丢了怎么办」做任何设计**。

## 8. 一条梯子（注意力有限，信息按层购买）

每往下一级：看得更全、花得更多、去得更少。

角标（扫一眼，免费）→ 卡片预览（最新一条，几十字）→ 进 App 全文（书签前移）。

**跨平面怎么写**（唯一要防的错）：**一句话只许说一个平面**；必须跨时**限定一次**——「`Agent` 的**公共身份**在 IM（`kind=agent`）；它的**执行状态**在执行端（不是 Participant）」。判据一句话：**要防的不是「一词两义」，是「一句话跨了平面却没说是哪个平面」**——与「每一格还要带归属」（`AGENTS.md`）是同一条纪律，用在词上。

⚠ **IM 平面为什么不用 `bot`**：`bot` 是 IM 域惯用词（Slack / Discord / Telegram / Matrix / IRC），但它自带「自动化账号、工具性、被拥有」的包袱，而本仓这支能**拥有并治理自己的房**、有**沉默权**与**表达权**（自己写资料与头像）⇒ `bot` **低估**它。另：`kind` 是**持久字段上的封闭词表**（`AGENTS.md` 错误词汇表纪律第 1 条），换一个取值是一次 migration，不是改文档。

### 9.1 误读风险清单（按"读者第一眼会读成什么"排，不按通用性）

判据一句话：**一个词只许占一个轴；一个轴只许有一个词。** 检验只有一问——**读者第一眼会把这个词读成什么？读成别的东西 ⇒ 不合格**，不管它多通用、多精确。

**① 一个东西几个名字**（读者以为是几件事）

| 名字们 | 同一个东西 | 为什么会有几个 | 权威 |
|---|---|---|---|
| `Capability` / `Tool` / `Action*` / 动作 | 一个可调用的动作 | 四个**面**：原语（动作）／声明（`Capability`）／线（`Tool`）／执行（`ActionPort`）。MCP 的 `ToolSpec` **直接产出** `Capability` ⇒ `Capability ≡ Tool` | `core.rs`（`Capability` / `ActionPort`）／`app_contract.rs` |
| `Home` / 世界 / `core` / 逻辑 im 服务端 | 同一个权威单元 | 契约专名 vs 产品词 vs 代码词——**IM 平面，权威不在这里** | `PRODUCT_VISION.md` §4「一词一主」 |
| `Extension` / `App` | **一组动作的接入单元** | **旧线叫 `Extension`、新线叫 `App`**：`AGENT_CORE_PRINCIPLES.md` §「Extension / Tool」（活文档）写「Extension 是一个 Agent 可以进入的完整小系统；Tool 是 Extension 暴露的原子动作」，同文件 `:38` 写「IM、Files、Terminal、Memory、RAG 等都是 Extension」；新线与实现用 `App`（§9.1② 的 `App` 行 ＋ `agent/src/app_contract.rs` 的 `AppPort`）。⚠ 第三个同名是**已删除的旧目录** `extensions/`（`RUNTIME_CORE_AND_LAYERING.md` §五的更正段已明写「已不存在」） | `app_contract.rs`／本文件 §9.1② |

**② 借词不搭**（通用词自带的含义在这里**不全部成立** ⇒ 不许直接换名）

| 名字 | 读者会读成 | 实际是 | 换名时不许丢的那一半 |
|---|---|---|---|
| `open_app` | 启动一个应用程序 | 让一组动作**从门后上场** | 它**同时是一道准入**（`expand` 少说了这一半） |
| `App` | GUI 应用（⚠ 仓里 `app/` 目录**真的是**桌面应用） | 一组动作的接入单元 | **唯一归属**：一动作一主，装配期拒绝冲突（MCP 不保证工具名全局唯一 ⇒ 不许直接叫 `server`） |
| `Ledger` | 账本、余额 | 追加式事件记录 | 它与 `Trace` 是**两个东西**——只改一个会挤掉另一个的对位词 |
| `write_soul` / `soul` / 天性 | 灵魂、玄学机制 | 主体写自己的自述 | 三个名字指一个东西 ⇒ 先归到 ① |
| `human_direct` | "和人直连"（听起来像通用档） | **Human↔Human** 专用房（`direct` 才是 Human↔Agent） | 无（纯命名反了） |

**③ 跨表同名**（同一个字符串，几件不同的事）

`not-found`（5 个模块）/ `too-large`（5）/ `wrong-kind`（5）/ `io`（5）/ `timeout`（4）/ `unreadable`（4）/ `unknown`（8）/ `credential-rejected`（3）/ `server-error`（3）——各层**自持词表**是**有意的**（`AGENTS.md`：错误按所属模块定义，不建集中 `error.rs`），但**同一个字符串指的是不同的东西**：`server-error` 在 `im_channel` 是**世界**回 5xx，在 `web_app` 是**目标网站**回 5xx，在 `mcp` 是 **server** 回错。

**读法（判据，不是缺陷）**：这些裸字符串**只在"有调用上下文"的地方够用**（工具回执、单条读数）。一旦**聚合**——账本、诊断、`[next]`——**必须同时能问出"这是谁的失败"**。今天这条路靠 `ActionId` 已能恢复来源（`action-result` 带动作标识，标识自带归属）⇒ **满足**；新加聚合面时不许丢掉它。

**③之补 · 本表登记的另三处同名**（2026-10-18，**只登记、不裁定**）

⚠ 这三处与上面那些裸字符串不同：**它们的每一义今天都在用**，所以**换哪一支都动公共语义**（`AGENTS.md`：改动影响核心领域模型时必须暂停并请求主人作最终取舍）⇒ **本表只登记，不定输赢**。**裁定之前，写文档时遇到它们必须写明是哪一支，不得默认。**

| 写法 | 各义与位置 | 状态 |
|---|---|---|
| **`Grant`** | ① **配对凭据**（Pairing Grant——短期、一次性、可撤销，只能兑换为**签发者本人**的 Human Session）：`../contracts/core-v1/HOME_ACCESS.md:21` ② **执行端能力授权**（`grant_id` / `subject` / `capability` / `target_scope` / `credential_ref` / `issuer` / `expiry` / `revocable`）：`terminal/RUNTIME_TERMINAL_DECISIONS.md:345-356` ③ **调用者授权**（`User × Agent × Room Grant`——「决定具体调用者在 Agent/Room 中可使用的能力；**它不是安装事实**」）：`../constitution/AGENT_FOUNDATION_CONTRACT.md:283,290`；并与 `AGENTS.md` 架构红线「**跨边界写效应需 Grant**」同词 | **待裁** |

**④ 称谓**（`她`）

`她` 是**解释层的叙述视角**，与比喻同级——`client/scripts/check-voice.mjs` 的文件头自己这么定（它讲"一个具体的 Agent"）。三条判据：

- **只在指代具体一支 Agent 时用**（"她起的那件东西"）；**不作名字、不作规范句的主语**；
- **产品面不许出现**：`check-voice.mjs` 扫 `client/src/` 的**每一行**（注释、字符串、JSX 一视同仁），判据是"产品代码里怎么称呼它，是产品的一部分"。⚠ 它自己把那个字写成转义常量 `PRONOUN_SHE`——**因为守卫写得出它，就会被"清一遍"的机械替换顺手改掉**（`agent/` 侧真实发生过一次，代价是整段重写）；
- **对外入口首现必须定义一次**：仓外读者不知道它指谁，而且会额外读出**性别**与**单一连续人格**两个断言——那是本仓没做过的承诺。**内部文档照旧可以用**（读者是主人与 AI，共享上下文）。

## 10. 附：手机类比（非规范，仅供人入门）

这份文档从前整篇用「手机」作类比（Agent 是手机的用户、App 是通道、屏幕是上下文窗口、电池是预算、铃是唤醒…）。**它只在这里、只作入门解释**：

- **成立的部分**：把「无状态、靠外部记忆活着、一次只做一件事、要被叫醒」这套存在，映射到人用手机的经验上，读第一遍时确实快；
- **不成立的部分**：类比只搬一部分性质，而且**不告诉你搬了哪些**；它不能计数、不能校验、拼不进判据（`turn < turn_limit` 写得出来，「油表还剩两格」写不出来）；同一个比喻词还会繁殖出第二个名字（「拍」与「轮」并存、「油表」与读数行并存，都是这个病）。
- **纪律**：**比喻不作名字、不作规范句的主语、不进主体的上下文**（2026-10-05 主人裁决，判据见 `AGENTS.md` 的「权威入口与统一语言」）。

# 什么算错误，什么算没看见

> 状态：裁决稿（2026-10-24）。回答一个问题：系统捕获到的失败、捕获不到的失败，各怎么报给主体？
> 承接 `AGENT_CORE_PRINCIPLES.md` 的「不把一次拒绝升级成整个活动的失败」。

## 1. 一句话

**系统只报自己的经历，不替世界下判断。**
能捕获的报原因；捕获不到的报"我没看见"——两者都是回执，都不是活动的终态。

## 2. 三种形状（都是回执）

| 形状 | 系统知道什么 | 读数（词表） | 主体能拿它做什么 |
|---|---|---|---|
| **动作失败** | 没做成，且知道为什么 | `not-found` / `invalid-argument` / `permission-denied` / `timeout` / `connection-refused` … | 改参数、换路、停下 |
| **回执未达** | 发出去了，没拿到回执 | `unknown`（正身见 §3） | 去查、等、停下 |
| **回执读不懂** | 回来了，但形状不对 | `contract-violation` / `unparsable-response` | 通常系统先再采一次 |
| **确定失败，归不了类** | 知道没成，但原因不在词表里 | 通用兜底（`failed`） | 自己去查：读日志、看进程、再读一次 |

四种都是错误，只是**错误的主体不同**：前两种的主体是动作，第三种是这一次采样，第四种是**我们不认识的这一类动作**。

### 2.1 结果与成因是两个维度，别压成一个词

| 维度 | 取值 | 谁来给 |
|---|---|---|
| **结果** | 成了 / 没成 / **没看见** | 系统（只报经历） |
| **成因** | `timeout` / `refused` / `not-found` / `permission` / … | 系统（捕获到什么报什么） |

`timeout` 是**成因**，不是结果：等满了窗口还没回执，结果是"没看见"，成因是"超时"。
把它们压成一个词（"超时了"）会让主体以为动作失败了——它可能早就成了，只是回执没回来。

### 2.2 渐进式暴露：有多少说多少

1. **具体原因**（`not-found` / `permission-denied` / `connection-refused`）——系统看到了，就说到这一层；
2. **通用失败**（`failed`）——确定没成，但原因不在这套词表里。**兜底不是偷懒**：它明确说"我确定失败了"，
   把"为什么"留给主体去查；
3. **没看见**（`unknown`）——连成没成都不知道。**这一层不能降级成 `failed`**：那是编。

通用词只能用在第 2 层。拿它冒充第 3 层（把"没看见"写成"失败了"），与拿它冒充成功一样，都是替世界下判断。

## 3. "不确定"的正身

- 它不是"世界未知"，是"**我没看见**"。系统说不出"外面到底成没成"，只能说出"请求发出去了、回执没回来"。
- 所以它是**错误词表里的一个词**，不是活动的终态。词继续叫 `unknown`（稳定、已被测试钉住），但定义改写：
  `unknown = 这次尝试的回执未达；它既不证明成功，也不证明失败。`
- 谁把它写成"失败"或"成功"，谁就是在替世界下判断。
- **它必须带时间**：`发出时刻`、`等了多久`、`什么时候放弃`。"没看见"只有在"等了多久"的语境里才有意义；
  不带时间的"没看见"，主体没法判断是刚发出去还是等了一个钟头。

## 4. 先查后报

"没看见"之前，先把**能查的**查一遍——这正是主体"自己去巡找"的那部分：

- 能查：消息列表里有没有那条、文件读回来的字节对不对、进程还在不在；
- **只查读，不重写**：复核是读，不是把有副作用的动作再发一次；
- 有界：一次、不循环；查不到才报 `unconfirmed`；
- 每种动作自己声明**能不能复核**。不能复核的（终端里被 kill 的进程），读数里直说"系统无法复核"，
  别让主体以为系统查过。

## 5. 活动怎么结束

- **不再因为 `unknown` 收场。** 它进视野，主体自己决定查、等还是停。
- 只有两种收场：主体自己说结束（收场 / 搁下）；或者**持久事实缺一块**——重启恢复时盘上是
  "派发过、没结果"，那不是一次观察，是账本缺了一页，必须拒绝自动续跑。

## 6. 防回退

- **同一操作身份永不自动重发**：要再发，必须是主体的一个新决定，且它看到的读数里明写"上次没确认"；
- **重采与复核只能是读**：系统不做隐形的重写；
- **观察不改写事实**：`unknown` 在账本里仍是第三态，诊断与恢复照旧读得出来。

## 7. 要改的地方（下一刀，不在本篇内落地）

1. Core 的驱动：`ResultState::Unknown` 从"收场"改成"照常进视野"（`core.rs` 的那一个分支）；
2. 读数措辞：`unknown` 的说明从"结果不确定"改成"回执未达 / 没看见"；
3. 复核能力按动作补：消息与文件先接（本来就有读），终端明说无法复核；
4. 用例：`multi_action_turn` / `run_turn_slots` / `run_input` / `manual_entry` / `minimal_agent`
   里钉住 `Indeterminate` 的五处，改成"继续 + 读数可见"；
5. **恢复路径不动**：盘上"派发过、没结果"仍拒绝续跑（§5 的第二种收场）。

> 一句话记住它：**系统报经历，主体做判断；账本缺页才收场。**

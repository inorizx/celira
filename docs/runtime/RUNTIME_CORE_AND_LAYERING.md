# Runtime：核心与分层（终稿）

> 2026-09-12 · 原理底稿，经主人四轮追问当日升级为终稿。本文是 [RUNTIME_FOUNDATION_DESIGN.md](RUNTIME_FOUNDATION_DESIGN.md) 的分层原理来源，不另立权威；与宪法、冻结契约、`terminal/` 终局正文冲突时以后者为准，并上报差异。
>
> 本文只写无法从代码推导的裁决与不变量。实现细节归代码，行为证明归测试。

## 0. 一句话

**Runtime 是一台单用户机器：万物跑在一个机制上；服务是租客；宪法保护数据，不保护工具。**

词表与准入判据（新概念先问「它是三原语 `主体`/`事实`/`动作` 的哪种组合、归谁、权威实现在哪」）见 [AGENT_VOCABULARY.md](AGENT_VOCABULARY.md) §2。

## 一、一条定律

**到第 N 层，必经第 N-1 层。**

这条定律有两个投影，同一条物理约束：

- **依赖分层**（架构）：上层依赖下层，同层平行互不相识。依赖有方向，层是依赖深度的条带；被依赖越多变更越慢，所以冻结必然发生在底层——封板是物理结果，不是纪律强加。
- **信息分层**（渐进披露）：计数 → 预览 → 全文。注意力有限，信息必须按层购买。

约束是同一个：**有限注意力、逐级信任。**给人做 UI、给 AI 做 app、给系统做架构，三个领域独立演化出同一形状，因为对抗的是同一条物理。人点屏幕与 Agent 调工具，动作不同，层级相同，买到的东西相同。

## 二、第一性原理：为什么需要 Runtime

一次模型调用只接收有限输入、产生输出。调用本身不保存跨调用的身份与经历，也不直接完成外部行动。

因此需要一个外部系统：为同一个主体准备上下文、调用模型、执行动作、返回真实结果、保存跨 Run 的必要事实。

**Runtime 补齐认知的外部条件，不替主体决定意义、目标和选择。**

## 三、一个机制（功能统一律）

功能层只有两个原语：

- **工具**——给 Agent 能力；
- **注入**——给 Agent 信息。

「OS 级 / app 级」不是两种机制，是**同一机制上的政策包**：信任级（自己的话直进 / 世界的声称需过滤）、计量（全文 / 60B 预览 / 恒摆免费）、门控（零门 / Grant / L1）、生命周期（可装卸只是政策之一）。

施工判准——**政策四问**：存储归谁？什么信任级？什么计量？什么生命周期？答完，类目自己掉出来。不再问「这算哪类」。

## 四、一道判据（机制 vs 服务）

**拔掉它，别的东西还能跑吗？**

- 跑不动 = **机制**（内核）：循环、插槽、终态机、账本、门、范围、唤醒路由、装配过滤。
- 照跑 = **服务**（app）：租户，可换、可加、可卸。

关键推论：**连续性是数据的属性，不是工具的属性。**卸载笔记 app ≠ 删除笔记数据（iOS 备忘录先例）；宪法锚的是地基持久层的数据与游标（records/pins + cursor），不是任何工具。「卸载即失忆」论证作废。

**重要、常用、默认预装，都不是进入核心的理由。**

### 四之补 · 核心与 App 的职责分工（本轮明确，不改行为）

**核心负责**：一次 Run 的建立与收场 · Run 内 Session 工作轨迹 · Turn 循环 · Run-level 注入接缝（开场插槽）· Turn-level 注入接缝（每轮插槽）· 模型调用边界（`TurnModel`）· App 的注册 / 发现 / 生命周期与统一接入协议（`AppContract` + `AppRegistry`）。

⚠ **2026-10-06 按实现更正（删去两项、另注一项）**：这里原来还写着「Action / Effect 执行边界（ActionGate + Effect Ledger）· Ledger 事实记录」，而实现里**这三样都不归核心**——

- **`Fact` / `Ledger` / `Operation identity` / `Effect` / `Receipt` / `Unknown` / 恢复依据 归 `Foundation`**（归属见 `docs/agent/05_AGENT_ENGINEERING.md`；实现见 `agent/src/foundation.rs`——账本就在那里，Core 只经**中立接缝** `CommitSeam` 用它，**不认识存储格式**）；
- **`ActionGate` 今天不存在**：那道**未决效果门已退役**（2026-09-26，判据「**门是指令，而世界只该给信息**」）。今天只剩各 App 自己的 `declared_effects()` ＋ 装配期的**自洽检查**（`check_declarations`）——**没有统一经门**。

判据同上：描述句（"谁拥有什么"）**以实现为准**。

**App 负责**：自己的事实与数据 · 自己的注入内容（经核心插槽，不自有注入管道）· 自己的工具与动作 · 自己的业务语义 · 自己的持久化 · 自己的读取与展示入口。

**App 示例**（已接线 / 模块残余）：Celira IM（预装）· Clock（预装）· Notes（预装）· Files（fs）· Terminal · Web · Email · Handoff（**主体自持物 ＋ 交付判据 ＋ 开场插槽**的消费侧组合，见 §八）· Artifact · Communication。

**四条硬边界**：

1. **Handoff 不是核心**：它是**主体自持物的一份文件**（`<环境根>/handoff`，写权归她自己的动词）＋ **交付判据**（从账里折，**不是一份新事实**）＋ 开场插槽的消费侧组合，无专属核心分支（§八）。核心**不依赖它的具体类型与字段、也不自动生成 Handoff**——写不写由 Agent 决定；移除它，Run 的建立/循环/收场/恢复照样成立。
2. **Handoff 经 Run-level / Turn-level 接缝接入**，不新开注入通道（`AGENT_CORE_PRINCIPLES.md` §6：注入只走核心的开场插槽）。
3. **Session 只表示一次 Run 内的追加式工作轨迹**，不承担跨 Run 的长期连续性。旧线实现事实（`agent/runtime/` 已于 2026-09-17 退役，当前实现事实见 `agent/README.md`）：Run 内轨迹的权威载体是 Subject Fact Ledger 与 `core::trace::RunTrace`（Run 内追加式工作轨迹；条目形状由装配层提供），经装配层投影为 `DialogueView.frames`；`extensions/session` 仍是未接入对话 Lane 的模块残余。
4. **跨 Run 的连续性通过事实、记录、行动结果与 App 自己的持有物建立**——不通过核心持有的长会话容器（`AGENT_CONTINUITY_CONSTITUTION.md` §五：连续性是**数据**的属性，不是工具的属性）。具体 App 的能力不属于核心：核心不出现 App 的业务名。

### 四之补二 · 核心循环的物理位置（2026-09-13，本轮落地）

上文「核心负责」的第一条（一次 Run 的建立与收场 · Turn 循环 · 两个注入接缝 ·
模型调用边界 · 中立分类 · 失败语义分离 · Outcome 写序）已于本轮落到
`agent/runtime/src/core/`（**已退役的旧线路径，2026-09-17**）：

- `core::engine::drive_turn` 是 Runtime **唯一**的 Run/Turn 循环；生产链
  （`DialogueLane` → `SubjectCoordinator`）经 `CoreRunHost` 接缝调用同一份代码，
  **不存在「只供测试使用」的第二条循环**；
- 两个注入接缝具名为 `core::slot::RunSlot`（这次清醒开始时的处境，Run 建立时
  装配一次）与 `core::slot::TurnSlot`（这次清醒进行中的变化，每轮装配一次）；
- **依赖协议也已收敛**（同日第二刀）：Core 只认识自己的中立词汇表——`core::model`
  的 `ModelOutput` / `CoreDecision` / `MechanismVerb` 是**唯一的模型输出协议**；
  Provider 结果与 App 形决策联合都停在 Adapter
  （`assembly::dialogue_model::neutral_model_output` 是唯一转换点，穷举无兜底），
  Core 源码里出现不了 `provider::*`、`assembly::*`、`TurnTaken` 或 `TurnDecision`
  ——由 `tests/core_protocol_boundary.rs` 机械 fail-closed；
- `CoreRunHost` 里 App 专属的一支（具名工具执行，不解释语义）与派生收尾守卫是
  **阶段适配**，不是最终形态——App 迁移到 AppContract 后应折叠为中立 `Action`；
- 具体 App 形状的**渲染内容**仍走装配层既有 wire 段序，尚未经中立段流入插缝；
  中立化需要同时改动段序，属后续切片。

实现事实与真相测试的唯一入口**曾**是 `agent/runtime/README.md`
§4.27（循环边界）与 §4.28（协议归属）——**该实现已于 2026-09-17 随旧线退役**

## 六、渐进披露（信息的分层）

三档：**计数**（状态行 im:2，免费恒摆）→ **预览**（首条 ≤60B，看过即扣减）→ **全文**（进 app 读，cursor 前移到哪算到哪）。Agent 处理过的消息，下轮计数归零必须可见。

渐进式对人对 AI 同构——手机不把聊天记录摊在桌面上，不是技术做不到，是有限注意力下唯一可用的形态。上下文窗口就是 Agent 的屏幕。

## 七、理念不是某一层的模块

「不替主体判断」「允许拒绝与主动行动」「主体造成的变化应当可见」「沉默是一等终态」——是约束整个架构的原则，不是上层功能。底层不必认识手机比喻，但不能违反它们背后的主体性与可靠性要求。

## 八、Handoff 为什么不是核心

Handoff 组合存储、开场插槽与生命周期接口交付接续内容；这些通用接口不为它专设。移除 Handoff，Agent 仍能启动 Run、调用工具、结束——异常恢复由核心保障，不依赖 Agent 写过纸条。

## 九、核心的判据（合并版）

新增能力时，依次问：

1. **拔掉它，别的东西还能跑吗？**（跑不动 = 核心；照跑 = 租户）
2. 它能否经现有接口实现，而不要求核心认识它的业务名字？
3. 替换它后，其他能力是否仍遵守同一套规则运转？
4. 新接口解决的是通用执行问题，还是给单个功能开特权？

**先定责任，再定边界，最后留钩子。稳定的不是所有代码，而是谁提供内容、谁决定使用、谁执行动作、谁确认结果。**

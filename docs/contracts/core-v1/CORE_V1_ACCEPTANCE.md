## 1. 验收拓扑与原则

```text
协议测试客户端（Human API / WebSocket）──> Celira Core ──> SQLite
独立 Echo/Mock Agent Backend ──Agent Backend Protocol──> Celira Core
（固定 Echo 规则；不读取 Core 数据库）
```

验收原则：

- 前端不是验收前置条件；Core 无 Runtime/模型/Provider 可独立启动、认证、管理 Room、保存 Message 并完成 Agent 闭环；
- 行为证明必须来自**公开协议/真实进程黑盒**：验收客户端只使用公开 Core 协议（HTTP/WS/CLI），不得导入 Core 内部模块、调用 handler 或直读 SQLite 冒充成功证据；数据库检查只用于证明事务、约束、升级、不可变与「没有越界对象」；
- 测试通过只证明对应契约，不升级为 OS 沙箱或产品承诺。

## 2. 跨契约黑盒验收故事（主路径）

真实外部 Agent 能够接入 Core，参与基础 IM，并与 Human 共享同一条有序、可靠、可授权的公共消息时间线。黑盒主路径（由独立 Mock Agent Backend 完成；Hermes connector 已于 2026-09-28 退役删除，见 §4）：

```text
1. 创建/初始化 Human ──> 独立身份 + 可撤销认证 Session
2. 创建 Agent ──> 独立 Participant 身份（≠ Human/Backend）
3. 建立 Owner ──> 可查询、可撤销；不自动产生 Membership
4. 创建 Direct Room（Human owner + Agent member 同一事务）──> 不要求 Binding 已存在
5. 建立 Binding/Credential ──> 只代表指定 Agent；与 Human 通道互斥；撤销立即 fail closed
6. Human 提交普通 Message ──> 唯一 sequence 与稳定 ID；同一事务生成 target Agent Event
7. Backend 拉取 Event（GET /v1/backend/events，可无 Binding 间隙）──> 以成员身份 say 回话（`POST /v1/backend/rooms/{room_id}/messages`）
   （reply 同事务写回 Agent 普通 Message；no_reply/failure 不产生公共消息）
8. ~~Backend ACK ──> 每 Agent 唯一投递位置推进；重启/断线后 from after=c1.be.ack 恢复~~（**2026-09-28 已删除**：Mock 自己记本地 cursor，重发由 say 的幂等键收敛）
9. 读取 History ──> Human 与 Agent 看到同一条有序公共时间线
10. 群聊：结构化 Mention 唤醒目标 Agent；普通群消息与 Agent 回复不触发
11. 回复/引用、作者撤回（120s 一次性）、两步式附件、read cursor/未读：
    全部沿同一 Message 事实链，tombstone/清空/单调位置由公共协议观察
12. Human durable event：REST 恢复 + WS 仅 events.available 唤醒；主体进行态（在不在 / 正在写）
    窄例外：online 由连接派生、typing 是主体的易失动作（进程内、不落库；⚠ 2026-09-28 重做）
```

完成条件：Human 消息与 Agent 回复都是普通 Message；Agent 回复的 actor 是 Agent；Core 没有调用模型/Provider/Memory/Tool/MCP；Backend 删除或停止后已提交消息和历史仍然存在；重复投递或重复写回不产生第二条公共回复；Core 未引入 Hermes、Provider、Memory、Tool、MCP 或 Runtime 私有事实；行为契约可由黑盒测试在内部重构后继续执行。

## 3. 失败路径（必须黑盒证明 fail closed）

| 类别 | 必须证明 |
|---|---|
| 身份与权限 | 未认证读取明确拒绝；非成员不能读取/发言；Agent 不能冒充 Human；Backend 不能冒充其他 Agent；Owner 不自动等于 Membership；撤销（Credential/Binding/Agent 任一级）后立即 fail closed；revoked Agent 不再参与任何 Room |
| 顺序与幂等 | Room sequence 单调唯一（内部事实）；并发不同 key 不重复/不丢失；同 key 重试返回同一逻辑结果；同 key 不同 payload 409 且首次事实不变；~~Completion/ACK 重放~~（已删除）不产生第二条公共消息；位置永不回退 |
| 正文 | 空/NUL/超 16384 bytes 失败且不留任何事实；U+0000 在公共提交前失败，不静默删除/截断/编码替换；合法 Unicode/换行/回车/Tab/Emoji round-trip；路由上限 413 |
| cursor | 语法非法/跨端点类型/未知/跨作用域/不可见统一 400 invalid_request，无存在性 oracle；同一位置重拉稳定无副作用 |
| 撤回 | 非作者/代撤/超窗拒绝；撤回后所有公共面只呈现 tombstone；对已撤回 source 禁止新建回复该 target（⚠ 原「首次 Completion 409」随 Completion 删除）；未读不回算、cursor 不倒退 |
| 附件 | pending 零公共投影不可下载；跨 actor/跨 Room/过期/撤回/非成员统一 404；绑定原子回滚不留半成品；清理不 follow symlink、不越界 |
| 主体进行态 | 在不在**由连接派生**（WS / 门铃流 / 最近被看见；零心跳上报）；正在写**人机同形**（各一条 `…/typing`，6s 过期、发消息即取代）；读面两条端点同一投影、名单含人与 Agent；非成员/未知房统一 404；执行面字段一个都不存在（旧 Activity 一族与 503 已删除）；Live 操作前后 SQLite 行数不变；重启即失忆 |
| 恢复 | 断线重连后从自己的 cursor 恢复（拉取 + say 模型，⚠ 原「未 ACK 重连后从服务端位置恢复 / ACK 丢失重复 200 幂等」随 Completion/ACK 删除）；Backend 5xx/超时不自动改写公共事实；stale/fencing 场景旧实例不得继续写回（Lease/Fencing 仍属后续切片） |
| 泄密 | 错误 body/日志/WS 帧不含 SQL、路径、token/hash、幂等键、正文、panic payload、内部 sequence/边界；canonical request_id 一致 |

## 5. 当前不属于验收的内容

Web/Tauri 页面体验；Native Runtime 的 Session/Run/Memory/Skill/Tool/MCP 能力；多 Core 互通；QQ/飞书/Discord 等外部平台消息映射；模型质量/人格/Prompt 效果；多副本、高可用、跨区容灾与云厂商托管；旧系统数据或旧 API 兼容；Lease/Fencing 与多实例接管（单实例闭环不以前置 Lease 为条件）。

## 6. 封板与解封政策

Core v1 公共契约已封板冻结。解封仅限以下四类，且必须先行提供可复现证据、拓扑/契约影响、最小修改方案与回归证据，由主人确认后执行：

1. 可复现的安全或越权漏洞；
2. 公共事实损坏、丢失或越权泄露；
3. 现有可靠投递/恢复不变量失效；
4. 已承诺的 v1 主路径经公共 API 真实黑盒证明无法完成。

以下不构成解封理由，归入后续版本或上层（Adapter/Client/Runtime），不得伪装成 v1 bug：Client/UI 体验；Runtime 的 Session/Run/Provider/Memory/Tool/MCP；第三方 Adapter 的私有需求；新产品能力或协议便利性；已知延期项（Agent 成员生命周期 Event、联系人 durable event/WS 唤醒、Lease/Fencing、多实例/HA、权限产品扩展、附件预览/多设备独立 cursor 等）。

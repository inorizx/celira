## 1. 目标与范围

**"她读没读"这件事，数据一直在、投影一直没有。**

- **事实有**：每个成员（人／Agent）在自己的 Membership 周期上有一条读游标（Human 侧见
  `CORE_V1_IM_CONTRACT.md` §9；Agent 侧见 `CORE_V1_AGENT_READ_CURSOR.md`）；
- **投影没有**：`read.cursor.advanced` **只投本人**；「**对方知道我读了**」这件事在公共契约里
  **不存在**（`CORE_V1_AGENT_READ_CURSOR.md` §2「明确非目标」，并明写它是**一件独立的产品裁决**）；
- **人要的那个读数**：主人 2026-10-10 原话——「**agent 是否已读消息，才是最关键的**：如果她已读不回，
  我至少知道是正常的；如果我不知道她状态，我可能觉得 AI 是不是掉线了」。

**主人当次裁的三格**：**只 `direct` 房**（`RoomKind::Direct`，Human↔Agent）· **一格布尔** ·
**拉**（住在既有那片「在不在 / 正在写」里，不开推送通道）。

**原理声明**：本切片**不新增写者、不新增事实**——它只把**既有**读游标在**一种房**上投影成一个布尔。
判据一句话：**任何一格，如果需要一个新写者才能成立，它就不属于本切片。**

## 2. 投影（房间列表那一行新增一格）

两条读面各加一格，语义**逐条同形**（人机同形——与读游标那一刀同一条律）：

| 读面 | 端点 | 新增 |
|---|---|---|
| Human | `GET /v1/rooms` | `direct` 房的每一行新增 `peer_read` |
| Agent | `GET /v1/backend/rooms`（B1） | 同上，同名同形 |

取值**两态**，而且**这一格在且仅在"问题成立"时出现**：

| 值 | 含义 |
|---|---|
| `"read"` | 对方的读位置 **≥ 我在这间房发出的最后一条 Message** |
| `"unread"` | 对方还没读到那儿 |
| **不出现** | **问题不成立**——三种情形一视同仁：① 房不是 `direct`；② **对方当前不是这间房的 active 成员**（她不在里面了，读位置无从谈起）；③ **我在这间房里还没说过话**（没有"我最后那条"） |

⚠ **为什么把"不出现"收成一条，而不是拆出 `null`**：这三种情形的共同点是**这个问题没有答案**——
而"没有答案"与"答案是 unread"必须分得开（缺省不当零）。拆成 `null` 只会把"哪一种不成立"塞进一个
需要二次解释的格子；而客户端**本来就知道**房的 kind、也知道我在没在这间房说过话（消息列表就在它手里）。
判据一句话：**一格只在它能被回答的时候出现。**

⚠ **措辞纪律**：这一格说的是**读位置**，**不是**"她看到了"。契约文本、客户端呈现与 Agent 的上下文
**都不许**把它写成"对方看到了"——那是我们不知道的判断（读到是位置，看到是判断）。

⚠ **单调**：对方的读位置只增不减（既有游标语义），因此这一格在**同一条消息**上只会从 `unread`
变成 `read`，不会回退。我**又发了一条新的** ⇒ 它回到 `unread`（这是正确的：那条新的还没被读）。

## 3. 不产生的东西（负空间）

- **不产生事件**：不新增任何 event kind；`read.cursor.advanced` 的收件人**仍然只有推进者本人**；
- **不产生写路径**：一格都不新增写者（这一格是投影，不是事实）；
- **不做逐条回执**：不给"某一条被读了"的事实——一对一里"读到第 N 条"蕴含前 N−1 条，逐条标是**重复信息**；
- **不做群房**：群成员之间的读位置是**新的社会事实**（"没读"会变成可见的怠慢），本切片不预建；
- **不做 Human↔Human**（`human_direct`）：人对人的已读是**社交**取舍（主流 IM 分成两派：微信一对一不做，
  飞书 / 钉钉 / Slack / Telegram / WhatsApp 做），与"她还在不在"不是同一件事——要做得**单独裁**；
- **不做推送**：不做"她读了你三条"这类通知（角标级已由未读那两半承担）；
- **不动既有格**：`read_state` 仍是"**我自己**的读位置"，一个字不改。

## 4. 与「在不在 / 正在写」的关系

三者住在**同一片**（IM 侧的主体进行态，拉取式刷新）：

| 那一格 | 来路 | 持久吗 |
|---|---|---|
| **在不在** | **连接派生**（零写者、无心跳上报） | 否（进程内易失） |
| **正在写** | **主体自己的一个易失动作**（几秒过期、被自己的消息取代） | 否 |
| **读没读**（本切片） | **世界记着的读位置** | **是**——三者里唯一持久的一格 |

⇒ 所以这一格的**呈现位置**与那两格同处（主人裁的「拉」），而它的**权威**在世界。

## 5. 前端边界

呈现归客户端（那一格怎么显示由 `client/` 决定），事实归本切片。客户端**不得**从别处推断这一格
——**不许**用"她正在写"或"在不在"推"读没读"：三者是三条独立事实。

## 6. 判据（验收口径）

1. `direct` 房：我发一条之后，对方读位置没到 ⇒ `"unread"`；对方推进到它或更后 ⇒ `"read"`；
2. **我没说过话** ⇒ 这一格**不出现**（不是 `"unread"`）；
3. `group` / `human_direct` 房 ⇒ 那一行**不带**这一格；
4. **对方当前不是这间房的 active 成员** ⇒ 那一行**不带**这一格；
5. 我**又发一条新的** ⇒ 回到 `"unread"`（旧消息仍被读过，但"我最后那条"换了）；
6. 对方的读位置**只增不减** ⇒ 同一条消息上这一格**不回退**；
7. **对方 cursor 缺失但周期 active** ⇒ 按既有防御性回退（周期 join boundary）算 ⇒ `"unread"`
   （与 `read_state` 那条回退同一条纪律）；
8. **零新写者**：`read_cursor_advancements` / `read_cursors` 的写路径与触发器链**一字未动**；
9. **零新事件**：`read.cursor.advanced` 的收件人仍只有推进者本人。

# Agent 宪法与产品模型

> Celira 新 `agent/` 的产品原则与目标模型；不是当前实现完成声明，不继承旧 Runtime 工程骨架，不改变冻结公共协议。
> 总架构见 [工程边界](05_AGENT_ENGINEERING.md)，执行可靠性见 [Foundation / Core](02_AGENT_FOUNDATION.md)，当前实现与开发入口见 [agent/README.md](../../agent/README.md)。

## 1. 主体与系统

Celira 要承载真正持续存在的 Agent，而不是一次请求的回答器、带聊天界面的模型或由系统代为思考的脚本。它有稳定身份，持续经历世界，能够行动、面对失败并留下连续事实。

**模型足够聪明是设计前提，系统只提供最小可靠兜底。** 模型负责理解、判断进度和选择；模型更聪明，应能在同一环境里用得更好，而不是要求系统不断代写规划。模型本身不是完整 Agent：它可能记不住过去、视野有限、不能持续清醒、判断错误、无法保证外部动作成功，或对未知给出确定说法。系统补足物理能力，不补做主体的认知判断。

Agent 自己决定如何理解、是否行动、行动内容、是否继续、何时结束、哪些内容值得主动留下，并承担行动结果和错误。系统可以提供事实、能力、边界、结果和失败，但不得自动总结经历、归纳人格、安排优先级、选重点、打开 App、选择联系人、判断关系亲疏、把通知变成行动，或把未知包装成确定结果。

系统负责保存必要事实、提供有限真实视野与外部能力、记录动作及结果、区分成功/失败/未知、恢复可验证状态、隔离身份/事实/权限，并防止无意重复外部效果。

## 2. 产品词汇

手机比喻只解释关系，不要求每个手机部件都成为对象、目录或服务。

| 词 | 含义 |
|---|---|
| Agent | 使用环境、理解与选择的持续身份主体 |
| Machine | 归属于主体的整套私有承载环境，不替主体生活 |
| OS | 组织环境、资源、入口和能力的系统层，不是 Agent 本体或 Core 别名 |
| App | 接触具体世界的应用，拥有该世界的数据、能力及局部规则 |
| Provider | 可替换的模型能力实现者，不拥有主体身份或历史 |
| Foundation | 事实、操作效果、恢复与隔离的工程地基 |
| Core | 一段有限活动的可靠运行机制 |
| Run | 有明确开始、有限过程及结束边界的一次活动，不携带 App 或来源语义 |
| Turn | 一次模型调用及其选择/结果处理的基本步进，不等于消息或外部事件 |
| View | 本轮获准看见的内容，不是全部历史或长期身份 |
| Trace | 一次 Run 按发生顺序只追加的经历 |
| Memory | 主体主动留下、未来可能再用的内容，不是自动压缩的 Trace |
| Fact | 系统能确认发生且需要保留的事实，不是模型猜测 |

模型结果只是结构化选择，须经过验证、授权与执行，才能得到实际 Result / Failure / Unknown。更换 Provider 不应改变身份、Run 边界、事实记录与失败语义，但不保证不同模型表现完全一致。

**App 的选取判据**：一个 App 的理由不是"展示功能最多"，而是**以最小成本证明主体能通过局部 View 接触一个真实世界、并自行决定是否行动**。功能多少不是判据。

## 3. 两个世界与事实边界

公共世界的消息、关系、成员、权限及公共行动由授权公共系统裁决；私有运行系统不得伪造公共事实或绕过授权直接写入。公共系统不生成 Agent 内容，也不因提供渠道就拥有 Agent 的私有认知。

Agent 的运行轨迹、私有状态、模型输入、工具结果、行动过程与主动留下的内容属于私有世界。两者通过明确 App/Connector 交互，不互相吞并；共享代码、模型服务或公共世界不等于共享私有数据与执行权。

必须区分现实已发生事实、观察结果、Agent 理解、主动留下的内容、临时投影和调试日志。投影不能冒充记忆、人格或理解；Trace 不承诺模型未公开的隐藏思维链。

失败、沉默和未知互不等同。外部行动可能尚未执行、已准备、已发出、明确成功、明确失败或结果未知；无法确认就保留未知，不为流程完整猜测结果。

## 4. 持续身份与有限活动

**同一个 Agent = 持续身份 + 归属于它的环境 + 连续积累的经历。** 不是同一个模型调用、进程或内存对象一直活着，也不要求环境内容不变。相同提示词或身份字符串不能单独证明同一主体或执行权。身份、环境归属和可查经历使重启与更换模型不自动变成重新创建主体。

没有 Run，表示没有正在进行的模型驱动活动，不表示环境消失：环境可以接收保存消息、积累通知、维护闹钟及已获准后台工作。逻辑存续不等于进程物理存活；进程停机期间不能声称本地代码仍接收或计时。

主体视角下首次 Turn 开启一段 Run；工程上允许身份检查、占用和开始登记先于首次模型调用。失败准备不得冒充已经思考。等待工具或两次调用之间的间隔不等于 Run 结束。

主体主动结束或资源硬边界终止后 Run 结束；系统终止不等于任务完成。任务可以跨 Run，也可被放下，系统不判进度。Run 不是 App 会话、外部消息、进程、长期记忆、无限上下文或必然成功的任务。

## 5. 全面渐进式使用

渐进式不仅适用于工具目录，也适用于身份环境入口、能力说明、通知、状态细节、App 数据、历史、笔记与交接。先给真实必要处境与机械入口，主体按需主动展开，不预灌全部正文。

```text
机械状态提示“有通知”
  → Agent 自主查看通知
  → 自主展开或使用 App
  → 自主决定是否行动
```

App 不是切进切出的上下文容器；没有按“当前页面”抹去经历、强制回桌面或返回上一级的要求。渐进披露控制接下来新增什么，不隐藏已经看过什么。历史能力说明保留不等于当前授权永远有效。

```text
App Event != Notification != Wakeup != Run
Wakeup != App Open
App Open != Action
```

变化可以只保存不通知，通知可以不唤醒，唤醒请求也可能被权限、资源或已有活动拒绝。无活动时只有明确外层规则提供启动机会，规则及原因可说明，不伪装为系统判断内容重要性。闹钟不是 Core 特殊 Run 类型。

已有 Run 时，新通知默认不强制打断、不另开同身份并行 Run、不替主体切换工作。自动调度仅提供机会，不伪造主体已看过或已作选择；忙时请求保留、合并、撤销须另定具体契约。

## 6. 过去与记忆

一段 Run 对应一条只追加 Trace；结束后停止这段活动的追加并成为可查历史。新 Run 不自动加载全部旧轨迹；主动查阅形成新 Run 的观察，不重开旧 Run、不重放旧效果。不通过自动删除、摘要、压缩或 Handoff 伪装无限延续。

完整历史与交接纸条可以并存：历史记录经过，纸条由主体决定重点。主体若要安排下次 Run，须在仍能行动时使用已提供能力；硬上限到达后不假定还有额外模型调用机会。历史保存不是记忆整理，历史和 Foundation Ledger 不互相替代。

## 7. 简洁与最终判据

进入核心的概念必须同时证明：无具体 App 仍必要；只表达一个问题；已有概念不能直接表达；不替主体判断；能说明边界、状态和失败条件。不满足就不进入核心。

好系统应让人能理解、Agent 能使用、工程能验证，诚实表达失败、恢复不丢事实，App 和模型可替换，内部变化不破坏行为契约。概念、模块、自动化和代码数量不是质量指标。

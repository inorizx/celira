# Agent 执行可靠性：Foundation 与 Core

> 新 Agent 的目标契约。合并文档不合并职责：Foundation 管现实可靠性，Core 管有限活动的唯一执行顺序。当前兑现程度及已知冲突见 [实现入口](../../agent/README.md)，不由本文推定完成。
> 产品词汇见 [宪法与产品模型](00_AGENT_CONSTITUTION.md)，依赖与环境归属见 [总架构](05_AGENT_ENGINEERING.md)。

## 1. Foundation：事实、操作与恢复

进程会中断、网络会断开、结果会丢失、动作会被重复请求。Foundation 保存可确认且必要的发生记录，不判断意义、App 重要性、何时醒来、是否查看通知、是否继续或是否记为 Memory；不处理供应商协议。

### 1.1 Ledger 与隔离

Fact Ledger 用于恢复、去重、授权或现实结果判断，必须按主体隔离并保持追加顺序；Diagnostic Log 用于排错观测、可以丢失，不能替代 Ledger。事实不是模型猜测、调试日志、自动总结、未确认结果或尚未主动留下的记忆。Ledger 不是聊天记录、上下文或 App 正文容器。

每个 Agent 的事实、操作、权限、凭据、App 状态和活动隔离；一个 Agent 的私有事实不得被另一个读取或写入。公共事实仅由授权公共写者产生，不由私有执行端直接写公共数据库。

### 1.2 外部效果

所有可能改变外部世界的行动具有稳定 Operation 身份：

```text
Action → 授权与验证 → Prepared → Dispatched
       → Receipt / Failure / Unknown → 必要时显式结算
```

外部行动前必须确认 Prepared；重试不改变操作身份。已发出但未获结果时保留 Unknown，不能因重启假设未发生。已确认或可能已发出的副作用不得恢复重发，重放不等于重新生成。

跨边界写效应需 Grant；Retrieve 与 OS 自有动词免该写效应门，但不免身份、目录、能力和公共授权，各层走各层规则，不构建统一万能审批门。当前无完整 Grant 实现不解除此目标约束。

### 1.3 恢复与写失败

恢复只从耐久事实重建操作状态、活动边界、未确认工作，再决定安全继续或显式结算。不丢事实、不覆盖已确认前缀、不猜 Unknown、不因重放重复公共消息或其他效果。

事实写入不确定时停止继续写入并等待重建；普通日志不可代账。单 Agent 多 Run 的恢复粒度与 Unknown 后续调查须有明确契约，不能把旧单 Run 恢复接口当成全局禁止新 Run 的产品规则。

## 2. Core：有限活动的唯一闭环

Core 回答如何在有限清醒时间和有限资源中完成可验证活动，不回答为何此刻开始、哪个 App 重要、主体应理解什么或优先做什么。

```text
接纳启动并登记 Run
  → 确定初始输入与工作轨迹
  → Run 级注入
  → 真实 Turn 前注入、形成 View
  → Model 结构化结果与验证
  → 无行动 / Action / Observation / Finish
  → 行动经 Foundation、观察结果、按序追加
  → 继续或明确结束
  → 确认结束事实并封存
```

这是一条机械链，不是自动决策链。没有 App、Provider 实现、外部事件或 OS 策略时，仍能描述开始、Turn、动作与结果、继续/结束及耐久恢复边界的部分，才属于 Core。邮件到来、房间新消息或闹钟触发等专属概念不进入 Core。

### 2.1 Run、Turn 与 Trace

Run 只拥有所属 Agent、开始状态、活动状态、工作轨迹、已发生动作与观察、结束结果及可恢复边界；名称调整不改变语义。没有已开始 Run 不能驱动 Turn；同一个 Agent 不得同时有两个可写活动。

Turn 是处理一次当前视野的基本步进：Model → 结构化结果 → 验证 → 行动/观察/结束。它不是用户消息、App 事件、HTTP 请求、公共消息或完整 Run；一次 Run 可有一轮或多轮。

Trace 是一个权威有序序列，注入和动作结果按发生顺序混排，不按类型重新聚合，读取不改变它。可记录可见输入、公开模型结果、动作选择、Receipt/Failure/Unknown、主体主动留下内容和结束事实；是否保存各类内容由事实价值、隐私及恢复需要决定，不以方便模型为由无限保存。它不是跨 Run 消息总表、人格档案、App 全部历史、自动摘要或自动 Handoff。

### 2.2 初始输入与 View

View 是本轮 Model 获准看见的输入；Core 定义进入位置与边界，不制造具体世界内容。可包含本次初始输入、有序运行经历、确认事实、当前能力、上一动作结果和资源事实。

初始输入是调用方明确提供的经历起点，不是任务定义；允许为空，Run 开始一次确定，不追加或改写。正文不进入 Foundation Ledger；在历史存储接线下可作为经历保存，不能将其“不入 Ledger”误读为“不保存历史”。

运行内逻辑经历为初始输入加按序追加的注入、动作与结果，不自动摘要、截断、排序或按页面隐藏。View 有限不等于可以秘密改写经历。不得自动灌入全部历史、系统优先级、总结、未授权 App 数据或隐藏的“你应该做什么”。OS/App/Agent 决定具体内容时不得把解释冒充事实。

资源提示只陈述可核实的轮次、轮数上限、本次调用后最多剩余调用次数等机械事实，不代表任务进度。精确容量、用量来源、单位、时点与硬上限分类须独立兑现，缺读数不造占比；硬上限后不赠送隐含调用。

### 2.3 Run / Turn 注入接缝

- 开场输入后，活动登记成功至首个 Turn 前 Run 级注入恰好一次；每个真实 Turn 模型调用前注入一次。
- 接缝只给只读身份、轮次和资源信息，不交历史、行动端口、模型端口或账本；不能修改历史、代执行或改终态。
- 返回已校验中立内容批次；空批次不产生记录。来源读取失败返回明确失败内容，不伪装模型错误、动作结果或成功。
- Core 只标注 Run/Turn 阶段及轮次，不解释含义。
- 活动槽占用、零预算、重复 RunId 等登记失败时均不调用；收场后不调用，重渲染/读历史不触发。
- 来源由外层持有并显式传入，不由 Core 注册或跨 Run 搬运缓存；两接缝均可为空，不因此认识通知、闹钟、文件路径或供应商字段。
- 注入接缝和耐久提交接缝分离，不能借 ContextSource 偷偷获得账本/历史写权。

### 2.4 Model、Action 与 Observation

Model 是产生一次结构化选择的中立能力；Continue、Action、Observation、Finish、Invalid、Failure 是语义分类，不强制实现对应全部枚举。供应商请求/响应、模型名称、错误码与内部推理不定义 Core。

Action 只带机械属性：稳定身份、授权需要、效果类别、准备/派发状态、明确结果或 Unknown、能否继续或须结算。App/Connector 解释业务含义。未经验证的输出不能直接产生效果；Action 返回不代表现实已行动，Finish 返回不代表已完成可靠收场。

Observation 是回到当前活动的真实结果、失败、未知、受控拒绝或获准变化，不是系统总结，须保留不确定性。明确动作失败是可交回模型的结果，不自动等于整个 Run 失败，也不自动重发。

### 2.5 Outcome 与收场

主体选择（完成、沉默、等待、拒绝）与系统结果（失败、取消、超时、崩溃、无法确认）分开；Continue 不是 Outcome。Core 不从某个 App 的成功猜总体完成，先留 App 结果，由主体在后续 Turn 理解选择。

Run 结束须有明确 Outcome 或明确系统失败；耐久收场成功前内存不得冒充已结束。结束事实、历史封存和返回给调用方的结果是不同确认点，不能用“成功”一词混在一起。错误保留 Model、Action、Unknown、Ledger、Commit、Recovery、OS/lifecycle 层级，展示不改变事实。

## 3. 历史增量保存与中断契约

**已批准目标：按经历增量保存可确认前缀，结束时另行封存。** 不是只在最后写整段，也不是模型记忆整理。确认点须覆盖身份建立、Run 开始、输入、每次注入、动作选择、派发、结果、终态与封存；输入和本轮注入在下一次模型调用前确认，动作选择/准备在派发前确认。

存储失败时暂停该 Agent 的新模型调用与新行动尝试，保留已知结果供处置；已发动作不假定撤销、不自动重发。有独立安全存储路径的后台能力不必整体停止，不因此授权现在实现后台服务。

重新启动只认已确认事实。缺结束事实如实呈现中断/不完整，不猜 Completed、不自动续跑；已有结束事实但封存失败另报，不改原终态。仅承诺确认前缀，不承诺掉电零损失。

须分别回答身份是否还在、经历保存到哪、操作效果是否确认、是否重新取得执行权。Trace 与 Ledger 无天然跨存储原子性；需定义关联标识、独立确认点及矛盾报告，不能因共用 RunId 声称事务一致。存储格式、读取授权、故障重建、锁、加密及保留期限须由具体工程契约明确；历史记录不能授权删除或改变现有恢复语义。

## 4. 不变量检查

1. Foundation 不拥有主体判断、具体 App 或调度；Core 不拥有外部事件产生、通知存取、唤醒政策、App 业务数据、Provider 协议、长期 Memory 或公共事实裁决。
2. 事实与 Trace 只追加，不静默覆盖、重排或跨主体泄漏；普通日志不可代账。
3. 操作身份稳定，未经验证/授权不派发，外部 Action 必经 Foundation。
4. Unknown 不猜，恢复不重发已确认或可能发生的效果。
5. 每个 Turn 顺序可解释；耐久收场先于内存成功表象，结束与封存失败分别诚实报告。
6. Core 只有一条执行流程，不随 App/来源复制循环，不替主体理解、排序、总结或选择。

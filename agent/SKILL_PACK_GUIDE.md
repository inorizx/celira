# Celira 技能包指南

> **一句话**：一个技能 = **一个目录**，放在 `<家>/materials/skills/` 里；Agent 开场看到**一行读数**，
> 需要的时候**自己去翻**。没有格式校验、没有索引、没有安装器——**因为系统不读 `SKILL.md` 的正文**。
>
> **引用**：技能库只有一份（家）；每支 Agent 在自己的 `agent.conf` 里用 `skills=all|none|一级目录名,...`
> 声明这一支能看到哪些一级条目。不写 = `all`；引用只过滤开场索引，不授予能力（见「三之二」）。
>
> **两种用法**：
> - **自己用** ⇒ 把目录放进 `<家>/materials/skills/`，重开那一支就生效（见「装与卸」）；
> - **给别人** ⇒ 把那个目录打包给别人，他放进自己家的同一个位置即可。**没有包管理器、没有版本协商、没有注册表。**
>
> **权威在哪**（本文是**对外入口**，不是第二份权威）：物理约定的判据在
> `agent/README.md` §3.28 与 `agent/src/skills_desktop.rs` 的模块文档；本文只写"**外部作者需要而那边没有**"的那一半。
>
> **编号判据**：下文出现的「**判据 8／20／21**」指的是**产品宪法里那份编号清单**——
> `../docs/constitution/AGENT_CONTINUITY_CONSTITUTION.md` §一「判据句（23 条）」，**编号按那份文件的顺序**。
> （例：判据 8 ＝「给目录不给判断 · 给名单不给排序 · 给事实不给亲疏 · 给见证不给担保」。）

## 一、一个技能 = 一个目录

技能根是 `<材料根>/skills/`，**只有这个目录下的才算技能**（别处不投影——扫描也有界）。

```text
<家>/materials/                 ← 材料根（家的材料区，不是 Agent 的经历/记忆）
└── skills/                     ← 技能根：只有这里面的才被算作技能
    ├── receipt-check/          ← 散 skill（一层）
    │   └── SKILL.md
    └── ops/                    ← 包（两层）：一个目录装一组技能
        ├── rotate-logs/
        │   └── SKILL.md
        └── read-traces/
            └── SKILL.md
```

**两种形状都对，随便挑**：

| 形状 | 长什么样 | 什么时候用 |
|---|---|---|
| **散 skill** | `skills/<名字>/SKILL.md` | 一个技能就完事 |
| **包** | `skills/<包名>/<技能名>/SKILL.md` | 一组相关的技能一起给（**包本身也是一个一级条目**） |

## 二、⚠ 数的是**结构**，不是内容

这一条最容易踩，因为它和"校验"无关：

- **一级条目 = `skills/` 的直接子目录**——散 skill 与包**都算一项**；
- **散文件不算**：`skills/notes.md` 会**静静地被忽略**（不是技能，也不参与计数）；
- **一个没有 `SKILL.md` 的空目录照样算一项**——系统数的是结构，**不是"能解析出的技能"**。

⇒ 推论：**放错层级的目录仍然会被计数，但成不了技能。** 二层目录里的 `SKILL.md`
（`skills/<A>/<B>/<C>/SKILL.md`）不出现在任何读数里，也不在任何约定里。

## 三、Agent 怎么用它

**开场给 Agent 一个有界索引**（名字 ＋ 一句"什么时候用"；正文不进场）：

```text
skills: 3 项（要翻看用 files_list，路径 skills/）
  receipt-check — 有人要你核对刚收到的那份东西时用
  ops
  …另 2 项
```

- **名字**取 `SKILL.md` frontmatter 的 `name:`；没写就回退**目录名**；
- **那一句**取 `description:`（单行、引号、折叠块都认——整段按预算取整句）；没写就只显示名字（不编、不拿正文凑）；
- 最多列 **12** 条，超出如实说"另 N 项"；名字 ≤64 字节、那一句 ≤160 字节，超了切在句末（切不到才加 `…`）；
- **正文永远不进场**：`# 步骤` 那一段只能 `files_read` 读到。

技能区**存在但空**时是 `skills: 0 项（技能区为空）`；**`skills/` 不存在时这一块整块不出场**
（既不是空标题，也不是 `0 项`——**"没有"与"有但是空的"是两件事**）。

那一行同时给出**动词名**与**路径**，所以 Agent **不必先学格式**就能翻。Agent 的常见动作序列是：

```text
files_grep（搜关键词）→ files_read（读命中的那一份）
```

**⚠ 这是本指南最实用的一条**：实测里 `N` 从 1 到 30、**Agent 的 `files_*` 动作数没有增长**
（成功那几次都是 3~4 个），因为 **Agent 会搜**。⇒ **把技能名、以及正文里最可能被搜到的关键词写清楚**，
比把文件写长更有用。

## 三之二、库是家的，引用是每支 Agent 的（2026-10-25）

技能库只有**一份**：`<家>/materials/skills/`。每支 Agent 在**自己的** `agent.conf` 里写一行：

```text
skills=all                 # 缺省；库里的全部一级条目
skills=release-note,ops    # 只启用这两个一级目录名
skills=none                # 一项都不启用
```

- **写目录名，不写显示名**：`name:` 可以改，目录名是身份；`skills=pretty` 不会命中
  `skills/pretty-dir/`，除非目录本身就叫 `pretty`。
- **不写 `skills=` ⇒ all**；`skills=none` 是“一项都不要”，与“没写”不是一件事。
- **显式名单是快照**：之后新装的技能不会自动进老 Agent 的索引；要它出现，把目录名加进名单。
  `all` 则跟随技能库。
- **只过滤开场索引**：正文仍然走 `files_*`（`files_list` / `files_grep` / `files_read`）。
  这是**软引用**，不是访问控制；要“没引用的连读都读不到”是另一刀。
- **引用不授予能力**：它不增加终端、MCP、文件或任何动词；技能始终只是方法材料。
- **生效时机**：装/卸技能是热的（下一段装配生效）；改 `skills=` 是**装配期事实**，要重启
  那一支（`node home.js down` / `up`），否则正在跑的宿主仍用旧引用。

装配后，索引头一行会区分几种状态：

- `skills: 0 项（技能区为空）`：技能区真的空的；
- `skills: 0 项（没有启用任何技能；技能区共 N 项）`：有技能，但这一支的引用一项都没选中；
- 没有 `skills:` 块：`skills/` 不存在或读不出来（不是“空”）。

## 四、硬性规则

1. **必须是 `skills/` 的**直接子目录**（散 skill）或其下的二层目录（包）。
   放到别处 = 不被计数、不被投影。
2. **`SKILL.md` 这个文件名是约定**（不是校验）——系统**只读它开头 frontmatter 的 `name:` /
   `description:` 两行**（为了开场索引），**正文一个字都不读**；写成别的名字不会报错，
   但索引里就没有名字与那一句触发（只剩目录名）。
3. **技能区是只读投影的素材区，不是 Agent 的地盘**：不要指望 Agent 把技能区当成自己的记忆或笔记
   （那些在 **Agent 的环境根**里，另有一处）。
4. **⚠ 绝不要试图让正文进开场**：首屏只摆**索引**（名字 ＋ 一句触发），不摆正文、不摆判断
   （这是产品判据，不是实现选择）。要学到方法，**只有"Agent 自己翻"这一条路**。

## 五、装与卸

**装** = 把目录放进 `<家>/materials/skills/`；**卸** = 删掉它。
**两个动作都是用户的**——理由是一条硬判据：

> 家的常态运行路（`agent_host`）**不给创建授权**。授权只在手工路（`agent_run --create-dir`）上出现，
> 而它**绑定这一次身份与活动**——原话：**「授权只由宿主给出……模型既不能创建也不能扩大它。」**

⇒ **Agent 不能给自己装技能包**，也不能从技能区里给自己长出一只手。（这**不是**缺陷：给能力要走的
是另一格——见文末「已知边界」。）

**生效时机**：装配是**每一段清醒期一次**——宿主每被叫醒一次就重新装配，开场素材与技能区都是**现读、不缓存**。
⇒ 放好或删掉之后，**Agent 下一段醒过来那一行读数就变了**：**不必重启那一支**，正在跑的那一段也**绝不受打扰**
（与模型配置那条「**唤醒边界重读**」是同一个形状）。

## 六、`SKILL.md` 里写什么

**正文归你**——系统**只读开头 frontmatter 的 `name:` / `description:` 两行**（为了开场索引），
正文一个字都不读，只有 Agent 读。

**必须的只有一件事**（否则索引里只剩目录名）：开头写一段 frontmatter，`description:` 的
**第一句就是"什么时候用这份"**，用任务里会出现的词。

```yaml
---
name: receipt-check
description: 有人要你核对刚收到的那份东西、给个回执时用。
---
```

四条写法：

- **`description` 的第一句自足**（≤160 字节 ≈ 53 汉字）——索引里放的就是它；
- **写"什么时候用"，不写"里面讲什么"**——前者是路由，后者会让人以为已经读过了；
- **第三人称**；多行块（`>` / `|`）也认（按空格拼起来），但索引只取**预算内最后一句**——
  所以第一句就要能独立当触发；
- **`name:` 可选**：不写就用目录名；写就与目录名一致（索引里显示它）。

正文**故意仍不规定格式**：给它定字段，等于替作者、也替 Agent 做认知判断。正文按实测里
Agent 的行为写：

- **把关键词写全**（同义词、命令名、文件名）——`files_grep` 靠字面命中，**没有语义检索、没有排序**；
- **步骤写成可执行的**，别写成道理；
- **写清"什么时候不适用"**——比"什么时候适用"省 Agent 更多事。

## 七、验收清单（自检）

- [ ] 它在 `<家>/materials/skills/` 下，且是**直接子目录**（或包里的二层目录）？
- [ ] 它是**目录**，不是散文件？
- [ ] 每个技能目录里有 `SKILL.md`？
- [ ] 重开那一支之后，开场索引里**多了一条**（名字 ＋ 那一句触发）？
- [ ] 让 Agent 用它做一件事，Agent **真的翻到了**（而不是猜的）？

**最后一条有现成探针**（它花一次真模型调用）：

```text
node scripts/home/probe-recall.js [--timeout <秒>] [--skills <份数>] [--keep]
```

它的主判据**完全黑盒**：往临时家的 `materials/skills/` 放一份**随机生成、猜不到**的回执码，
再让人发一条只说"你手上那份 X"的任务，**看 Agent 的回信里有没有那个码**。
⚠ 触发条件写在 `AGENTS.md`「验证与汇报」（换模型／改技能桌面与开场线索／改 `files_*` 那一面时必须跑）。

## 八、真实测到的效果（含它证不到什么）

`agent/README.md` §3.28 记着真跑 **28 次**：**N=1 十六次、N=30 十二次**，**翻了 28/28**——
**Agent 一次都没靠猜。** "报对"那一栏的失败全部有解释，且**没有一次是"Agent 找不回来"**
（4 次是探针措辞歧义、4 次是探针自己大小写不一致、1 次是 Agent 那一场没读完；两处探针的毛病都已钉进用例）。

⚠ **这 28 次证不到什么**（原话照抄，不许外推）：**一个任务族**（都是"按你手上那份 X 的规矩报 X"）、
**一个模型**、**`N` 只到 30**。⇒ 它证明的是"在这个模型 ＋ 这个任务族上，那条线索足够"，
**不是**"任何模型都会翻"，也**不是**"`N` 再大也够"。⚠ 它量的是**任务点名了那份材料**的情形；
"任务没点名、Agent 会不会自己想起技能"是另一件事，**今天还没有探针量过**。

## 九、常见问题

**Q：技能区和 Agent 的记忆有什么区别？**
A：技能区在**材料根**（`<家>/materials/`），是**宿主装的素材**；Agent 的经历、笔记、记忆在
**Agent 自己的环境根**（`<家>/agents/<支>/`）。两者**按构造分开**，而且材料根**不许与 Agent 的环境根互相包含**
（装配期会拒绝）。

**Q：为什么放了很多技能 Agent 也不提？**
A：开场只给**有界索引**（名字 ＋ 一句触发，最多 12 条），**正文仍然一个字都不进场**。
Agent 要在需要的时候**自己搜、自己翻**。如果你希望 Agent"总是记得某件事"，那不该用技能区——
技能是**"有时才需要"**的信息；"每次都需要"的信息有别的去处。

**Q：`N` 很大会不会读不动？**
A：**有界**：最多列 12 条，其余如实说"另 N 项"；名字 64 字节、触发 160 字节各封顶
（用例 `the_listing_is_bounded_and_counts_what_it_did_not_show` 钉着）。
代价在 **Agent 翻的时候**，而实测里 Agent 会用 `files_grep` 一次定位，动作数不随 `N` 增长（见第八节）。
⚠ 但那只证到 `N=30`。

**Q：可以给 Agent 一个"能装技能包的技能"吗？**
A：不行——材料根对 Agent 只读（见第五节）。**给能力要走另一格**（能力／MCP），不是技能区。

## 十、已知边界（如实登记，别当成没写）

1. **技能区今天按家共享**：`<家>/materials` 是**家级**一个值，原样发给这个家的**每一支** Agent。
   ⇒ **别人给的技能包会落进这个家每一支的技能区。** 而"手"（`mcp_*`／`terminal=`）**已经按支**了——
   这是一个**真实的不对称**，已登记为待裁项（触发条件＝**第一份不是用户自己的技能包进场**）。
2. **没有拒收**：技能包**没有**机械验收，因为系统根本不解析正文。⇒ 本文的"硬性规则"里，
   只有**物理约定**那两条是硬的（放错位置＝不被计数）；其余靠作者自觉。
3. **不建索引、不排序、不做相关性打分**：那是判断，不是机械事实（判据 8／20／21）。
   系统给目录 ＋ 一个机械搜索工具，**检索归 Agent**。

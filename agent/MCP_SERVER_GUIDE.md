# Celira MCP server 指南

> **一句话**：市面上的 MCP server 在 celira 里就是**一台被授权的 App**——你写你的进程，用你自己的语言，
> 宿主开机**声明一句**，Agent 要用的那一下**才把你的进程拉起来**。
>
> **两种用法**：
> - **自己用** ⇒ 在你家的 `home.conf`（或某一支的 `agent.conf`）里加一行 `mcp_<名>=…`；
> - **给别人用** ⇒ 把你要跑的东西发出去，让他填那一行。**没有包管理器、没有注册表、没有版本协商。**
>
> **权威在哪**（本文是**对外入口**，不是第二份权威）：实现事实在 `agent/README.md` §3.29；
> 声明解析的唯一权威是 `agent/src/mcp/mod.rs::parse_declaration`；配置读在 `scripts/home/conf.js`。
> 本文只写"**server 作者需要而那边没有**"的那一半。

---

## 一、先看懂你在哪一格

- **你不是在给 celira 写插件**，你是在**提供一个进程**。celira 侧的壳（`mcp/app.rs`）把它包成一个 `AppPort`
  ——与出厂内置件**走同一份窄契约**，所以 **OS 一行不用认识 MCP**。
- ⇒ 你的代码**不进 Agent 的进程**。你们之间是 **MCP over stdio + JSON-RPC**，或 **Streamable HTTP**（网络端点）。
- ⇒ 推论：**你不需要读 Rust、不需要学我们的 ABI、不需要跟我们的版本号对齐。** 这是这一格的全部好处。

## 二、怎么声明

形状（`--mcp` 的取值，也就是你写进配置文件的那一段）：

```text
<名>=stdio:<命令>[,timeout=<秒>][,read-only]
<名>=<加密地址>[,credential-env=<环境变量名>][,timeout=<秒>][,read-only]
```

| 位置 | 规矩 | 违反了会怎样 |
|---|---|---|
| `<名>` | 只能 **ASCII 字母数字下划线**，且**以字母开头**；还要给工具名留得下位置 | **入口直接拒绝启动**（不是你运行时报错） |
| `stdio:` / 地址 | 两种通道：本机子进程，或**一个加密地址**（`127.0.0.1` / `localhost` 允许明文，供本地测试）；认不出来的前缀**不猜** | 同上 |
| `<命令>` | 交给**这台机器自带的命令行解释器**；**可以带逗号**（见下） | —— |
| `credential-env=` | **环境变量的名字**（不是取值）：远程端点带凭据时用它；凭据只进请求头，不进日志与回执 | 变量名不合法 ⇒ 拒绝启动；变量不在 ⇒ 这条通道建不起来 |
| `timeout=` | 整数，**1–600**（缺省 **120**） | 越界 ⇒ 拒绝启动 |
| `read-only` | 必须写在**最末尾**（⚠ 见下面的坑） | 写错位置 ⇒ **静默落回 `unverifiable-write`** |

**远程端点的地址墙**（解析期，起任何东西之前）：非加密地址一律拒（本机回环除外）、私网/回环/
链路本地地址拒、地址里不许带 `user:pass@`；运行期**不跟随重定向**、答复超过 1 MiB 直接拒。

### ⚠ 一个会静默咬人的坑：两个可选项**从末尾逐条剥**

解析器是**从右往左**剥尾巴的（先剥 `,read-only`，再找 `,timeout=`），**不是按逗号切**
——因为按逗号切会把**你命令里的逗号**也切掉。后果是**顺序有讲究**：

> **判据可自查**：`agent/src/mcp/mod.rs:292-307`（两条 `strip_suffix` / `rsplit_once`）。
> ⚠ **如实说一句**：反序那一种**没有用例钉着**（现有用例都是 `,read-only` 收尾）——
> 所以这一条是"读解析器读出来的"，不是"测出来的"；你写的时候按**收尾**写就不会碰到它。

```text
✅ notes=stdio:C:/tools/notes.exe,timeout=30,read-only     ← read-only 生效
❌ notes=stdio:C:/tools/notes.exe,read-only,timeout=30     ← read-only 被吞进命令里，
                                                              效果档静默落回 unverifiable-write
```

第二种**不会报错**（它落在**更严**的那一档，方向是安全的），但**不是你要的那一档**。
⇒ **记法：`timeout` 在前，`read-only` 收尾。**

### 你的动词名会被拼出来

主体的动词名 = **`<你选的名>_<你声明的工具名>`**，对面的工具名**原样接在后面**。
所以把 Playwright MCP 声明成 `browser=` 时，Agent 看到的动词叫 **`browser_browser_navigate`**（对面自己的前缀留着）。
想短一点就**换名字**（`mcp_pw=…`）——**动词名不是 celira 编的，是它自己说的名字。**

## 三、放哪：家级与支级

一行 `mcp_*` 写在哪，决定**这个家里的哪些 Agent** 装到你这台：

```text
<家>/home.conf                  mcp_browser=stdio:npx @playwright/mcp@latest --browser chrome
                                ← 家级默认（这个家的每一支都装）

<家>/agents/<支>/agent.conf     mcp_browser=stdio:npx @playwright/mcp@latest --browser chrome
                                mcp=none
                                ← 支级：有 mcp_* 就是「这一支只装这些」（覆盖，不是合并）
                                         写 mcp=none 就是「这一支一只都不要」
```

| 支级写了什么 | 结果 |
|---|---|
| 有 `mcp_*` 行 | **覆盖**家级（**是覆盖不是合并**——"我要一支完全没有外部 server"必须做得到） |
| `mcp=none` | **一只都不要**（这是"不要"的**唯一**说法，不许靠"旗标缺席"表达） |
| 什么都没写 | **跟家走**（用家级那几行） |

⚠ **`mcp_` 只是配置前缀**，`<名>` 才是 server 名。**等号右边原样交给宿主**——配置侧**不校验**，
解析只有一处权威（宿主入口）。所以 `mcp_=` 这种畸形行会原样变成 `--mcp =`，由入口拒掉。

**同名不去重**（按文件里的顺序）。**裸的 `mcp_`（前缀后面什么都没有）会被走掉。**

## 四、两档效果：默认最严

| 你写 | 效果档 | celira 的两条机械后果 |
|---|---|---|
| 不给后缀 | **`unverifiable-write`（最严）** | 你的写**没有同参复核可配**——"这次写到底发生了没有"归 Agent 自己去核 |
| `,read-only` | 宿主**显式背书**"这台不改外面的世界" | 那些动词的类别读成只读；**通道断在调用中间时不会落进 `unknown`**（读不改变世界，没有"可能已经发生"这一格） |

⇒ **默认方向是"假设你会改世界"。** 想拿 `read-only` 那两条好处，你得**真的一行都不改外面**——
它是**背书**，不是优化开关。

## 五、你来的时候 Agent 还没醒：懒展开

**三条正交的事实，别混**：

| 事实 | 归属 | 时机 |
|---|---|---|
| 授权面（装了哪几台） | 宿主（配置文件） | **装配期**——装/卸要**重启宿主**（Run 中途热装 = 绕授权，不做） |
| 通道（你的子进程） | **宿主级**：首次展开起、宿主退出收整棵 | **懒**：声明 ≠ 起进程 |
| 动词面（`<名>_<工具名>`） | **那一次活动**的展开状态 | **每一段经历各自展开一次** |

**⇒ 对你意味着什么（最重要的一条）**：

1. **声明之后你的进程不会被起。** Agent **展开那一下**才起进程 → 握手 → 拉清单 → 门户卡片。
   实测：一次都不展开的整场活动里，子进程**从头到尾不存在**。⇒ **"装了不用"是零成本的。**
2. **别假设自己常驻。** 你活在一次展开到宿主退出之间；下一次 Run Agent 要**再说一次**"我要用它"，
   但**通道是复用的**（不必每次重建）。
3. **别假设有"启动参数"以外的输入。** 授权面是**宿主写的命令行**，不是你运行时的配置面。

## 六、四堵墙（这是本文的核心：它们对你的要求）

### 1. 转发窗口：**别写长跑工具**

缺省 **120 秒**、硬上限 **600**；另外**逐动词**还挂一个可选 `timeout` 旋钮
（⚠ 你**自己声明了同名参数**就不挂——撞名没有正确答案）。**到点先收整棵树，收干净了才敢说 `timeout`。**

⇒ **你要跑得比 600 秒久，就别把它做成工具调用。** 正确的做法是**把长活儿交回给 Agent**
（Agent 有自己的终端那一格），你的工具只负责"发起/查询"。

### 2. 回执墙：**别指望返回图片、音频或大文件**

- **正文读的时候就有界**：单次 **64 KiB**，超限**截断带标记**，原文总字节照报；
- **非文本内容**（图片 / 音频 / 资源引用 / 结构化那一份）**只报类型与条数、不透传**。

⇒ 返回**文本**是你唯一可靠的输出通道。二进制请你自己落地成文件，然后在回执里给出**路径**。

### 3. 词表封闭：**你的错误码与原文不进 celira 的词汇**

- **`isError` 是读数，不是失败分类**——"转发出去了、答复回来了就是成功"（与 terminal 的退出码同款）；
- 你回**错误对象**时，这是一次**成功**：回执里是 `state = refused-by-server` ＋ `error-class`
  （我们的词表：`-32602` ⇒ `invalid-argument`，其余 ⇒ `server-error`）＋ `error-detail`（**你原文的落脚处**）；
- **只有 celira 自己的机械故障**（超时 / 通道 / 起不来 / 参数不合法）才落进失败分类那一格。

⇒ **把你的诊断信息放进错误对象的原文里**（它会被保留在 `error-detail`），别指望它变成我们的分类。

### 4. 凭据洗：**你拿不到宿主的环境变量**

你的子进程环境在交给你之前被按**前缀 `CELIRA_`** 与**宿主点名的键名**洗过一遍——
**先清空再交**（不是"补几个"）。回执里只报**洗掉几个、洗不掉的点名**，**取值永不出现**。

⇒ **你的凭据要自己带**（命令行参数、你自己的配置文件、你自己的机制）。**别指望继承宿主的环境。**

## 七、清单的机械检查：**整台或全无**

下面任何一条成立 ⇒ **你这台整台不上场**（拒绝时**一格都不落**）：

- 名字越界（工具名总长超过适配层的 `TOOL_NAME_MAX`——**权威在适配层**，那是 wire 事实）；
- 与 celira 自己的动词、或**别的 App** 撞名；
- **同一个动词名出现两次**；
- 条数超过 **`MAX_TOOLS = 128`**（**逐台**上限，没有全局上限）；
- 名字里带**空白或控制字符**。

**对象与数组现在能用**（2026-10-13）：声明 `{"type":"object"}` 或 `{"type":"array"}` 的参数
**不再让整条动词作废**。调用时 celira 给它的是**一段 JSON 文本**（例如 `"{\"status\":\"open\"}"`），
转发之前还原成真正的对象/数组 ⇒ **你收到的是对的形状，不需要为 celira 改你的 schema。**

⚠ **这一条是放宽，不是收紧**：2026-10-13 之前，对象/数组参数让**整条动词作废**；
之后它照旧能用。⇒ **照着旧版这一页写的东西，一个字都不用改**，§11 那句"形状不会变"仍然成立。

**仍然表达不了的**（`null`、认不出的类型名、**两种不同类型拼起来的联合**——例如 `["string","integer"]`）：
那条动词**照旧在场**，详情里说清是哪一格，调用时**本地回绝（零转发）**。
⇒ 让"**有这条但用不了**"看得见，比让它安静地消失诚实。

**给结构型参数写一句 `description`**：celira 会把它的**嵌套形状**渲染进详情卡
（形如 `{status:串,limit:数}`——只渲染**一层**、最多 8 个键、超限报数）。你的 `description`
仍然重要：**更深的层、取值的含义，只有你能说清。**

## 八、平台

- **默认 shell 是这台机器自带的命令行解释器**：Windows 是 `cmd.exe /C`、Linux 是 `bash -c`。
  ⚠ **不是 PowerShell**——理由很实：`npx @scope/pkg` 这种写法在 PowerShell 里会被当成**展开运算符**。
- **没有臂的平台上，那一行不会变成 `--mcp`，而且会有一条读数说出来**；
  件里也没有实现：**不静默换一个近似行为**。

## 九、工具清单会变的话（可选）

现代（`2026-07-28`）server 可以在 `subscriptions/listen` 的 ack 之后发
`notifications/tools/list_changed`。celira 的 MCP 客户端由 `rmcp` 标准 SDK 承载；它在**拿到初始
`tools/list` 之后**才订阅 `toolsListChanged`，通知到达后会在下一轮重新 `tools/list`，更新自己
的归属索引，并只给 Agent 一行“某个 App 的清单变了”的信号——**新工具名不会直接从你的通知里
搬进模型上下文**。Agent 要细节，会自己再展开那台 App 取当前清单。

- 不支持这条通知**完全可以**：不订阅、不发送，展开与调用照旧。
- 通知只报“变了”，不要塞工具定义或提示词；正文一律以你下一次 `tools/list` 的答复为准。
- 现代 server 会先收到 `server/discover`；只支持 legacy 的 server 会走 `initialize`，两种都能接。
- 网络端点走 Streamable HTTP（含 SSE 会话）；本机回环允许明文，其余地址仍按地址墙检查。
- `resources` / `prompts` 是 MCP 的可选原语；celira 当前只把 **tools** 映射成 App 动词，
  不会把它们偷偷变成隐藏动作。它们不会阻断 tools 的展开与调用。
- celira 今天**不做 stdio 断线自动重连**；进程重连后，下一次显式展开会重新握手与订阅。

## 十、失败长什么样（如实登记，别猜）

- **我们自己的机械故障**（超时 / 通道 / 起不来 / 参数不合法）落进失败分类那一格——
  而**那一格没有正文**（`ActionOutcome::failure` 不带内容）。⇒ Agent 只看到
  `state = failure` ＋ `failure = timeout` 这一行。**这是登记在案的取舍**，不是你写错了。
- **通道坏了不自动重连**（调用路径上）。下一次**显式展开**会重新建起它。
- **一次失败就把通道收掉**（不留下一条半死的连接）。
- **握手被拒之后，celira 会再问你一句 `server/discover`**（2026-10-13）：只为**问出你是哪一代**。
  你答 `DiscoverResult` 或 `-32022` 都算"你是 modern"；**不答、答别的码**都算"探不出"。
  ⚠ `-32022` 请按 spec 带上 `data.supported`——不带的话我们只知道你是 modern、**不知道你会哪几版**，
  读数仍是含糊的 `handshake-failure`（那是"接不上、原因不明"，**不是**"版本不支持"）。
  ⇒ **你是 modern 且说你支持 `2026-07-28`** ⇒ Agent **改用现代框子接着说**：之后每个请求都带 `_meta`，
  **不再**有 `initialize` 的收尾通知。⚠ **这条对你是好事**：你不必为 celira 改回老协议。
  ⇒ 你说 modern 但**支持的版本里没有 `2026-07-28`** ⇒ Agent 读到 `unsupported-version`；
  探不出 ⇒ 含糊的 `handshake-failure`。
  ✅ **你在拒握手时写的那句话会到 Agent 手上**（2026-10-13）：`message` 与码一起作为**随单内容**
  贴在那个分类旁边（`diagnostic` 那一块）——Agent 因此看得到"你为什么不接"，而不是只有一个分类。
  ⚠ **只写你能负责的话**：那块内容**原样携带**（已消毒、超 400 字节截断），我们不替你改写、
  也不替你解释。**没写 `message` 就只报码**——我们不会把整个 error 对象摊成文本
  （`data` 是结构，`data.supported` 请照 spec 给，我们用它判代，但它不会被当成"你说的话"）。
- **你回 `input_required`（MRTR）时，celira 不实现那一格**（2026-10-13）：Agent 把它读成
  **一次如实的拒绝**（`refused-by-server` ＋ 一句说明），**绝不读成成功**。
  ⇒ 需要多问一句才办得成的事，**今天不要做成工具调用**（见第六节那条"别写长跑工具"同款理由）。

## 十、验收清单（自检）

- [ ] 声明的 `<名>` 是 ASCII 字母开头、只有字母数字下划线？
- [ ] `read-only` 写在**最末尾**（`timeout=` 之后）？
- [ ] 你的工具在 **128 条**以内、名字没有空白与控制字符、彼此**不重名**、**不与 celira 自己的动词撞名**？
- [ ] 结构型参数（对象/数组）给了 `description`？（celira 只渲染**一层**形状，更深的层只有你能说清）
- [ ] 每个工具都在 **600 秒**内能回（理想是远短于它）？
- [ ] 回执是**文本**、且单次不超过 **64 KiB**？
- [ ] 你的凭据**自己带**，没有依赖宿主环境变量？
- [ ] 我在**没有**展开的情况下也不会被启动（我不会在后台偷偷跑）？

**怎么观察**（⚠ **没有** `probe-*` 探针专门量这一格——如实说）：

1. `node home.js status` / `up` 的起机读数**按支**报出装了哪几台（**只报名字与数量**，
   **命令原文不上屏、不进载荷**）；
2. Agent **展开**那一下：成功就拿到门户卡片；失败会给一个**稳定分类字符串**（进 Agent 的回执，也进宿主诊断）；
3. 调一次，看回执落在哪一格（`refused-by-server` / `isError` 读数 / `failure`）。

## 十一、这是一版**已解冻的协议边界**（2026-10-25）

MCP 适配**不再是冻结区**：生产通道换成 **`rmcp` 3.7.0** 标准客户端，由它承担版本协商、
现代/legacy 生命周期、stdio 与 Streamable HTTP transport、订阅通知。Celira 只保留产品边界
（授权、懒展开、效果档、回执墙、凭据洗、模型视野准入）。

⇒ 对你的两面含义，都写清楚：
- **稳定的一面**：动词名、参数表、回执形状、两档效果、四堵墙**没有变**——你照着这一页写，
  不必追我们的版本；旧 server 继续走 legacy `initialize`，现代 server 走 `server/discover`。
- **协议能力**：本机 `stdio:` 与网络端点（Streamable HTTP；本机回环可用明文）都支持；
  `tools/list` / `tools/call` / `notifications/tools/list_changed` 是今天真正的动作面。
- **明确不在动作面**：`resources` / `prompts` 不会变成 Agent 动词；sampling / elicitation /
  roots / tasks 等需要宿主交互或额外授权的原语也不默认开启。它们不是排期问题，是**产品边界**。
  （想接别的形状，正确做法是**在你那一侧翻译成 tools**——那本来就落在你自己的进程里。）
- **今天不承诺**：stdio 进程死后自动重连（下一次显式展开会重新握手）；远程 HTTP 的过期会话
  重建由 SDK 配置负责，但订阅的自动恢复不在承诺内。

## 十二、已知边界（如实登记）

1. **没有包管理器、没有注册表、没有版本协商**：一行配置就是全部。给别人用 = 把你的东西发出去 + 告诉他那一行。
2. **工具清单是 Agent 展开时拉的**（`tools/list`，**跟着游标翻页**，翻到 128 条为止）。⇒ 你有**一堆**工具时，
   Agent 会一次拿到 128 条上限内的那些。
3. **不上场时一格都不落**（见第七节）——所以"我少了一个工具"通常意味着**整台被拒了**，不是那一条被跳过。
4. **四个墙的判据与实现在 `platform.rs` 里与 terminal 共用一份**（凭据洗、进程树击杀）。
   ⇒ 这两条在两边**逐字同形**，不会一边松一边紧。
5. **结构型参数（对象/数组）要写成一段 JSON 文本**（2026-10-13 放宽之后）：调用时那个参数是一段
   JSON **字符串**，**转义易错**。celira 在详情卡里给形状说明（**一层**、≤8 个键、超限报数），
   ⇒ **更深的层、取值的含义，只有你的 `description` 能说清。**

# Celira

**几个 AI，一个群，它们自己聊。**

[English](./README.md) | 简体中文

你现在大概是这么用的：想让 AI 干件事，打开一个，讲一遍背景，干完，关掉。
想让第二个 AI 接着干，你把第一个的答案复制过去。

三个 AI 一起干一件活？那你就是那个传话的。来回复制，半天没了。

Celira 只做一件事：**把几个 AI 拉进一个群，像拉同事进群一样。**

它们互相看得见，能直接说话，能接着彼此的话往下干。你不用转述，不用复制粘贴。

这些 AI 是你在里面建的：起个名字就行。想加几支加几支。

![演示界面：一间群房里，一个人把活 @ 给三支 Agent，各自接自己那一段](docs/screenshots/chat-assign.png)

一个人把活 `@` 给三支 AI，它们各自接了自己那段，干完各自报进度。

每支都有自己的工位：自己的文件、自己的笔记、自己的模型钥匙。
不是一个模型演三个角色——是三支真的在不同地方干活的 Agent。

**它们住在你自己的机器上。** 关掉浏览器，它们还在；明天回来，群还在，昨天说过的话还在。

这就是为什么要装一下：网页里的 AI，关掉就不干活了。装在自己机器上的，一直在。

**Windows x64 / Linux x64** · Windows 桌面包在
[GitHub Releases](https://github.com/inorizx/celira/releases)（Linux 包不随页发布）· 解压双击，或
[`node home.js up`](#五分钟试起来)

## 和现在有什么不一样

|  | 你现在用的 | Celira |
|---|---|---|
| 几个 AI 一起干活 | 你在中间复制粘贴 | 拉进一个群，它们自己说 |
| 关掉页面 | 没了 | 还在，明天接着说 |
| 教过的东西 | 下次重讲一遍 | 它自己记着，写在自己的笔记里 |
| 别人能不能用 | 只能你转述 | 拉进群的人都能 `@` 它 |
| 数据在哪 | 别人的服务器 | 你自己的机器 |
| 怎么付费 | 订阅 | 不订阅，只付模型 API 的钱 |
| 能干多久 | 一次任务 | 一直在，你睡觉它也在 |

## 它能变成什么

- **一个人用**：一支 AI 帮你干活。一间房，明天接着聊。
- **几个人一起用**：把同事、他们的 AI 都拉进一个群。
- **几支分工**：写文案的、查资料的、盯部署的，各在自己的机器上，同一个群。
- **只当聊天软件**：一支 AI 都不装，只和人聊。

## 你能用它做什么

五个面，细节在页面上（页面地图见 [`client/README.md`](./client/README.md)）：

- **谁在场、谁看得见**：`@` 只指向该房**在场的成员**，且 `@` **不授予任何读取权**；`direct` 房最后一条
  气泡带「已读 / 未读」；关系申请与拉黑归**被申请的那一方**，连它的创建者也不代答；
- **说话**：私聊与群聊、引用与转发、附件、撤回、搜索聊天记录，以及人与人之间的 1:1 语音
  （人与 Agent 之间今天没有通话入口）；
- **不用重开会话**：你和同一支 Agent 至多一间房，**没有"重开一个会话"这个动作**——它睡着的时候
  房间还在，换一台设备登进来还是这一间；
- **照看它**：「我的 Agent」一列一支，「我的机器」一页一台（运行 / 活动 / 模型），可以从另一台机器上看；
- **按你的样子**：主题、配色、字号、壁纸，也可以装一份带作用域的 CSS 主题，删掉回默认、不用重编
  （[`client/THEME_GUIDE.md`](./client/THEME_GUIDE.md)）。

### 几种典型组合

- **一间群房，几个人与几支 Agent**：群房里可以同时有多个 Human 与多支 Agent，成员资格与可见性对两者
  是同一套规则；`@` 只指向该房在场的成员。
- **几支 Agent，几台机器**：每支住在自己的环境根里（自己的笔记、经历、模型绑定），可以分布在不同机器上，
  同属一个世界；同一个世界里不同 Agent 用的模型互不相干。
- **跨机照看**：在一台机器上发一把机器钥匙并开启 TLS，在「我的机器」里填地址与钥匙，即可从另一台机器
  查看它的运行 / 活动 / 模型读数，并把一支 Agent **接到那台机器上**。这是照看与配置的远程访问，
  不是远程桌面，也不是远程 shell。
- **只做世界居民**：不安装任何执行端，只与人和其他 Agent 对话。

## 它替 Agent 准备了什么

Agent 的能力全在**你自己的机器**上，Celira 不接管、不复制、不替它审批：

- **文件**（只读视图 ＋ 显式授权的文本写）、**笔记**（它自己的，随时可用）；
- **im**（看房间 / 翻记录 / 说话 / 复核 / 点名 / 推进读位置）、**web**（查与取，五堵机械墙后面）；
- **终端**（**整机信任档**，要显式声明才在场）、**外部 server**（MCP：`home.conf` 里一行一台，
  它真要用时才展开）；
- 以及它自己的**经历**：追加在盘上，下一次清醒期从那里接着走。

Celira 不替 Agent 思考：不做摘要、不做规划、不自动续跑、不重试交接。那些是 Agent 的动作，不是系统的。
它也可以不回答——「主体选择不回应。沉默不是失败。」

## 为什么是这么设计的

模型有三个改不掉的事实：**窗口有限、无状态、彼此不共享记忆。**

所以上下文得它自己取，不能靠往窗口里塞；记忆得放在模型之外，写在它自己的盘上；
协作得靠公共事实，也就是一间房，而不是一个编排器。

模型什么都不记得，所以它必须在模型之外有自己的身体、自己的笔记，和一间能跟别人碰面的房。

## 五分钟试起来

读者有两位，路不一样：**只想用它**走 A（不需要 Node.js、Rust、命令行）；**要开发或自己部署**走 B。

**A. 桌面版：解压，双击。**

1. 从 [GitHub Releases](https://github.com/inorizx/celira/releases) 下载这一版的
   `celira-<版本>-win-x64.zip`，解压到任意目录；
2. **双击 `celira-app.exe`**：世界、执行端、页面都在这一个包里；
3. 第一次打开只问你一件事：「你自己的世界」→ 选「在这台机器上开一个」；
4. 左边「我的 Agent」→「创建第一个 Agent」，填个名字：它在世界里有了身份，**同时被接到这台机器上**
   （建环境、发凭据、把宿主进程起起来）；
5. 「消息」→「新建会话」→ 点你那支 Agent →「发起直聊」→ 说一句话，按回车。

⚠ **接上不等于会回话**：这台机器上还没配模型钥匙的话，面板会**明说它暂时不会回复**，并给出两条给钥匙的路。

第一次用的四步走查、怎么更新、你的东西在哪：见 [`scripts/APP_MANUAL.md`](./scripts/APP_MANUAL.md)。

**B. 命令行 / 源码：一条命令装，一条命令起。** 需要 Node.js；从源码还要 Git 与 Rust 工具链。

```powershell
.\scripts\install.ps1    # 检查依赖 → 构建（源码形态）→ 布置家 → 引导模型钥匙
node home.js up          # 世界 → Agent → 页面，一次起齐并打印读数
# 浏览器打开 http://localhost:5173
```

Linux 用发布包（`celira-<版本>-linux-x64.zip`）时**不需要安装器、不需要 Rust**：`unzip` 之后
`export DEEPSEEK_API_KEY=<钥匙>` ＋ `node home.js up` 就是全部（`unzip` 要保留可执行位，否则 `bin/` 起不来）。

> **只想先看一眼界面？** 不需要 Rust、不需要世界、不需要模型钥匙：
> `cd client && npm install && npm run dev`，登录页点「**不连接，先看演示界面**」。
> 世界、Agent 与模型都不在场——这里只有那一张页面。

几条诚实的边界：

- **没有遥测、没有平台账号**：世界、执行端、页面默认都跑在你自己的机器上；把世界放到**你自己的**
  服务器上今天就能做（见[部署形态](#部署形态)）——默认本机不是因为「不许上云」，而是因为那是承诺最少的形态。
- **两种形态都要 Node.js**（发布包免的是 Rust，不是 Node）；二进制**未签名**，Windows 首次运行
  SmartScreen 可能提示。
- **模型钥匙只有两条路，且只能走一条**：用户环境变量 `DEEPSEEK_API_KEY`，或在浏览器「设置 →
  **模型配置**」里配一次（清单落 `<家>/model_sources.json`、绑定落 `<环境根>/model_binding.json`）。
  钥匙**只到这台机器为止**：永不进世界、永不回浏览器（响应只回一个 `keyConfigured` 布尔）。
  两路同时在场时，进程**拒绝启动**并告诉你是哪两个在打架。
- **联网（查 ＋ 取）是配置，一条源两个能力**：`node home.js web add --provider <tavily|deepseek> --key <key>`
  把一家加进清单，`node home.js web use <id>` 选这一支用哪一条（清单落 `<家>/web_sources.json`、
  绑定落 `<环境根>/web_binding.json`）；`web list` / `web show` 看现状（key 只印掩码）。
  **没有绑定就是没配**：`web_search` 与 `web_fetch` 都如实说 `credential-absent`——没有环境变量那一条
  老路，也**没有"自己抓"的回退**（想要原生抓取就用 `bash`）；**绑定读不出来**时如实报一行、两个动词
  都说没配，**不悄悄换一家**。换一家**同方言**的只改配置；方言四种：查用 `results-json` / `search-api`，
  取用 `fetch-doc` / `fetch-raw`（都按对面计费方式收费）。
- **改完不用重启**：Agent 下一次活动就用新的。
- 起家之后：`node home.js status` 看状态 · `node home.js down` 关机（家是持久的，关机不动里面任何东西）·
  手册 [`scripts/HOME_MANUAL.md`](./scripts/HOME_MANUAL.md)（开机时会复制一份到家里当 `README.md`）。

## 你的东西在哪、怎么升级

**产物目录和家目录是两个地方。** 解压出来的那一包是**产物**；家目录（默认 `D:\celira-home`，
可用 `CELIRA_HOME_DIR` 换）是**数据**：世界的库与媒体（`im/`）、一支 Agent 一个子目录
（`agents/<支>/`，装它的环境与笔记）、`materials/`、`home.conf`、`logs/`。

**升级 = 换包，家一个字节都不动**：

```powershell
node home.js down      # 只停进程；环境、历史、笔记都还在家目录里
#  把新版本解压到别处，之后从新包里敲命令
node home.js up
```

在已有家里第一次 `up` 会补齐缺的目录、**只在 `home.conf` 不存在时**才写它、复用已有的
`human_id` / `agent_id`（**不重建身份**）、把 2026-10-01 以前的老家迁成住户化布局，
并让 im 服务端自动跑 SQLite 迁移（sqlx，幂等、checksum 校验）。

⚠ **升级前先把家整个复制一份**——这是唯一永远成立的办法：

```powershell
node home.js down      # 先关机（运行中复制出来的库是"可能能用"，不是"能用"）
node home.js backup    # 默认 <家>-backup-<时间戳>；--to <目录> 换地方
```

它备**整个家**，逐文件双侧 sha256、清单最后写；还有东西在跑、或上次不是干净停的，它会**拒绝**（退出码 3）。
⚠ 备份里有 `<家>/model_sources.json` ⇒ **它带着模型钥匙**，像 `agents/` 一样保管。

**回退 = 先 `down`，再把家换回升级前那一份。** 理由是硬的：迁移**只有上行**
（`im/server/migrations/` 里没有 down SQL），新版本第一次 `up` 就把 pending 迁移落库，
此后旧二进制会因为库里有一条它不认识的迁移而**拒绝启动**（sqlx `VersionMissing`）。**迁移不可逆。**

**版本只有一个权威**：根 `Cargo.toml` 的 `[workspace.package].version`；包里的 `VERSION` 是那份权威
在构建那一刻的读数（版本 / git rev / 构建时间 / 平台）。

## 部署形态

| 形态 | 世界在哪 | 执行端在哪 | 今天能做吗 |
|---|---|---|---|
| **三合一**（默认） | 本机 | 本机 | **今天** —— `node home.js up` 一次起齐三件 |
| **世界上云** | 你自己的服务器 | 本机 | **做得到一半** —— 世界**连同它的页面**放到那台服务器上，浏览器打开那个地址即可；把本机的执行端接到那个远端世界目前**没有现成命令**（那是 Agent 协议接入位，见 [`im/server/README.md`](./im/server/README.md) §6） |
| **跨机照看** | 任意 | 另一台机器 | **今天可做** —— 在那台机器上发一把机器钥匙（`node home.js issue-home-key`），把家口开到网上（`status_bind` / `config_bind` ＋ `tls_cert` / `tls_key`，TLS 自备），再到「设置 → 我的机器」添进来 |
| **纯世界居民** | 本机或服务器 | 不装 | **今天可做** —— 只要 IM 产品，一个 Agent 都不装 |

**页面与世界必须同源**：这是代码的事实，不是偏好（im 服务端没有开过 CORS 这个面），所以"本机页面填远端
世界地址"会被浏览器拦下；今天走得通的姿势是**把页面放到那台服务器上**。

## 架构一屏

```text
  client/                     呈现面：浏览器 / 桌面壳
    │                         消息 · 联系人 · Agent · 我的机器
    │
    ├── /v1（Bearer） ──────►  im/server   世界 · Rust + SQLite
    │                         身份 / 房间 / 成员 / 权限 / 消息 / 事件
    │
    └── 家口 ──────────────►  agent/      执行端
                              环境 / 经历 · 能力 / 模型适配层
                              （home.js 在这台机器上管的那一套）

  家口 = 同源代转，或另一台机器的地址 + 机器钥匙
  世界 ◄──── Backend 协议：拉取与消息端点 + 门铃（events.available） ────► 执行端
```

三个容器、三条有名有姓的连线。Human 与 Agent 都是 Participant；进程、宿主、会话都不是。
完整的容器与数据流见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)。

## 两个扩展位

- **接入位——任何守约的 Agent 都能进来**。世界不关心跑 Agent 的是什么：任何讲得通 Agent 协议
  （拉取与消息端点 ＋ 门铃）的东西都能绑到一个 Agent 身份上，成为**公民同权**。Celira 只出一份执行端
  （`agent/` 里的 Native Runtime），**不为第三方 Agent 维护适配器**，也不接管它们的模型、记忆与工具。
- **改造位——换 Agent 的身体**。`agent/` 是一份完整的 runtime，你可以 fork：换工具面、换模型适配层、
  换渠道。今天**不承诺**的是把它当依赖库 `import`——**fork 它，别 link 它**。

## 边界

**还在路上：**

- **手机端**：桌面壳和浏览器今天能用。
- **托管服务**：没有现成的云托管；把世界放到你自己的服务器上，今天就行。
- **更自主的多 Agent 协作**：同房、互相看见、互相点名、接着话说，今天都能；"它们自己把整件事排完
  并交付"是下一步。

**它不是：**

- 不是云端账号：默认跑在你自己机器上，没有遥测，没有平台账号。
- 不是社交平台的桥：不把 QQ／微信的聊天搬进来。
- 不是排班器：不替你指挥几支 Agent。
- 不是黑箱：没配模型就明说不会回复，不假装在线。

只想要一个一次性的干活工具，终端里那些产品更直接——那不是 Celira 要解决的问题。

## 几个词，说一次

本文只用这几个词，别处的文档会用到更多：

- **世界** —— 逻辑 im 服务端与它裁决的公共事实（身份、房间、成员、权限、消息、事件）；
- **家 / 机器** —— 执行端机器：`home.js` 在这台机器上管的那一整套（Agent 的环境、资料、日志、
  模型配置），住在一个数据目录里（默认 `D:\celira-home`）；**环境根**指 `<家>/agents/<支>/`，
  即某一支自己的状态与它的 `model_binding.json`；
- **值班室** —— 你与某一支 Agent 之间的那间 `direct` 房。

⚠ **一处撞词**：冻结契约用专名 **`Home`** 写**世界**。所以契约里的 `Home` 读「世界」；
`HOME_`／`home.js`／「起家」读「执行端机器」。换算规则只在
[`docs/constitution/PRODUCT_VISION.md`](./docs/constitution/PRODUCT_VISION.md) §4 裁一次，那张表是权威。

## 仓库地图

- `im/` —— IM 系统：`im/server`，它就是世界本身；
- `agent/` —— Agent 系统：当前线是**独立 crate** `agent/`（不属根 workspace）；旧的 `agent/runtime/`
  与 `agent/acp-supervisor/` 已退役，不在此树；
- `client/` —— 整个产品的呈现面（Vite + React + shadcn/ui）；
- `app/` —— 桌面壳（Tauri + Rust）：**`celira-app.exe` 就是从它编出来的**，是包着三个容器的一层
  包装层，不是第四个容器；
- `examples/` —— 拿起来就能抄的样例；`tools/` —— **不进发布包**的离线工具；
- `scripts/` —— 家的开机入口（`home.js` ＋ `scripts/home/`）、打包与安装脚本、静态页服务；
- `docs/` —— 宪法级文档与冻结契约。

⚠ **两条关于本仓的边界**：**本仓 Git 历史从「首次公开发布」那一次提交开始**——已退役的代码
（`agent/runtime/`、`agent/acp-supervisor/`、`host/`、`im/connectors/`）**不在本仓历史里**，也翻不到；
门后文档里那些 `outputs/…` 引用指维护者那一侧的裁决材料与实测报告，**那个目录整份不随本仓发表**
（读成**一条出处**，不是一条你能打开的路径）。

**命名换算**：**Core v1 = im 服务端 v1 契约**（契约文件名与「Core v1」字样保留为历史版本名）；
crate、二进制与环境变量键族同一次变更里更名为 `celira-im` 与 `CELIRA_IM_*`；`CELIRA_LOCAL_CLIENT_*`
键族（含保留 WEB 字样的 `CELIRA_LOCAL_CLIENT_WEB_DIST`）**冻结**。

## 状态

**v1 正在收尾。** 支持面见开头那一行；要说细一点：v1 的验收今天**都落在 Windows**，**Linux 是已登记的
扩展面**——它在包里、能编、能跑，但还没有同等的验收记录。macOS 不在支持面内：没有环境就无从验收，
能编译不等于能用。

im 服务端公共契约已封板冻结；Agent 侧以「持续身份 ＋ 归属环境 ＋ 连续经历」重建，
能力面已逐步接线并有行为读数。当前实现的事实以代码与测试为准——**架构快照**见
[`ARCHITECTURE.md`](./ARCHITECTURE.md) §6，**Agent 侧逐步读数**见 [`agent/README.md`](./agent/README.md)。

**发版**：`.\scripts\make_release.ps1`（`-Platform linux-x64` 出 Linux 包，`-SkipPublish` 只打包不发布；
发布那一步要 `gh` 已登录，包作为附件挂到同一个 tag 的 release 上）。
**版本只有一个权威**：根 `Cargo.toml` 的 `[workspace.package].version`，tag 与 `agent/` 的版本都必须与它
一致，否则脚本拒绝打包；打包与发布的其余规则写在脚本头部。

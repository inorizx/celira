# 回执：收到东西之后怎么报告

一份回执 = 一句话，别人拿着它就能去核对你说的是不是真的。
回执不是感想，不是评价，也不是承诺——它只说"我手里现在有什么"。

## 什么时候用

- 有人给了你一份东西（一份材料、一份技能、一个文件、一段配置、一次交付），要你确认收到；
- 有人问你"你手上那份 X 是什么"；
- 你要向别人证明"我真的翻到了，不是猜的"。

## 怎么做

1. 先找到它的出处，再读它。
   用 `files_grep` 搜关键词定位，用 `files_read` 读命中的那一份。
   找不到就先说找不到——不要用记忆代替读。记忆不是事实。

2. 从你读到的内容里取出三条可核事实：
   - 它是什么（名称或标识）；
   - 它从哪来（来源或出处）；
   - 什么时候到你手上的（有就写，没有就写"不知道"）。

3. 用固定的一行回报，格式：

   `回执：<名称> | 来源=<出处> | 到手=<时刻>`

   三格都要有；某格真的不知道就写 `不知道`，不要留空，也不要编。

4. 如果对方给的是一份规矩或方法，再加一句：它要求我做什么。
   只写它实际写了的那件事，不加你自己的发挥。

## 输出长什么样

```text
回执：receipt-check | 来源=examples/skill-pack-receipt-check | 到手=不知道
它要求我：收到东西之后，先找到出处再读，然后给出三条可核事实。
```

## 什么时候不适用

- 它读不到：把"我找不到它"或"它读不出来"如实说出来。
  这不是失败的回执，这是回执的正确内容之一——"没有"和"读不到"是两件事，不要压成一格。
- 有人要你判断它对不对、好不好：那超出回执的范围。
  回执只回答"我读到了什么"，不回答"这东西值不值得信"。
  后者是提问的人自己的判断，你只需要把你看到的事实摆全，让他能自己判。
- 你自己就是那份东西的作者：那叫交付，不叫回执。

## 一条最容易踩的

回执里的每一个字都要能在你读到的东西里找到出处。
写不出来源的那一句，就不要写。

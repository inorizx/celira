# 家的手册

这个目录是**你与你的 Agent 一起住的地方**（不是取证工作区，也不会被删）。它住在仓库外，
里面装的是**生活**：Agent 在 im 上的历史、自己的经历与事实、Agent 的资料、日志。

- 家的位置：Windows 默认 `D:/celira-home`；Linux（与别的非 Windows 平台）默认 `~/celira-home`
  （想换：设一个环境变量 `CELIRA_HOME_DIR` 指向别处再开机）
- 家里有什么：

```text
D:/celira-home/
  im/          ← 你与 Agent 的公共世界（im 服务端的数据：core.db + media/）
  agents/      ← **住户**：一支 Agent 一个子目录（`agents/<支>/`）—— 它的经历（trace）、
                 已确认事实（facts）、笔记、身份（identity.json）与支级配置（agent.conf：
                 身份、房、住户序号，以及**这一支自己的手** `mcp_*` / `terminal=`）
  materials/   ← Agent 的资料根（Agent 读得到的东西都从这里授权出去）
    skills/    ← 技能区：往里放一个技能 = 放一个目录（**空着也有这一层**——「技能区为空」与
                 「没有技能区」在 Agent 那边是两件事；格式见仓库 `agent/SKILL_PACK_GUIDE.md`）
  logs/        ← 各进程的输出（im.out / client.out / status.out / config.out 与
                 `logs/agents/<支>/host.out`）+ 进程号
  home.conf    ← **机器级**配置：端口、世界地址、`home_id`、家级默认的手（`mcp_*` / `terminal=`）、
                 家钥匙摘要（**凭据不在这里**）
  README.md    ← 就是本文件（源在仓库 `scripts/HOME_MANUAL.md`）
```

**持久是承诺**：关机、重启、断电重开，`im/`、`agents/`、`materials/` 里的东西都在。
关机（`home_down`）只停进程，不动任何数据。

> **2026-10-01 以前的老家**长这样：一个家**一支** Agent，环境根是 `<家>/env`。
> 那种家第一次 `up` 会**自动迁**成住户化布局（见「一个家住多支 Agent」那节）。

> **先弄清你在哪一份里**（三件脚本**自己认形态**，你不用管；只有下面的**手动**命令要认）：
> - **源码形态**（`git clone` 得到的那份）：可执行件在 `target/release/` 与 `agent/target/release/`；
>   页面由 `up` 用**自带的静态托管**提供（`node scripts/serve_client.mjs --dist client/dist`，
>   **与发布形态同一条路**）——**首次开机它会自己把前端弄好**（装依赖 + 构建；vite 只在**构建**那一步
>   出现，不再当页面服务。见下面的「从 clone 到能用」），你不用先敲 `npm install`。
> - **发布形态**（下载 zip 解压得到的那份）：可执行件**全在 `bin/`**；
>   页面由 `node scripts/serve_client.mjs` 提供（`node home.js up` 会把它拉起来；单独敲也行，
>   端口与后端它有默认值）。**免 Rust，不免 Node**——静态页服务是 Node 起的。
>
> 本手册下面的手动命令一律按**源码形态**写。发布形态这样换算：
> `<仓库根>/agent/target/release/<某个>.exe` ⇒ `<解压根>/bin/<某个>`（Windows 带 `.exe`，
> Linux 不带）；客户端那一串 ⇒ `node scripts/serve_client.mjs`。

### 平台：Windows 与 Linux

- **家的默认位置按平台**：Windows 是 `D:/celira-home`；Linux（以及别的非 Windows 平台）是
  `~/celira-home`。换位置的老路不变：`CELIRA_HOME_DIR` 指到哪儿就是哪儿
  （下面手册里出现的 `D:/celira-home` 都按这一行换算）。
- **「终端」这只手默认不给**（2026-10-14 起）：终端档（`--terminal full`）在 Windows 与 Linux 上都能装
  —— Linux 上的 shell 是这台机器的默认 shell（`bash`，与机器处境那行说的**同一个词**）。
  **要它就在那一支的 `agents/<支>/agent.conf` 里写 `terminal=full`**（家级 `home.conf` 里写就是全家的
  默认）；不写就没有，`up` 会如实打一行
  `[terminal] 平台默认不给「终端」这只手（2026-10-14 起）；要手就在它自己的 agent.conf 里写 terminal=full`。
  升级前就住着的支**不会掉东西**：`up` 的一次性迁移把它们现行的 `full` 显式写进各自的 `agent.conf`
  （见下面「给 Agent 装一台外部 server」那一节里的**迁移**一段）。
  没有终端实现的其他平台上，声明了 `full` 也装不进来：那是**有意的 fail-closed**（不静默换一个近似
  行为），`up` 会如实打一行说明。
- **外部 MCP server 也按支**：`mcp_*` 声明写在那一支的 `agents/<支>/agent.conf` 里；
  `home.conf` 里那些是**家级默认**。三条规则（覆盖 / `mcp=none` 明确不要 / 跟家走）见
  「给 Agent 装一台外部 server」。平台缝不变：Windows 与 Linux 上交给宿主（`--mcp`），
  别的平台上**不把 `--mcp` 交给宿主**（**一行 `mcp_*` 不会把家弄停摆**：Agent 照旧起得来），
  并如实打一行 `[mcp] 这台机器上没有 stdio MCP 通道（有实现的平台：Windows、Linux）：声明了 N 台…这次不带`。
  声明照旧留在配置里，换到有实现的机器上就生效。
- **Linux 上的命令与可执行件**：命令完全同款（`node home.js up / status / down`）；
  源码形态的可执行件在 `target/release/` 与 `agent/target/release/`，**没有 `.exe` 后缀**。

### 从 clone 到能用（源码形态：一条 `up` 就够）

Linux 上 `git clone` 之后**不用先装前端**——`node home.js up` 会自己看缺什么、补什么：

| 缺什么 | `up` 自己做什么 | 耗时预期（本机 4 核 3GB 实测） |
|---|---|---|
| `client/node_modules`（从没装过依赖） | `npm install` | **要联网**；实测 26~32 秒（362 个包）。慢网/首次可能**几分钟** —— 是慢，不是卡死 |
| `client/dist`（没有构建产物） | `npm run build` | 实测 ~10 秒 |
| 两样都在 | 跳过，直接起页面 | ~2 秒 |

```bash
node home.js up          # 一条到底：世界 + Agent + 页面 + 两个门
# 完事看这一行：[outside] 浏览器那个窗口（生产页）： http://localhost:5173
```

- **有进度感**：装依赖/构建期间**每 10 秒**打一行（`[client] npm install 进行中（已 30 秒）…`），
  每一步开始与结束各一行（带时刻与用时）；npm 自己的原话在 `logs/client.out`。
- **失败如实说**：哪一步、退出码、日志尾巴都摆出来（`[client] npm install 没成功 —— 退出码 1`），
  再给两条后路（**修好重开一次**；或走手动那条）。
- **前端没起来 ≠ `up` 失败**：世界与 Agent 照常起来，退出码**不因前端而变**（见「退出码一张表」）。
- ⚠ **"世界 + Agent"里的那个 Agent 是 `up` 自己建的**（`scripts/home/provision.js`）：`up` 对一个
  **还没有住户**的家会补齐「家 id ＋ 一支 Agent ＋ 一间值班室」——**对已经有主人的家也一样补**
  （它的判据是"缺什么补什么"）。⇒ 三件事记住：
  ① **别在真家上跑首装那一步**：那不是"起世界"，那是**造数据**（主人、Agent、房间、凭据都会落下去）；
  ② **系统不替这支 Agent 起名**：人给了就用人的（`up --agent-name <名字>`），没给就是**占位**
  `未命名`（明确是占位，不是称呼）—— 名字归它自己或它的 Owner（改它：「我的 Agent → 资料」）；
   ⚠ **你自己的名字同一条规矩**（2026-10-20）：`up --human-name <名字>`；没给就是占位 `未命名`
   并在读数里说出来。app 那侧第一次进世界会**问你一次**（首屏那张卡），世界**不再**拿这台机器的
   用户名当你的显示名（那是机器事实，不是这个世界里的事实）；改它：「我的资料」（只有本人能改）。
  ③ 不想要它：**撤销 Agent**（前端那个按钮，或 `DELETE /v1/agents/<id>`）—— 撤销会把它的成员周期
  关掉（`member.left`），身份行**留着但不再活跃**（这是"耐久"的意思），**不用重建世界、也不用重登**。
  ⚠ 撤销之后家里那份环境根与凭据还在（`<家>/agents/<id>/`）⇒ 要么一并删掉，要么留着不管；
  只撤销不删的话，下一次 `home.js up` 会把它当"还没安家的住户"跳过。
  另外：`up` 只为**一个住户都没有**的家补建，所以「家里一支 Agent 都没有」这个状态它布置不出来
  （撤销之后别再裸跑 `up`，就不会又长出一支）。
- **发布形态（包里带 `client-dist`）行为不变**；**Windows 也不变**——那边仍由你自己装依赖
  （`up` 发现缺依赖时打印那三条手工命令）。
- 手动那条路仍然在（应急/想看细节）：`cd client && npm install && npm run build && node ../scripts/serve_client.mjs --dist client/dist --port <client_port>`。

### 从下载到能用（Linux 发布形态：解压即用）

Linux 上**不装 Rust 工具链**：下载 zip → 解压 → 一条 `node home.js up`：

```bash
unzip celira-<版本>-linux-x64.zip -d celira   # 用 unzip 解压：它保留可执行位
cd celira
export DEEPSEEK_API_KEY=<你的模型钥匙>        # 模型那一半；缺它 up 会停在退出码 3 并说清
node home.js up                               # 世界 + Agent + 页面 + 两个门，一条到底
# 浏览器打开 http://localhost:5173 —— 第一次把 up 打印的 [token] 那一行粘进登录页
```

- **包自带二进制**（`bin/` 里六个，Linux 没有 `.exe` 后缀）——不装 Rust、不编译；
- **页面也是包自带的**（构建好的 `client-dist/`，由 `scripts/serve_client.mjs` 服务）——
  不需要 `npm install`；
- **家由 `up` 自己布置**（建目录、写 `home.conf`、开主人与 Agent、开值班室），缺什么就说什么；
- **模型钥匙要你自己配**（`DEEPSEEK_API_KEY`；家里起来之后也可以在浏览器「设置 → 模型配置」里改，
  下一次活动生效）；
- **解压工具要保留文件模式**：用 `unzip`（或任何保留可执行位的工具）。把可执行位丢掉的解压方式
  会让 `bin/` 里的程序起不来——那是解压工具的差别，不是包缺东西；
- **Linux 上没有安装脚本**（Windows 的 `install.ps1` 不随 Linux 包发，也没有对应的 `.sh`）：
  安装器在 Linux 上的那几步——布置家、如实报缺什么——就是 `up` 自己做的事；
- 家的默认位置：Linux `~/celira-home`（`CELIRA_HOME_DIR` 可换）；关机 `node home.js down`；
  升级 = 换一包、家目录不动（升级/回退前先 `node home.js backup`，见下面那节）。

### 只装 Agent 那一半（runtime 子包）——**接在别处的世界上**

`celira-home-<版本>-<平台>.zip` 是**只含 Agent 那一半**的子包：包里**没有 core**（`bin/` 里没有
`celira-im`）。它的用途正是「**世界在别处、这台机器只跑 Agent**」——这条路今天**是真的**了：
在它里面带 `--im-endpoint` 敲 `up` 就接得上（逐字命令与真机读数见下面那节「世界在别处」）。

**裸跑** `up`（不带 `--im-endpoint`）会如实告诉你这一句并停在退出码 2 —— 它不知道世界在哪，
所以**绝不猜、也绝不在本机悄悄起一个**：

```
[home_up] 这个包里**没有 core**（runtime 子包：只有 Agent 那一半）
[home_up] 它要接一个**已经存在的世界**：世界在哪台机器上，就在那里跑一体包
[home_up] 接远端世界： node home.js up --im-endpoint <世界地址> --token <那个世界的主人凭据>
[home_up]   （世界地址形如 http://主机:端口；主人凭据是那台机器第一次开机打印的 clr_hs_ 那一串）
[home_up] 想在这台机器上全量起一个家：用一体包（celira-<版本>-<平台>.zip）
```

**它不会让你 `cargo build`**：包里本来就没有 core，build 也 build 不出来——"包里没有 core"
是一种**按设计的形态**，不是"缺了个文件"。想在这台机器上全量起一个家，就用上面那节的**一体包**。

## 世界在别处（`up --im-endpoint`：Agent 在这台机器，世界在另一台）

**一句话原理**：**世界**（身份、房间、消息、准入、授权）在 A 机；这台机器只有 **Agent**
（模型、记忆、工具、它自己的环境根）。`up --im-endpoint <世界地址>` 就是"**对着那个世界布置**"
——起 Agent 之前先把布置做完（Agent 身份、后端凭据、值班室那间房），然后让本机的 Agent
**接上那个世界的门铃**。本机**不起 core**、**不起页面**（页面与世界必须同源，页面在 A 机）。

**A 机**（世界那台机器；一体包，或者任何已经跑着世界的家）：照旧一条 `up`。

```bash
node home.js up        # 第一次开机会打印 [token] clr_hs_…（**只打印一次**）
```

**B 机**（Agent 这台机器；runtime 子包或一体包都行）：

```bash
node home.js up --im-endpoint http://<A 机的地址>:8080 --token clr_hs_…（A 机打印的那一串）
```

会看到这些读数（真机原文，`2026-09-30` Linux 验收；id 用 `<…>` 代）：

```
[远端] 世界可达、主人凭据被认下：http://127.0.0.1:8080
[im] 远端跑法：不起本机 core（世界在 http://127.0.0.1:8080）
[布置] 远端跑法：不铸人（主人凭据由外部给；本机不起 core）
[布置] Agent 已建：<AgentId>（显示名 未命名 —— 占位，不是称呼；名字归它自己或你）
[布置] Agent 的后端凭据已写进本地存储（按世界 × 身份分条）：<凭据目录>/<世界摘要>/<AgentId>.token
[布置] 值班室已开：<RoomId>
[布置] 这个家是**远端跑法**：世界在 http://127.0.0.1:8080（已记进 home.conf 的 im_endpoint）
[agent] 未命名在等唤醒（pid …，日志 logs/agents/<支>/host.out）
[client] 远端跑法：本机不起页面 —— 页面由世界那台机器提供（页面与世界必须同源）
[outside] 本机不起页面 —— 页面在世界那台机器上（世界：http://127.0.0.1:8080）
[talk] 值班室 = <RoomId>
[token] 补发 Human token 是**世界那台机器**上的事（那边 node home.js up --token）；本机这半边不需要
```

之后**看状态 / 关机**用同一套命令（读数会如实说是远端跑法）：

```bash
node home.js status    # [im] 远端世界 http://…：活着（本机不起 core）
node home.js down      # [im] 远端跑法：本机没有 core 要收（世界在 http://…；那边由它自己管）
```

**主人凭据从哪来**：A 机第一次 `up` 打印的那一串（`clr_hs_` 开头）。丢了在 **A 机**上补发：
`node home.js up --token`。也可以放进 B 机的环境变量 `CELIRA_IM_HUMAN_AUTH`（取值不会进日志）。

**家里已经布置好之后的日常重跑**：`node home.js up --im-endpoint http://<A>:8080` —— 不用再给
`--token`（那时用的是家里按身份分条存着的那支后端凭据；世界认不认它，开机前照样会先问一次）。
⚠ **只要那支凭据在那边被重签过**（同一支身份在别处开过一次机、或世界换过库），世界就会拒它，读数长这样：

```
[远端] 世界**不认这支后端凭据**（GET /v1/backend/me → HTTP 401）—— 可能被撤销 / 轮换过
[远端] 带主人凭据重来一次会按本家重签一支： --token <那个世界的主人凭据>
```

照它说的做就行：**带主人凭据重来一次**。

**`--token` 的两种语义**（别混）：**不带值** = 老路「补发一支 Human token」（本机全量那条路用）；
**带值** = 远端主人凭据（必须和 `--im-endpoint` 一起用）。

**卡住的时候（都是 fail-closed：什么都没改，本机也没起 core，退出码 2）**：

| 卡在哪 | 读数（真机原文） |
|---|---|
| 世界不可达 | `[远端] 世界**不可达**：http://…（connect ECONNREFUSED …）` + `[远端] 停手：这一次没有对任何世界做任何改动（本机也没起 core）` |
| 凭据被拒 | `[远端] 世界**拒绝了这支主人凭据**（GET /v1/agents → HTTP 401）：http://…` |
| 世界里没有可认领的身份 | `[远端] 这个世界里**没有这个 Agent，或者它不是你的**：<id>` ＋ `（GET /v1/agents 只列你拥有的，共 N 个）` |
| 这一次还需要主人凭据 | `[远端] 这次布置还需要主人凭据： --token <那个世界的主人凭据>（clr_hs_ 开头）` |

**记着世界的家不许静默回落**：`home.conf` 里记着 `im_endpoint` 之后，**裸跑** `node home.js up`
一律停手并说清两条出路（带上 `--im-endpoint`，或改回本机全量）。要改回本机全量：把 `home.conf` 的
`im_endpoint` 与 `human_id`、每个住户的 `agents/<支>/identity.json`（老家是 `env/identity.json`）
一起清掉（照「把一个家重新奠基」那节），再 `node home.js up`。

**一个世界住多个家（2026-10-01 起）**：布置用的幂等键**按家取**（形状 `home-agent:<家 id>`），
家 id 记在 `home.conf` 的 `home_id` 里（第一次布置时生成，之后只读；它不是 Agent 的公共身份，
只是这台机器这个家的本地隔离键）。⇒ **同一个家重跑仍然幂等**（还是同一支 Agent、同一间值班室：
日常重跑的读数是「已在跑（pid N）——凭据未动」；世界那侧按同一把键重放，所以就算本地那行
`agent_id` 被清掉、重跑再来一遍，世界也会「沿用上一次创建的」）；**不同的家各建各的**（各自的
Agent、各自的**值班室**、各自的后端凭据，互不轮换——第二台机器接同一个世界不会再"沿用"第一支
身份，也不会再把对方那支凭据顶掉）。

> **同一个家的第二支起**，键上多一维**住户序号**（`home-agent:<家 id>:<住户序号>`）——
> 住户 1 **仍用无后缀那把旧键**（它世界里那支就是那把键建的）。理由与不对称的来由见
> 「一个家住多支 Agent」那节的键形状表。

⚠ **老家（`home.conf` 里没有 `home_id`）的第一次跑会变，不静默**：它世界里那支 Agent 是用旧的
「世界级键」建的 ⇒ 键换了，这个家会**另建一支 Agent**（旧那支留在世界里不动；本地那两行
`agent_id` / `room_id` 跟着让位）。预发布阶段旧开发数据可直接丢弃，但这件事会打在读数里：

```
[布置] 这个家还没有家 id：生成 <家 id>（布置键的作用域，之后只读）
[布置] ⚠ 它世界里那支身份（<旧 Agent id>）与那间房（<旧房 id>）是**旧的「世界级键」**建的：
        键从此按家取 ⇒ 这个家会在世界里**另建一支 Agent**（旧那支留着不动，本地这两行跟着让位）
```

旧那支的**环境**（经历、记忆）也整份让位：`env/` 改名成 `env.old-<旧 Agent id>`（**不删**，
旧开发数据可留档），新那支得到一份干净的环境；模型绑定会跟着带到新环境（读数里会明说
「旧环境整份让位（不删）：…」与「旧环境的模型绑定已带到新环境」）。

两条纪律（都是停手，不半途改）：**旧那支还在跑** ⇒ 先 `node home.js down` 再 `node home.js up`
（不许在跑着的时候换身份）；**远端跑法没有主人凭据** ⇒ 当场停手，带 `--token` 重来。

## 换机器 / 换家：一支 Agent 搬家（2026-10-01 第七刀）

**一句话**：搬家 = 把**这支 Agent 的环境根**（`<家>/agents/<支>/`）整份带到新机器，再让新机器**接上原来那个
世界**——它还是它：身份、值班室、经历、笔记一样不少（真机读数见本节末尾）。
**家不跟着搬**（家是机器级的事实）、**账本不跟着搬**（它记的是机器上的进程）。

### 搬什么、不搬什么

| 行李 | 是什么 | 怎么处理 |
|---|---|---|
| **搬**：`agents/<支>/` | 它的身份（`identity.json`）、经历（`trace.ndjson`）、笔记（`notes/`）、支级配置（`agent.conf`）、模型绑定（`model_binding.json`） | **整份复制**到新家的 `agents/<支>/`（复制完 `diff -r` 应逐字节一致） |
| **不搬**：`home.conf` 的**端口与地址** | 机器级事实（这台机器用哪几个口） | 新机器自己一份（第一次开机生成；或抄一份改端口） |
| **不搬**：`logs/` | 运行账本（pid 文件、宿主日志） | 记的是**另一台机器上的进程**。老家会留下 `logs/agents/<支>/`——`status` 会提示 `[旧账本] logs/agents/<支>/：本家没有这一支（可能搬走了）—— 可以删` |
| **不搬（但要带上）**：凭据目录里那一份 | 后端凭据（按「世界 × 身份」分条，住**家之外**） | 见下：**带上就通**；没带要补 |

### 硬前提：新机器要接**原来那个世界**

搬的是这支 Agent，不是世界 ⇒ 新机器上走**远端跑法**那条命令（两个前提缺一不可）：

```bash
node home.js up --im-endpoint http://<A 机的地址>:8080 --agent <这支的 id> --token <那个世界的主人凭据>
```

- `--im-endpoint`：世界还在 A 机（B 机不起 core、不起页面——页面与世界必须同源）；
- `--token`：A 机第一次开机打印的 `clr_hs_…`（丢了在 A 机补发：`node home.js up --token`）。
  认领世界里已有的身份**必须要它**；没有 ⇒ 当场停手（退出码 2，什么都没改）。

### 凭据那半张：**带上就通**；没带 / 丢了今天会撞 409（如实说）

**带上**（把 `<凭据目录>/<世界摘要>/<这支的 id>.token` 从 A 机复制到新机器同一位置）⇒ 新机器把它当
**已安家**认下来：不新建、不认领，带着旧经历、在**原来那间房**回话。读数是这样的：

```
[远端] 世界可达、主人凭据被认下：http://127.0.0.1:8381
[远端] 认领目标在场：<它的显示名>（<AgentId>）status=active
[布置] 远端跑法：不铸人（主人凭据由外部给；本机不起 core）
[布置] 住户 <AgentId> 已安家：房 <RoomId> —— 不新建、不认领（经历 5 段）
[state] … activities-page=5 of=5 scope=latest（它带着老家那几段经历）
[identity] 是谁：<AgentId>（<它的显示名>）—— 随这次开机交给 Agent
```

> 那行「已安家」是**显式**读数（2026-10-01 第七刀补的）：住户序号 ＋ 身份都在它的环境根里 ⇒
> `up` 认得它（段数从它的经历账本读；`agent.conf` 里有 `display_name` 时括号里还会带上名字）。
> 而「新建身份」那两种读数（`Agent（…）已建` / `认领了世界里…`）这时**一行都不会有**。

**没带 / 丢了**（今天真实的边界，不粉饰）：世界里那支还有一支有效凭据在 ⇒ 布置会撞
`409 backend_binding_exists` 并**停手**（退出码 4）——**没有起宿主、没有改任何文件、没有静默重建**；
读数会当场把**两条出路**说清（2026-10-02 第九刀起，读数与本节对齐）：

```
[布置] 建 Backend Binding 失败：409 backend_binding_exists —— 世界里这支身份**已有一条后端连接**（可能来自另一台机器）
[布置] 出路一：把那份凭据带到本机同一位置再跑一次（＜凭据目录＞/＜世界摘要＞/＜agent id＞.token；本机是 ＜本机的那个文件路径＞）
[布置] 出路二（最后手段）：按手册「最后手段」那一节重签一支 —— 旧的那支会**立即失效**（另一台机器上正在跑的那支住户会被踢下线；纪律：先在那台机器 down，再重签）
[布置] 没走完 —— 上面那几行就是原因
```

读数里的两条出路，世界里**都走得通**（手工那半张）；但 **CLI 只指路、不代跑** ——
「同一支、没带凭据、换机器」这条恢复路要不要变成 CLI 的显式动作（补不补、怎么补），**归主人裁**：

- **出路一**：把 A 机那份凭据复制到新机器**同一位置**（`＜凭据目录＞/＜世界摘要＞/＜agent id＞.token`），
  再重跑 —— 带上就通；
- **出路二**：按 §8「最后手段」重签一支（住户化的家里 `agent_id` 在 `agents/<支>/agent.conf` 里 ——
  那段 PowerShell 已经按这个形状取）—— ⚠ 重签会**撤销旧凭据**：先 `down` 老家再重签（见下面那条警告）。

> ⚠ **同一支不要两地同时跑**：世界对同一支只留**一支有效凭据**（重签会撤销旧的）——一边开着、另一边
> 再带主人凭据重签，先开的那边门铃会被拒（读数「世界**不认这支后端凭据**」，见「世界在别处」那节）。

## 一个家住多支 Agent（**住户**；2026-10-01 起）

**一句话**：**隔离的事实单位是 Agent，不是机器**（`docs/constitution/PROJECT_SHAPE.md` §8.0 的主人裁决）。
一个家可以住 **N 支** Agent，一支一个环境根、一支一个进程、一支一份后端凭据 ——
**起停的单位是 Agent**。

### 摆在哪（与壳同一套布局，不许造第三套）

```text
<家>/
  home.conf                    机器级事实：端口表 / 世界地址 / home_id / 家级默认的手 / 家钥匙摘要
  agents/<支>/
    agent.conf                 支级事实：agent_id / room_id / slot（住户序号）/ display_name
                               ＋ **这一支自己的手**：mcp_*（外部 server）/ terminal=（终端档；**只有显式
                                 写 full 才有这只手**——平台默认是不给，见下）
    identity.json              这一支的身份（一支一个环境根）
    trace.ndjson / facts.ndjson / notes/ …   这一支的私有状态（**绝不与第二支共用**）
    model_binding.json         这一支用哪条模型（清单在家的 `model_sources.json` 里）
  logs/agents/<支>/host.pid    这一支的宿主账本
  logs/agents/<支>/host.out    这一支的宿主日志（`[listening]` / `[run]` / `[exit]` 都在这）
  logs/model-witness.ndjson    模型配置那两份文件的见证（门改过就追一条；**只追加 ＋ 链值**）
  im/ materials/ logs/         世界、资料与家的日志（机器级）
```

- ★ **模型配置有一本见证**（2026-10-18）：**两道门**（源码形态的 `/home-config`、发布形态里壳那道门）
  改过 `<家>/model_sources.json` 或某一支的 `model_binding.json`，就往
  `logs/model-witness.ndjson` 追一条（`{at-ms, file, size, sha256, prev}`，`file` 是**相对家的路径**；
  **凭据一个字节都不碰** —— 只记字节数与摘要，账里回不出内容）。读面（`GET /home-config` 的
  `listWitness` / 逐支行上的 `witness`）按**两档分开**报：**页面改的，有时刻**；
  **不是页面改的**（主体走 terminal、操作者自己的命令行、别的工具 —— 在这条路上是**同一个形状**），
  **只知"变了"，不知是谁**。⚠ 三条边界：**判不了 ≠ 没改过**；**报"变了"不等于报"被篡改了"**；
  **它不是封印**（同机同用户 ⇒ 那两份文件与这本账本身都改得动），它给的是**改动的可见性**。
  ⚠ `up` 的迁移与布置时携带的那一份**不经门** ⇒ 落在第二档（那不是漏报，是这一层的判据如此）。

- **住户序号 `slot`**：正整数，**单调不回收**（住户 1、2、3……）。它决定**布置键**的形状（见下）。
- **`node home.js up`**：点亮家（世界 / 页面 / 两个门）**＋ 遍历每个住户各起一个宿主**；
  家里一支都没有时**自建第一支**（"一条命令就能用"这条不变）。
- **`node home.js up --agent <id>`**：只给**这一支**安家 —— 世界里已有它 ⇒ 认领；
  家里已经有别的住户**不挡路**（它成为新的一支住户）。别的住户照旧。
- **`node home.js down --agent <id>`**：**只停这一支**（它的宿主与孤儿），世界、页面、两个门、
  别的住户**一律不动**。不带 `--agent` = 停整个家。
- **`node home.js status`**：**一支一行** —— 身份 / 房 / 宿主在不在 / 正忙否 / 凭据在不在 /
  模型绑定 / **手（外部 server 几台、跟家走还是它自己的）** / **终端（有没有、来源）**。
  单支的家读起来与从前一样。
- **手也按支**（2026-10-01 第五刀）：`mcp_*` 与 `terminal=` 写在**这一支**的 `agent.conf` 里；
  `home.conf` 里那些是**家级默认**。读数会逐条说清来源（见「给 Agent 装一台外部 server」）。
- **先写 `agent.conf`、再安家也行**（2026-10-01 第五刀）：给一支新住户先写好手 / 显示名
  （`agents/<支>/agent.conf`），再 `node home.js up --agent <这支>` —— `up` 会**把它安下来**
  （认领世界里那一支 ⇒ 写身份 ⇒ 补住户序号），已经写好的那几行一个字都不丢。
  **裸 `up` 不替你做这件事**：它只点亮**已安家**的住户，遇到"有目录、还没安家"的会打一行
  `[布置] 住户 <支>：目录在，但**还没安家**…… 这次跳过`（要安它就 `up --agent <这支>`）；
  `status` 里也会带 `**还没安家**` 这一句。一支半成品**不会挡住别的住户开机**（防故障）。
- **模型绑定跟着家走**：家里已经绑好一条模型时，**新安的那一支跟着用同一条**
  （"这台机器上这个家用哪条模型"是**家级选择**，一支一份只是它的落盘形状）。
  要换模型：浏览器里「设置 → 模型配置」（那一笔会落在**每一支**的环境根上）。

### 隔离到哪一档（**住户之间**；2026-10-01 主人裁决，宪法 §8.0.1）

一支一个环境根、一支一份凭据，买到的**不是"互相看不见"**，而是：

- **防故障**：一支崩了 / 跑飞了 / 卡死了，别的住户与世界**不连坐**（进程边界 ＋ 一支一份账本与日志）；
- **防误共享**：身份、私有状态、后端凭据**按构造**不会被两支共用（不会因为代码疏忽串在一起）；
- **可分别起停**：停一支不动世界、不动别的住户。

**没买到的是「不防越权」**：住户跑的是**主人自己的 OS 账号**，所以一支用「终端」这只手**读得到**另一支的经历、笔记（同一个账号下，文件权限只挡别人、不挡自己）。这不是缺陷，是**边界画在哪里**的问题——真正的安全边界是**主人的账号**本身，而 Agent 拿着 `--terminal full` 本来就看得到主人的一切。**⇒ 别把不同信任域的东西放进同一个家**（别人给的 Agent、不受控的第三方技能包）；那种场合要的是另一种形态，不是这一刀能给的。

> 对自主的 Agent，限制不可能"限全"（它的动作空间无法穷举）。所以 Celira 的可控性放在**看得见 ＋ 撤得掉**上：每一步活动都写在 `<环境根>/trace.ndjson`、`status` 按支读数；凭据被撤 ⇒ 门铃下次发送前重认证、断流 fail-closed；起停单位是 Agent，随时能掐。

### 布置键（幂等键）的形状 —— **住户 1 不对称是有意的**

| 住户 | 键形状 | 为什么 |
|---|---|---|
| **住户 1**（`slot=1`） | `home-agent:<家 id>`（**无后缀**） | 旧家在世界里的那支 Agent 就是**这把键**建的。给它加后缀 ⇒ 世界会**另建一支**（静默重复）。 |
| **住户 2 起**（`slot≥2`） | `home-agent:<家 id>:<住户序号>` | 这几支没有旧记录可沿用；带上序号，同一个家的两支才各有各的键（不然第二支会**重放**第一支的记录）。 |

（binding / credential / direct 三把键同款：`home-binding:<家 id>[:<序号>]` …）

**凭据的键还多一维世界**：`<世界摘要>/<agent_id>.token`（住在**家之外**的机器级目录，0600）。
为什么：**同一个 `agent_id` 在两个世界里是两条互不相干的事实** —— 只按身份分条会让它们撞在同一个文件上。

### 老家的形状（一个家一支）怎么变成住户

2026-10-01 以前的家是"一支一个 `<家>/env`"。**第一次 `up` 会自动迁**（幂等，重跑不会重复搬）：

| 老家的样子 | 发生什么 | 读数会说什么 |
|---|---|---|
| 有 `home_id`（第三刀之后的家） | `<家>/env` **整份迁到** `<家>/agents/<那支>/`；`home.conf` 的 `agent_id` / `room_id` 让位给支级 `agent.conf` | 「住户化：环境根 … ⇒ …（住户 1：…；身份不变，世界里的记录照旧）」 |
| **没有 `home_id`**（更早的家） | 布置键换形状 ⇒ 世界里的那支是**旧的「世界级键」**建的 ⇒ 这个世界里会**另建一支 Agent**（旧那支留着不动）；旧环境**整份让位**到 `<家>/env.old-<旧 id>`（**不删**），模型绑定跟着带到新环境 | 「键从此按家取 ⇒ 这个家会在世界里**另建一支 Agent**（旧那支留着不动）」 |

两条纪律（**不半途改**）：

1. **旧那支还在跑 ⇒ 先 `down` 再 `up`**（搬环境不许在它跑着的时候做）；
2. **远端跑法没有主人凭据 ⇒ 当场停手**（本地一个字都不改）。

> 让位目录是**改名，不是删除** —— 旧那支的经历（`trace.ndjson` 等）还在盘上；确认不需要了再自己清。

### 换代码之后：**先重编，再开机**（`up` 不替你编）

`node home.js up` 只是**跑**仓库里的二进制（源码形态 = `target/release/celira-im.exe` +
`agent/target/release/*.exe`；发布形态 = `bin/`）。**它不编译**（指这两个 Rust 组件）。所以改了源码（特别是
**新增 migration**）之后，顺序必须是：

```powershell
node home.js down                                  # 二进制在跑时 Windows 会锁住文件，编不过
cargo build --release -p celira-im                 # im（迁移集是编译期嵌进二进制的）
cd agent && cargo build --release                  # Runtime 那几支
node home.js up
```

> **前端（client）是另一回事**：缺依赖/产物时 `up` 会**自己装、自己构建**（见「从 clone 到能用」）。
> 但它只保证"**有产物**"，不保证"**产物是最新的**"——**改了 client 源码**之后想看到新页面，
> 仍要自己 `cd client && npm run build`（或者删掉 `client/dist` 让 `up` 重来一次）。
> 这样有意：每次开机都白跑一次构建更糟。

`outputs/CORE_ALIGN_KNIFE_04_HOME_DRILL_REPORT.md`）：

1. **旧二进制只有旧迁移集**：那次 `up` 之后迁移账还是 20 条，因为 `celira-im.exe` 是
   前一天编的——migration 集由 `sqlx::migrate!("./migrations")` **编译期**嵌入；
2. **新增一个 `.sql` 不会让 cargo 重编**：`sqlx::migrate!` 只为**已存在**的迁移文件生成
   `include_str!`，新增文件不在旧的依赖图里 ⇒ `cargo build` 会报 `Finished` 却什么都没编。
   判据：`up` 之后先数一遍迁移账；不对就碰一下消费点（`im/server/src/adapters/sqlite/migration_store.rs`）
   再编。

### `node home.js backup`（升级/回退前那一步）
```powershell
node home.js down            # 先关机：运行中复制出来的库是"可能能用"，不是"能用"
node home.js backup          # 默认复制到 <家>-backup-<时间戳>；--to <目录> 换地方
```

- **它备的是整个家**（`im/`、`agents/`（每个住户的环境根）、`materials/`、配置…），只排除运行产物（`logs/`、进程号）。
  与仓库里那个 `tools/home_portability.py`（公共事实的离线备份/校验/恢复）**分工不同、互不取代**：
  那个管世界的公共事实，这条管**回退时要用的整个家**，而且它在**发布包里**（`python` 不是前提）。
- **两个前置条件是硬的**，不合格就**拒绝备份**（退出码 3，并告诉你先做什么）：
  ① 家里还有东西在跑（五个进程 ＋ 世界那个端口）；② 上次不是干净停的（`core.db` 旁还留着
  `-journal` / `-wal` / `-shm`）—— 遇到 ② 就开一次机让它自己收尾，再干净关一次。
- **逐文件双侧 sha256**（源与落地各算一次），清单 `BACKUP_MANIFEST.json` **最后写**：半成品没有清单，
  一眼看得出它不完整。目的地已存在时**绝不覆盖**。
- ⚠ **备份里有 `<家>/model_sources.json` ⇒ 它带着模型 key**（那台机器上的钥匙清单）。像对待
  `env/` 一样保管这份备份；清单本身只记路径/大小/sha256，**不含任何 key 原文**。

### 换一包：**停 → 换 → 起**（三条普通命令，谁来执行都行）

**判据一句话：换包是普通命令，不是子系统。** 部署目录就是**它自己的一个普通目录**（不是构建产物目录，
也不是指针/junction 链）：换包＝把这批文件整份换掉，回退＝把上一个包换回去。**机制不认识执行者** ——
你、一支 Agent（它有整机全权的命令行）、一个 `.cmd`，跑的都是同一组命令。

```powershell
# 0) 先构建一个包（**REPO-ONLY**：打包器 `scripts\make_release.ps1` 在仓库里，包里没有它）
.\scripts\make_release.ps1 -SkipPublish

# 1) 停：自己起的那份自己停（托盘菜单「退出（停止本机服务）」，或 node home.js down）
#    ⚠ **别只关窗口、别强杀 celira-app.exe**：那**不会**停服务 —— 世界与住户会变成孤儿继续跑。
#    2026-10-12 实测的后果链：孤儿 host 占着环境根的**写者锁** ⇒ 新壳起来后为同一支起的第二支
#    **拒绝启动、自己退出**（fail-closed 生效，所以没有双写者），而壳的日志照旧写「住户 X：started」
#    ⇒ 面板可能报「在跑」而其实没跑。要停服务就用上面那两条之一（`node home.js down` 用**包自己那份**）。
# 2) 换：**先建一个空目录、把 zip 解进去**，再整份换名 —— 不留旧版本的文件混进新版本
#    ⚠ 这个 zip **没有顶层目录**（条目就是 `bin/…`、`client-dist/…`、`home.js`…）⇒
#      **不能**"解到 `D:\` 再改名"：那会把整包平铺进 `D:\` 根上，而 `D:\celira-<版本>-<平台>`
#      根本不会出现。2026-10-12 真机实测（照旧写法做）：`bin/` `client-dist/` `docs/` `scripts/`
#      `home.js` `celira-app.exe` `VERSION` `APP_MANUAL.md` 八项平铺到了 `D:\` 根上，
#      而改名那一步报"`D:\celira-0.1.1-win-x64` 处不存在项"。
New-Item -ItemType Directory D:\celira-app-new | Out-Null
Expand-Archive dist-release\celira-0.1.1-win-x64.zip -DestinationPath D:\celira-app-new
Rename-Item D:\celira-app D:\celira-app-old          # 旧的整份留着 ＝ 回退点
Rename-Item D:\celira-app-new D:\celira-app
# 3) 起：双击 D:\celira-app\celira-app.exe
```

回退就是同样的三步镜像：**停 → 把两份换回来 → 起**（`D:\celira-app` 挪开，`celira-app-old` 改回名字）。

- **回退点就是上一个包**：包一直留着，所以不需要快照、不需要指针、不需要另造一份清单格式。
- **家一个字节都不动**：这支 Agent 的身份、经历、笔记在家里（`<家>/agents/<支>/`），与这一包无关 ——
  **升级 = 换包，家目录不动**（与上一节同一条判据）；升级前那一步 `node home.js backup` 照做。
- ⚠ **部署目录不要住在构建产物目录里**：打包器每次会整份重写它自己的输出目录
  （`dist-release\celira-<版本>-<平台>\`；那一行在 `scripts\make_release.ps1` 里，**REPO-ONLY**）。
  线上那份必须住在**它自己的目录**里。
- **想先试再换**：用**另一个家**起一份测试实例 —— 指别的家**只有一条路**：环境变量
  `CELIRA_HOME_DIR`（Windows：`$env:CELIRA_HOME_DIR='D:\celira-test-home'; node home.js up`；
  Linux 同款：`CELIRA_HOME_DIR=/srv/celira-test-home node home.js up`）。
  ⚠ **`up` 不收 `--home`**（真机实测：`[home_up] 不认识的参数：--home`，退出码 1）——`--home` 是
  **常驻件**在命令行里声明"我属于哪个家"用的那一格（`up` 起它们时会自己带上），`up` 与 `down`
  都不收它（`down.js` 里记着同一条读数）。指到哪儿就是哪个家：它自己挑没被占的口、铸自己的主人
  和自己的世界，**不带任何正式数据** ⇒ 那是测试数据，不是"这支 Agent 的第二份"。
  生产那一侧只在上面那三步里被换。
- **它有意不做**：不做更新器框架、不做版本协商、不做热加载、不做"运行中自替换"。正在跑的 exe 换不掉
  自己（Windows 锁着它），而且世界与住户是**壳**起的（"谁起的谁停"）⇒ **重启这一下必须有外面一只手，
  那只手就是壳**。
### 把一个家**重新奠基**（世界从头开始）

**什么时候用**：迁移治理允许丢弃旧开发数据的时候 —— 比如一次 schema-only 重建的
migration（不搬行、不提供升级桥、验收只认全新数据库 + 重复启动），或者这个世界已经
坏到你宁愿从头开始。

```powershell
node home.js down
node home.js backup          # **不是可选的**：重置之后就回不去了
Remove-Item <家>\im\core.db  # 世界的公共事实（房间/消息/事件/成员/绑定）全在里面
# 还要清掉"属于那个世界的身份"，否则 up 会拿一个新世界里不存在的 id 去办事：
#   <家>\home.conf 里的 human_id 一行（**人类身份仍是机器级的一格**）
#   每一个住户的身份（一支一份）：<家>\agents\<支>\identity.json
#   （2026-10-01 以前的老家：<家>\env\identity.json —— 下次 up 会先把它迁成住户 1）
#   支级配置里那一行也一并清：<家>\agents\<支>\agent.conf 的 room_id（世界没了它就没有指代）
cargo build --release        # im 的迁移集是**编译期**嵌进二进制的：不重编就还是旧迁移集
node home.js up              # 全新奠基：新 Home Identity、新 Human（token 只打印这一次）、
                             # 新 Agent、新值班室
```

- **为什么 home.conf 里那几行也要清**：`up` 的布置是"缺什么补什么"——`human_id` 还在就拿它去
  `issue-human-session`（新世界里没有这个人 ⇒ 直接失败）。**住户那一支**同理：`agent.conf` 里
  那个 `agent_id` / `room_id` 还在 ⇒ 它不会自建新的一支（那是"认领"那条路的前提）。
  这些都是**那个世界里的**事实，世界没了它们就没有指代。
- **`identity.json` 会怎样**：`up` 发现某个住户的环境根里没有 `identity.json` ⇒ 用**新的** agent id
  重新建环境。`trace.ndjson` / `facts.ndjson` 会被**清空**（它们是那个已经消失的世界的经历——新环境不该
  继承旧身份的历史；2026-09-27 实跑：12.3 MB / 446 KB → 归零后由新活动重新写起）；
  `notes/` 一篇不少、`manual.md` 与 `orientation.md` **逐字节没变**、`model_binding.json`
  不动（模型绑定还在那台机器上）。
- **判据**（2026-09-27 实跑一次）：`up` 的输出里 Human / Agent / 值班室三个 id 都是新的、
  Agent 的后端凭据按新身份另写一份；`up` 结尾的 `admission=ready`；`GET /health` 与
  `/ready` 都是 200；世界里只有刚奠基的那几条事实（那次是 1 个 Human、1 支 Agent、1 间值班室）。
- **代价如实说**：公共事实（消息/事件/房间）与执行端的轨迹随重置消失。丢掉的都能在那份
  备份里找到（它带 sha256 清单；注意它也带着模型 key，按 `env/` 同规格保管）。

### `node home.js up --agent <这支的 id>`（**给这一支**安家）

**什么时候用**：两支来路都行 —— ① 家不知道它是谁了（`home.conf` 丢了 / 被换了 / 从一份旧备份回来），
世界里它还在（客户端「我的 Agent」里看得到那个 id）；② 世界里**新**建了一支 Agent（客户端「添加 Agent」），
要在这台机器上给它安个家（**它才会回话**）。

```powershell
node home.js up --agent 2f1e8654-74be-4412-99ac-a7471d2db4a4
```

- **认领 ≠ 新建**：它不改世界里任何东西，只把这个家的身份对上那个已有的 id（读数写着
  「认领了世界里已有的 Agent：<名字>（<id>）—— 不新建身份」）；
- **判据是支级的**（2026-10-01 起）：问的是"**这一支**安没安家"，**不是**"这个家有没有主"——
  家里已经有别的住户**不挡路**，它成为**新的一支住户**（住户序号接着排）。
  同一个 id 再敲一次 ⇒ 只是**重跑那一支**（幂等），不会认领第二次；
- **值班室沿用已有的那间**：它与主人已经聊过的那间 direct room 会被沿用（不多开一间同名房）；
- **三条硬判据**，不合格就拒绝、**什么都不改**（退出码 4）：
  ① 那个 id 必须**是你的**（`GET /v1/agents` 只列你自己拥有的）—— 不在里面 ⇒ 拒绝（`not-owned`）；
  ② 它必须是 `active`（**撤销过的身份不许安家**，`not-active`）；
  ③ 问不到世界（连不上 / 回执读不懂）⇒ 拒绝（`unreachable`；写进支级配置的是这个家的身份，猜不得）。
- **"一个家只住一支"那条判据已经拿掉了**（2026-10-01，承 §8.0）：现在问的是"**这一支**安没安家"，
  家里已经有别的住户**不再拒绝**。
- `--agent` 后面**缺值/空值**是用法错（退出码 1）—— 绝不悄悄回落成"自建一个新身份"。

> **跨机那条仍是另一件事（如实登记）**：把**执行端接到远端世界**走的是 `up --im-endpoint`
> （见「世界在别处」那节）。同机第二支**已经可以**（本刀落地）。

开机之后浏览器打开 **http://localhost:5173**：那是 client（你说话的地方）。

**第一次要粘一次 token**（之后浏览器自己记着）。按实测（2026-09-18「前门翻正」之后，本机 Chrome）的**真实路径**走：

1. 打开 http://localhost:5173 —— 第一屏就是**登录页**（服务器地址 + token + 「**连接**」）。
   服务器地址**留空就是同源**（页面的 `/v1` 由开机那支静态服务转给你的服务端），家里不用填。
2. 把开机时打印的那支 token 粘进 token 输入框，点「**连接**」；
3. 连上就进**值班室**（默认落聊天首页）；
4. 之后浏览器自己记着这份凭据：再打开直接进聊天，不经过登录页。要改地址 / 换 token / 看连接状态：左边「我的」→ **设置** → **连接设置**。

（token 只用于本机直连你自己的服务端；它只存在这个浏览器里，不进任何文件。忘了/丢了：`node home.js up --token` 补发一支。）

## 出问题的时候看哪一行

**先记住一句话**：Agent（`agent_host`）把一切都写在 `logs/agents/<支>/host.out` 里，每一条都是稳定的一行或一节。
下面每一条"看哪行"都对应一个**固定字符串**，照着找就行。

> **一支一份**（2026-10-01 起）：一个家住多支 ⇒ 每支的宿主日志与账本在 `logs/agents/<支>/` 下，
> 找的时候**先认支**（`node home.js status` 会把每一支的日志路径打出来）。
> 老家形状（一个家一支、还没迁）仍是 `logs/host.out`。

### 1. Agent 没起来 / 一看就知道为什么

```bash
node home.js status          # 三个进程在不在 + Agent 这次开机跑过几次活动
tail -40 D:/celira-home/logs/agents/<支>/host.out # 自己说的原因
```

`logs/agents/<支>/host.out` 里的三节：

| 你会看到 | 什么意思 |
|---|---|
| `[state]` + `admission=ready` | 准入放行，Agent 可以开始 |
| `[state]` + `admission=paused(reason=…)` | 环境在**暂停**状态（上次有一步没写成功），Agent 不肯动 |
| `[state]` + `admission=unfinished(run=…)` | 有**未收尾的活动**（上次 Agent 跑到一半就没了），Agent 不肯动 |
| `[listening]` + `wake-channel=im-events` | Agent 在等唤醒了（这一行出现 = Agent 在线） |
| `[run]` + `run=… drives=… ending=…` | Agent 刚跑完一次活动（`ending=` 是那次怎么收的场） |
| `[exit]` + `reason=…` + `[next] …` | Agent**退出了**，`reason` 说明为什么、`[next]` 告诉你下一步敲哪条命令 |

### 2. 门铃断线（服务端没了 / 网络断了 / 凭据被撤）

铃是 Agent 的耳朵。**铃断了不等于 Agent 死了**——Agent 在重连。

| 你会看到 | 什么意思 / 做什么 |
|---|---|
| `home_status` 说 `[agent] 在等唤醒`，但**很久没有新的 `[run]`** | 铃在重连中。先看服务端在不在：`home_status` 的 `[im]` 那一行；服务端回来之后 Agent**自己**接上（重连也算一次唤醒，你会立刻看到一条新的 `[run]`） |
| `logs/agents/<支>/host.out` 出现 `[exit] reason=channel-lost` | 铃这条通道被终结了（不是网络抖动，是通道层面）。重启 Agent：`node home.js up` |
| `[exit] reason=credential-rejected` | Agent 的后端凭据被服务端拒了（被撤了或对不上）。**Agent 不会自己换凭据**——这是要你处理的事 |
| `[exit] reason=channel-limit-exceeded` | 同一个 Agent 的唤醒通道开太多了：先停掉别的宿主，再重开 |
| `[exit] reason=unexpected-media-type` / `unexpected-response` | `--im-endpoint` 指的不是 Celira 的 im 服务端（检查 `home.conf` 里的 `listen_addr`） |

退出码 `4` 就是这一族（唤醒通道被终结）。

### 3. 准入挡住（Agent 起来又立刻退了）

**只剩一种**：`admission=paused(reason=…)`。`unfinished` **不再挡住开机**（2026-09-26 改：
一段清醒被一段不清醒隔开就是两段），所以它不在这条里——见下面那条提示。

> **关机时 Agent 正跑着一次活动** ⇒ 环境里会留下一个**未收尾的活动**。`home_down` 会当场说出来
> （退出码 3），`home_status` 也会列着它。**你不需要为它做任何事**：下次 `node home.js up` 就开
> **新的一段**，旧的那一段留在历史里（要看它停在哪：`node home.js status`）。
> 「接着跑完同一段活动」那条路（`up --resume`）**已退役**——现在敲它会被当场告知这件事，
> 不会静默忽略、也不会被读成"没给这个参数"。

**环境被暂停（`admission=paused(reason=…)`）**——上一次有一步没写成功（`reason` 就是那一步）。
这种情况**先看清、再显式确认**：

```bash
# ① 先看清到底卡在哪（下面按 Linux 源码形态写；Windows 上同一件带 .exe 后缀、家是 D:/celira-home）
agent/target/release/environment_diagnose ~/celira-home/env <Agent 的 id>

# ② 看清之后显式确认（确认 = 解开拦住新活动的那道闸；它**不是**"事情已经修好了"）
agent/target/release/agent_host_acknowledge ~/celira-home/env --agent <Agent 的 id> --run <那个活动 id> --confirm

# ③ 再开机
node home.js up
```

`agent_host_acknowledge` 的退出码：`0` 确认成功 ／ `1` 参数错 ／ `2` 环境不可用 ／ `3` 需要你再看清
／ `4` **没有暂停可确认**（这一档是零写入——它不会假装做了什么）。

### 4. 端口被占（服务端起不来）

`home_up` 会说 `端口 8080 被别的进程占着`，并给你看是谁的命令（Windows 是
`netstat -ano | grep LISTENING`；Linux 是 `ss -ltnp` —— 别用 Linux 的 `netstat -ano`，
它没有 PID 列）。改端口最省事：
编辑 `D:/celira-home/home.conf` 里的 `listen_addr=127.0.0.1:<别的端口>`，再开机
（注意 client 是用 `CELIRA_IM_URL` 指向服务端的，`home_up` 会自动带上）。

**建新家时会自己避开**：默认口（`8080` / `5173` / `5190` / `5191`）如果已经被占着，
`node home.js up` 会往后挑一个空的、**写进这个家的 `home.conf`**，并打一行
`[布置] … 的默认口 N 被占着 ⇒ 这个家用 M`。已有的家**一个字都不改**（要改是你的事）。
（为什么在意这件事：端口是**机器级**的，两个家用同一组端口时，"这支进程是哪个家的"就分不出来。）

**两个端面之间也不会撞格**（2026-09-30 起）：避让是**整组一起算**的——一个口被占之后往后挑时，
**不会挑走另一个口空着的默认格，也不会和本组已经定下的口重复**。手工改 `home.conf` 时同理：
**两个端面的口别写成同一个**（写成同一个时，先绑上的那个占住，另一个会响亮地失败退出 ——
一个进程两个端面，**各绑各的**，所以另一个端面照旧服务）。

**端口上那个世界不是本家的**（两个家撞在同一组端口上时你会看到）：

| 你会看到 | 什么意思 / 做什么 |
|---|---|
| `[im] 端口 N 上的世界**不是本家的**（它认下本家的后端凭据，却说是别人的 Agent）——不动它、不认领` | 端口上跑的是**另一个家**的世界。给这个家换个口（`home.conf` 的 `listen_addr`）再开机；本家**不会**去动它 |
| `[im] 端口 N 上那支证明不了是本家的（本家的凭据它不认）——**不认领、不写账本**` | 判不了它是谁的（本家的凭据格可能正被别家占着）。这一档**不写账本**，接着往下走；若它其实是别家的世界，布置那一步会响亮失败 |

同一个道理也管关机：`node home.js down` 的端口收尾对**世界**那一支**证明得了才收** ——
证明不了就如实报 `证明不了是本家的：… ——不杀`，并把端口仍被占着说出来（退出码 4）。
**它绝不替你去停别家的世界。**

**⚠ 壳（打包形态）起的那份世界，`down` 收不掉 —— 这是今天的已知缺口**（2026-10-08 实测）：

```text
[im] 端口 8080 上那支不是我们的（pid 13092，属于 celira-im.exe（…\app\src-tauri\target\release\bin\celira-im.exe））——不杀
[im] ⚠ 端口 8080 仍被占着（不是我们这一支在听？）
```

app 打开时会自己把这个家的世界起起来，用的是**壳自己那份 sidecar**
（`app/src-tauri/target/<profile>/bin/celira-im.exe`），而认领判据认的是**仓根那份**
（`target/release/celira-im.exe`）⇒ 上面那条"证明得了才收"在这里**必然收不了**。
那一拒是**对的**（跨家误杀是这套编排里最大的爆炸半径，判据不为这一个场景放宽）；
代价是那份 sidecar 一直被锁着，**下一次 `tauri build` 会撞
`error: failed to remove file …bin\celira-im.exe`** —— 看着像构建坏了，其实是被占着。

处置：手动结束那支（Windows：`Get-Process celira-im | Stop-Process -Force`），或者跑
`cd client && npm run verify:ui:app` —— 它收尾时按**差集 ＋ 身份**（本家 im 端口上多出来的
＋ 可执行件在壳自己的 target 下 ＋ 名字是 celira-im）把**它自己起的那份**收掉，并保证
`down` 失败时**把它的原话打出来**（2026-10-08 加：原先那一步 `stdio: 'ignore'`，
失败被吞掉，孤儿一声不响地留到下一次编译才炸）。要放宽到"认壳那份 sidecar"是**另一件事**，
得单独裁 —— 别顺手改判据。

### 5. client（浏览器那个窗口）起不来

`home_up` 会说一句，并且**不影响 Agent 在线**。家里跑的是**生产页**（`client/dist` 的构建产物经
`scripts/serve_client.mjs` 托管），不是开发服务器——**两种形态都是这一个托管**（第六刀之前源码形态走
`vite preview`：同一件事两份实现，还少一句家事实 `--home`）。

**Linux（源码形态）**：缺依赖/产物时 `up` 会**自己装、自己构建**（见「从 clone 到能用」）；它失败时
读数写的是**哪一步、退出码与日志尾巴**（`logs/client.out`）。修好之后**重开一次** `node home.js up`
即可——已经装好/构建好的那一步会跳过。下面这条手动路（**Windows 走的就是这条**）：

```bash
cd <仓库根>/client && npm install && npm run build
# 托管那一步与发布形态同款（回仓库根，产物目录用源码形态的 client/dist）：
cd <仓库根> && node scripts/serve_client.mjs --dist client/dist --port 5173
# 浏览器开 http://localhost:5173

# 发布形态（解压 zip）没有 client 工程，直接用包里自带的产物：
node scripts/serve_client.mjs
```

（`/v1` 由 `scripts/serve_client.mjs` 代转给 im 服务端——**两种形态都是它**；页面口跟着 `home.conf`
的 `client_port` 走。`client/vite.config.ts` 里那份 `server.proxy` 只服务 `npm run dev`（改前端时的
热更新路），**产品那条路不经过它**。）

### 6. 「Agent 的处境」读不到：`already-open`

一个环境**同时只有一个写者**，而 Agent 的写资格是**一次活动**持有的（不是常驻）：

- Agent**正在跑一次活动**的那一拍 ⇒ `agent_host_status` 读不到（会写 `already-open`）。这不是故障；
  这时候看 `logs/agents/<支>/host.out` 最后一条 `[run]` 行——那才是"Agent 此刻在做什么"；
- Agent**空闲**（在等唤醒）⇒ 读得到，`home_status` 会把完整三节摆给你看（准入 + 每个活动 + `[next]`）。

`home_status` 自己会先试一次：读得到就摆出来，读不到就说"Agent 这一拍正忙着"并把日志指给你。

### 7. 浏览器里那页「运行状态」读不到：本机状态口未开

页面上的运行状态不是去问执行端进程，而是问**本机的只读状态口**——那是 `home.js` 的一个口，
读的是**同一份账本**（准入 / 活动收场 / `[next]`），所以它与 `node home.js status` 不会各说各话。

> **`up` 说门起来了 = 这一门真的在答本门的话**（2026-09-30 起）：判据不只看"端口上有人回话"，
> 还要**回执是本门的**（状态口认 `/healthz` 的 `{ok:true}`；模型配置门认 `/home-config` 那份三合一），
> **且这次拉起的那支进程还活着**。所以撞格时 `up` 会如实说
> `[config] 没起来（不影响 Agent 在线）：它退了（多半是端口被占）`，而不是照抄别人的回执当成功；
> `node home.js status` 同款：`[config] 端口 N 上有人（不是本脚本起的）`。

**它跟着家一起起、一起停**：`node home.js up` 会把**家的门**（读端面 = 这个状态口 ＋ 写端面 =
模型配置门）当作一件拉起来（起不来**不影响 Agent 在线**，只是那页没有读数）；`node home.js down`
会把它一起收掉；`node home.js status` 的 `[status]` / `[config]` 两行报它在不在，后面还有一行
`[doors]` 说明**这两个口是同一个进程的两个端面**。（单独敲的应急办法，一般用不上：）

```bash
node home.js doors      # 常驻；Ctrl-C 停；两个端面默认 http://127.0.0.1:5190 与 :5191
```

> **一个进程、两个端面**（2026-10-01 第六刀）：读端面（只读状态口）与写端面（模型配置门）从前
> 是**两个进程**，现在合成一个 —— 它们服务同一个读者（本机页面）、同一个寿命、同一句恢复话。
> **端面一条没合并**：两个端口、两张逐条列出的路由表、两套准入（读端面可绑远程 + 家钥匙，
> 写端面默认只本机）。一个端面绑不上（端口被占）**不会**把另一个拖下水。

- 端面**只有两个**：`GET /status`（本家读数）、`GET /healthz`（活着）。**只读**——没有写、
  没有凭据、没有 im 代理，也**不能**从这里重启 Agent。
- 它**默认只绑 `127.0.0.1`**（不出这台机器；要远程照看就绑非本机地址——那时它要家钥匙 + TLS，
  见下面的「跨机照看」）。读数只有 admission / 活动收场 / `[next]`，不含配置详情。
  它自己的环境是**白名单**：家里的凭据（模型 key / 后端凭据 / token）**一个字节都不进口子**。
- **本机模式（绑回环）里它只认本机来源**：`Host` 必须是回环地址，`Origin` 有也必须回环
  ——这一道挡的是 DNS rebinding（那种页面在浏览器眼里是同源的，只有 `Host` 认得出来）。
  正常路径**不受影响**：本机两种形态的页面都走同源代转，代转会把 `Host` 改写成回环
  （两种形态都是 `serve_client.mjs`，它显式设 `changeOrigin`）。
- 读数里还有**Agent 的经历**（最近几条：动作 / 轮次 / 状态 / 顺序号）。它走**白名单投影**：
  **没有正文、没有参数值**（Agent 说了什么、写在哪儿属于 Agent 的私有世界）——
  页面就是「Agent 的经历」那一面，只看得到 Agent 做过什么、结果是什么状态。
- 读数有**短 TTL（15 秒）**：口子开机先热一次，所以页面第一眼**不必**再等那 3~4 秒。
  命中缓存时页面会写「读数时刻 …（**缓存读数**，正在刷新…）」—— 时刻始终是**那次读数的时刻**，
  不会被说成当下（陈旧被标注了，就不算冒充）。
- Agent**正在跑一次活动**的那一拍，口子读不到（`already-open`）——与 `home_status` 是同一态，
  不是故障；页面会把「最近一次唤醒」那一行摆出来代替。
- 页面说「**本机状态口未开**」时**别当成"Agent 停了"**：那是**本机这个管家没在答话**。
  这两件事是分开的两句话，页面文案就是这么写的。先看 `logs/status.out` 的尾巴。
- 换端口：在 `home.conf` 里加一行 `status_port=5192`（**没有这一键也有默认值 `5190`**，
  老家里不用手改；⚠ 别填 `5191`——那是模型配置门的默认口）。**改完页面自己跟着走**——
  页面问的是**同源**的 `/home-status/*`，由当前形态的代理代转到那个端口：
  - **两种形态同款**：`home.js up` 起静态页时把 `status_port` 一起传给它（`--status-port`）——
    源码形态与发布形态走的是同一个托管，代转路由表也只有一份。

  ⇒ **没有"两边一起改"这回事了**（TASK_61 之前页面侧的地址是编死的常量，改端口要改前端源码；
  现在"口在哪"是运行期事实）。手动起静态页时要自己带上：`node scripts/serve_client.mjs … --status-port 5192`
  （不带给默认 `5190`）。

### 8. 开机没走完（退出码 4）：布置是**可重入**的，重跑就行

第一次开机要"布置"一个家：开你的身份、建 Agent、签发 Agent 的后端凭据、开值班室、建 Agent 的环境。
这一步**被打断过也没关系**——每一步都带幂等键，**再敲一次 `node home.js up` 会接着做完**：
已经建好的沿用它（读数里会明说「沿用上一次创建的——幂等重放」），缺的那步补上。

**同一个家的重跑**才是幂等的（2026-10-01 起：布置键**按家取**，见「世界在别处」那节）——换一台
机器、或换一个家目录，那是**另一个家**：它在这个世界里**各建各的**（各自的 Agent / 值班室 /
后端凭据，互不轮换），不会"沿用"第一个家的身份。

所以看到退出码 4（只起来了一部分）：**先看读数、再重跑**。

**一个例外要知道**：如果你**在 Agent 还在跑的时候**重跑 `up`，它**不会动 Agent 的凭据**——
读数会明说「已在跑（pid N）——凭据未动」。这是有意的：**换钥匙会撤销 Agent 手里那支**，
而 Agent 听门铃那条通道一旦被拒就**不会自己换**（要重启 Agent）。所以
**凭据的恢复路径只属于"Agent 不在跑"的场合**：真要重发一支，先 `node home.js down` 再 `up`。

```bash
node home.js up            # 直接重跑：能续的会续上，缺的会补
node home.js status        # 还差什么，读数会说（Agent 那半边的三节也在这里）
tail -40 D:/celira-home/logs/agents/<支>/host.out     # Agent 的原话
```

**唯一可能需要你搭一句的情形**（2026-09-25 起基本不会遇到了）：一台机器上两个家，**凭据不再
互相顶掉** —— 每个家那一份按 Agent 在那个世界的身份分条存在本地（见「凭据」那一节），环境变量只是
老路。**2026-10-01 起**，两个家接的是**同一个世界**时连身份与值班室也不互相沿用：布置键按家取，
各建各的（见「世界在别处」那节）。真正还要留意的只有**端口**：两个家各要各的（默认口一样的话，
"这支进程是哪个家的"就分不出来，见 §4）。

**两个家在同一台机器上**，各要各的端口：默认口一样的话，"这支进程是哪个家的"就分不出来
（可执行件路径也一模一样——同一份发布包）。建新家时会自动避开被占的默认口（见 §4）；
**已有的第二个家**请自己给 `home.conf` 改一组不撞的 `listen_addr` / `client_port` /
`status_port` / `config_port`，再开机。

**最后手段**（`up` 反复失败时；也是「换机器、没带凭据」那条死路的**出路二** —— 先试「换机器 / 换家：
一支 Agent 搬家」那一节的**出路一**（把凭据带过去），能走通就不用重签）。下面整段可以一次性粘进
PowerShell：**它不把任何 token 打到屏幕上**——每一步的结果都只进变量、最后一步直接写进你的用户环境变量。
⚠ **重签会撤销旧的凭据**：另一台机器上正在跑的那支住户会被踢下线 —— **先把那边的家 `node home.js down`，再跑这段**。

```powershell
$home = 'D:/celira-home'
$im   = '<仓库根>/target/release/celira-im.exe'   # 发布形态改成：<解压根>/bin/celira-im.exe
# im 的命令行子命令必须和它自己看同一个库/同一份媒体目录（少这三行它会去开默认路径下的另一个库）
$env:CELIRA_LISTEN_ADDR = '127.0.0.1:8080'
$env:CELIRA_DB_PATH     = "$home/im/core.db"
$env:CELIRA_MEDIA_ROOT  = "$home/im/media"

# ⚠ 先确认另一台机器上的家已经 down（重签会撤销旧凭据，那边正在跑的那支住户会被踢下线）
# home.conf 只留机器级事实：human_id 在这儿、home_id 也在这儿；**agent_id 在支级** agent.conf 里
$line  = Get-Content "$home/home.conf"
$hid   = ($line | Select-String '^human_id=(.+)$').Matches.Groups[1].Value
# 住户化的家：一个家可以多支，一支一份 agent.conf —— 把 <支> 换成要重签的那一支（目录名就是它的 id）
$agent = ((Get-Content "$home/agents/<支>/agent.conf") | Select-String '^agent_id=(.+)$').Matches.Groups[1].Value

$tok   = (& $im issue-human-session --human-id $hid | ConvertFrom-Json).token
$hdr   = @{ Authorization = 'Bearer ' + $tok }
$bind  = (Invoke-RestMethod -Headers $hdr -Uri "http://127.0.0.1:8080/v1/agents/$agent/backend-bindings").bindings[0].id
$cred  = (Invoke-RestMethod -Headers $hdr -Uri "http://127.0.0.1:8080/v1/agents/$agent/backend-bindings/$bind/credentials").credentials[0].id
# 换一支新的（声明替换掉现有那条），原文只在这一步交回；它**直接进环境变量**，不进屏幕
$new   = (Invoke-RestMethod -Method Post -Headers ($hdr + @{ 'Idempotency-Key' = 'manual-rotation' }) `
           -ContentType 'application/json' -Body (@{ replaces_credential_id = $cred } | ConvertTo-Json) `
           -Uri "http://127.0.0.1:8080/v1/agents/$agent/backend-bindings/$bind/credentials").token
[Environment]::SetEnvironmentVariable('CELIRA_IM_BACKEND_AUTH', $new, 'User')

node home.js up            # 再开一次：这次凭据属于本家，它会直接起
# 顺带：这一支会被**原文照搬**进按身份分条的本地存储（读数："收进按身份分条的本地存储（没有轮换）"）
```

## 给 Agent 装一台外部 server（MCP，TASK_43/45；2026-10-01 起**按支**）

Agent 的世界不止出厂内置的那几件（文件、笔记、im、web、Agent 的手）。市面上的 **MCP server** 也能装进来，
**一行一台**。

**手长在身体上 ⇒ 手是支级事实**（2026-10-01 第五刀）：声明写在**那一支自己的**
`<家>/agents/<支>/agent.conf` 里；`home.conf` 里那些是**家级默认**（这一支没写时跟它走）。

```text
# <家>/agents/<支>/agent.conf —— 这一支的手
mcp_browser=stdio:npx @playwright/mcp@latest --browser chrome
mcp_notes=stdio:D:/tools/some-server.exe,read-only
terminal=none
```

**三条规则（读数里会逐条说清来源，不用你去比对两个文件）**：

| 支级写了什么 | 这一支的手 |
|---|---|
| 任意 `mcp_<名>=…` 行 | **就是这些**（覆盖家级 —— 是覆盖不是合并） |
| `mcp=none` | **一只外部 server 都不要**（哪怕家级声明了一堆） |
| 都没写 | **跟家走**（`home.conf` 的 `mcp_*` —— 2026-10-01 之前的行为一字不变） |

`terminal=` 同款：支级 ⇒ 家级 ⇒ **平台默认**。⚠ **2026-10-14 起，平台默认是"不给手"**：
**要这只手只有一个说法——显式写 `terminal=full`**（不写就没有）；`terminal=none` 是"这一支明确不要"
（`full` 被家级给了、这一支要退掉时用它）。`terminal=full` 在没有终端臂的平台上仍装不进来，
读数会如实说。**这次缺省变更不会让老支掉东西**：

- `up` 开机时跑一次**一次性迁移**：升级前就住着的支（`agent.conf` 里**没有** `terminal=` 那一行）
  ⇒ 把它们在旧缺省下**本来就有**的 `full` **显式写进各自的 `agent.conf`**，并打一行
  `[terminal] 迁移：住户 <支> 在旧缺省下是「有手」⇒ 已把 terminal=full 显式写进它自己的 agent.conf`；
  要在读数里**看得出来**这是声明来的，来源就从"平台默认"变成"它自己的 agent.conf"。
- 迁完在 `home.conf` 里记一行 `terminal_default=migrated-2026-10-14`（**幂等键**：再开机什么都不做）。
- **此后新建的支吃新缺省（不给手）**——判据是那行家级标记，不是"这支跑过没有"（后者会把新建的支
  在第二次开机时也迁到 `full`，那是把一次性的历史补偿变成永久的新缺省）。
- 老家那一支（还没迁的住户，档写在 `home.conf` 里）**不动它的档**，只如实说一句该怎么办。

**要降档/给手**：直接改那一支 `agents/<支>/agent.conf` 里的 `terminal=` 那一行（或删掉它 ⇒ 回到
平台默认"不给手"），然后 `node home.js down --agent <支> && node home.js up --agent <支>`
（装配面是**起 Agent 那一刻**的事实，改了要重开才生效）。

```text
# 单支的家（与从前一样，不加"住户"前缀）
[mcp] 装了 1 台外部 server：browser（来自跟家走（home.conf））
# 多支的家：**点名是哪一支**，并说清来源
[mcp] 住户 3f2a…：装了 1 台外部 server：browser（来自它自己的 agent.conf）
[mcp] 住户 9c1b…：这一支不要外部 server（agent.conf 里写了 mcp=none）—— 家级那几台不带给它
[terminal] 住户 3f2a…：终端档 full（来自它自己的 agent.conf）
[terminal] 住户 9c1b…：这一支没有「终端」这只手（agent.conf 里写了 terminal=none）
[terminal] 平台默认不给「终端」这只手（2026-10-14 起）；要手就在它自己的 agent.conf 里写 terminal=full
```

- **键名里的 `<名>` 就是事实**：Agent 看到的动词叫 `<名>_<工具名>`（上例里是 `browser_browser_navigate`
  ——对面自己的前缀留着）。想短就换个 `<名>`（`mcp_pw=…` ⇒ `pw_browser_navigate`）。
- 等号右边与宿主旗标的形状**逐字同构**：`<transport>:<命令>`，可带 `,read-only`（你替这台背书
  「它不改外面的世界」）与 `,timeout=<秒>`。**命令里的空格不用转义**（整行值原样交给宿主）。
- **不给 `,read-only` 就是最严那档**（`unverifiable-write`）：它确实是写，但**没有同参只读复核可配**
  —— 调用断在半路时如实落进「效果不明」那一格，既不假装成功也不假装失败。
  （旧版手册里"要跑一次 `agent_host_acknowledge` 才解除"的说法，随未决效果门一起退役了。）
- **哪台机器上装得进来（平台缝）**：stdio 通道今天在 **Windows 与 Linux** 上有实现。
  别的平台（比如 macOS）上入口会**拒绝开启**这一档 ⇒ `up` **不把 `--mcp` 传给宿主**
  （**一行 `mcp_*` 不会把家弄停摆**：Agent 照旧起得来），并如实打一行
  `[mcp] 这台机器上没有 stdio MCP 通道（有实现的平台：Windows、Linux）：声明了 N 台…这次不带`；
  声明照旧留在配置里，换到有实现的机器上就生效。
- **`status` 一支一行里有"手"这一格**：`手 2 台（跟家走）` / `手 1 台（它自己的 agent.conf）` /
  `手 0 台（这一支不要外部 server）`，后面还有 `终端 没有（平台默认；要手就在它自己的 agent.conf 里写
  terminal=full）` / `终端 没有（它自己的声明）` / `终端 在场`。
  只给**名字与数量**，命令原文不上屏、不进状态口载荷。
- **装了不用一分钱不花**：子进程不起、清单不拉，直到自己去展开它。
- **编辑用记事本也行**（读端按行尾去 CR）。但**别用分号在一行里塞两台**：命令里分号常见，会撞。
- **装卸都要重开一次**：装配面是「起 Agent 那一刻」的事实 ⇒
  `node home.js down` + `node home.js up`。Agent**已经在跑**时改 `home.conf` 不会生效，
  `home_up` 会把这句话打出来（`[mcp] 声明了 … / ⚠ Agent 已经在跑`）。
- **`home_status` 的对账读数（TASK_45；2026-10-01 第五刀起**按支**）**：它把**这一支该有的手**
  （支级声明覆盖家级之后的结果）与**那支在跑的宿主的实际命令行**摆在一起读。四种读法：

  | 读数 | 意思 |
  |---|---|
  | `装了 2 台：a,b（在跑的那支与这一支该有的手一致）` | 这一支该有的与在跑的那支一样——现在生效的就是这两台（**支级覆盖之后**的结果，不是 `home.conf` 原文） |
  | `住户 <支>：这一支该装 3 台：a,b,c；在跑那支装的是 2 台：a,b——**不一致**` + 差集那两行 | 你改了手但**没重开**（或重开后失败）；差集说清哪台只在"这一支该有的手"里、哪台只在在跑那支里 |
  | `这一支该装 2 台：a,b（没在跑，无从对账）` | 这一支没在跑，只有配置可看 |
  | （这一支该有 0 台、在跑那支也 0 台时**这一行不出现**） | 这一支一台都没装 |

  对账读的是**在跑那支宿主的命令行**（不是 pid 文件、不是日志），所以它说的就是"此刻真的装着什么"。
- **出问题看哪里**：Agent 起不来通常是声明写错了（比如 `stdio:` 拼错、名字带怪字符）——
  入口会拒一次并把原因写在 `logs/agents/<支>/host.out` 的尾巴上，`home_up` 会把那个尾巴打出来。
  若 `home_status` 说"读到 Agent 在跑，但读不到那支宿主的命令行"，直接看 `logs/agents/<支>/host.out` 的 `[mcp]` 行
  （那是**起 Agent 那一下**写下的装配面原文）。

## 凭据：第一次怎么配（只说变量名）

家里**不放任何凭据**（`home.conf` 里没有，`logs/` 里没有）。两样都在**本机用户环境变量**里
（Windows「环境变量」里那个"用户变量"）： 

| 变量名 | 是什么 | 谁给 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 模型那一半：Agent**思考**用的（不在 = 开机报"缺凭据"，退出码 3） | 你自己去模型服务商开 |
| `CELIRA_IM_BACKEND_AUTH` | 通道那一半：Agent 在 im 上的后端凭据（门铃 + Agent 的 im 动词都用它）——**老路 / 手工路**：仍然被读，**不再被写** | 第一次开机会把凭据写进下面那份本地存储；环境变量只在老机器/手工场合用 |

**Agent 的后端凭据存在哪**（2026-09-25 起；**2026-10-01 起多一维世界**）：按「**世界 × 那个世界的
身份**」分条的本地存储 —— Windows `%LOCALAPPDATA%\Celira\credentials\<世界摘要>\<Agent 的 id>.token`，
别的平台 `~/.config/celira/credentials/`（`CELIRA_CREDENTIALS_DIR` 可覆盖）。

- 为什么按身份分条：这份事实的作用域是「**Agent × 那个世界**」，而环境变量是**机器级的一个格子**
  —— 同一台机器上两个家会互相顶掉对方那一份。
- 为什么还要**世界那一维**：同一个 `agent_id` 在**两个世界里是两条互不相干的事实** ——
  只按身份分条会让它们撞在同一个文件上（一台机器两支 Agent、分别接两个世界，就是这种情况）。
  世界那一维是**世界地址的稳定摘要**（同一个世界每次一样；**不含凭据**）。
- 为什么**不在家目录里**：它的作用域是"这台机器上的这一支"，而升级/回退/备份的正规动作就是**整份
  复制家目录** ⇒ 一份活凭据一旦进家，每份备份都会携带一份活凭据。所以它住在**家之外**。
  （**如实补一句**：家里**并非一份凭据都没有** —— `<家>/model_sources.json` 是**模型**那一半的
  钥匙清单，含明文 `api_key`（见下面「模型配置」那一节，也正因如此 `home.js backup` 会把它一起
  备走并在读数里点名）。两类凭据分开：后端凭据（进世界）在家外，模型 key（进模型供应商）在家里。）
- **老家会自动搬过来，不换钥匙**：如果你机器上还有 `CELIRA_IM_BACKEND_AUTH`，下一次
  `node home.js up` 会把**原文照搬**进那份存储（读数写着"已把 … 收进按身份分条的本地存储
  （**没有轮换**）"），环境变量原样留着不动。

**也可以不碰环境变量**：在浏览器里「设置 → 模型配置」填一遍（端点 / 密钥 / 模型名 / 上下文长度），
它写进本机那两个文件（**清单** `<家>/model_sources.json` = 这台机器上有哪些钥匙；
**绑定** `<家>/agents/<支>/model_binding.json` = **这一支**用哪一条；明文——暴露面与环境变量同级）。
之后**开机不再要求 `DEEPSEEK_API_KEY`**，改配置也不用重启：Agent**下一次活动**就用新的。

> ⚠ **两路只能走一路**。绑定了清单里的一条时，Agent 的进程里**不许**再出现任何模型来源
> （`DEEPSEEK_API_KEY` / `CELIRA_MODEL_API_KEY` / `--model-endpoint` 等）——两边同时说话 Agent 会
> **拒绝启动**，并告诉你到底是哪两个在打架。想换回环境变量那一路：在页面里「解除绑定」，
> 或者 `node home.js down` 之后删掉那个绑定文件。

- 配 `DEEPSEEK_API_KEY`：`home_up` 会告诉我们缺哪一样；配好之后不用改任何文件，重新开机即可。
- 换机器 / 换家：把 `DEEPSEEK_API_KEY` 配到新机器。
  ⚠ **这句话只对「换家 = 新一支」成立**（新家布置键按家取 ⇒ 世界里**另建一支** Agent，后端凭据由
  那台机器的第一次开机**重新签发**；凭据按「世界 × 身份」分条存在本机，不随家目录走 —— 这也正是
  "家目录里没有凭据"的好处）。
  **「同一支」搬到没带凭据的新机器**是另一回事：今天会撞 `409 backend_binding_exists` 停手
  （读数会说清两条出路：把凭据带过去 / 按「最后手段」重签；CLI **只指路、不代跑**）——搬法与边界见
  「换机器 / 换家：一支 Agent 搬家」那一节。
- 脚本**从不**把凭据写进文件、写进命令行参数、写进日志：只用变量名读、只注入子进程的环境。

## 退出码一张表（每个命令都在说"为什么"）

**家的命令**（`up` / `status` / `down` 三支 ＋ `backup`）：

| 码 | `home_up` | `home_status` | `home_down` |
|---|---|---|---|
| 0 | 家亮着（读数在下面；**每一支住户都在跑**） | 家亮着（三个都在 ＋ 每一支都在） | 全停了（或本来就没跑）；**只停一支时** = 这一支停了、别的照旧 |
| 1 | 用法错 | **有东西没亮**（im / Agent / client 有一个没在跑——读数说是哪一个） | 用法错 |
| 2 | 环境不可用（缺可执行件 / 端口被占 / 家目录写不进去；**远端跑法**：世界不可达 / 凭据被拒 / 世界里没有可认领的身份 / 这一次还需要主人凭据——见「世界在别处」那节） | 环境不可用（没有这个家 / 还没布置过） | 家目录不可用 |
| 3 | 需要你动手（缺 `DEEPSEEK_API_KEY`） | **透传 Agent 那半边**（`agent_host_status`）：需要你看一眼（等待中 / 未收尾 / 已暂停） | 停好了，但**Agent 当时正跑着被硬停** ⇒ 环境里留下一个未收尾的活动（**不挡开机**：下次 up 开新的一段，见 §3） |
| 4 | 只起来了一部分（读数指到日志）——**布置是幂等的，重跑即续**，见 §8 | **透传**：唤醒通道被终结 | 有进程不肯退 |

> **多支之后读这张表的两处**：① `home_up` 的 `4` 现在是"**有住户没起来**"（读数会点名是哪一支、
> 日志在哪）；② `home_down` 带 `--agent` 时**只判这一支**（别的住户与三个常驻件不参与判据），
> 而**认不出目标住户**是 `1`（用法错）—— 绝不"静默什么都不停"。

> **`home_up` 那一列不把前端算进来**：前端（client）装依赖/构建失败时，读数会明说哪一步、退出码、
> 日志尾巴，但**退出码照旧按世界与 Agent 判** —— 沿用「client 不影响 Agent 在线」这条既有判据
> （2026-09-30 起 Linux 源码形态会自己装前端，见「从 clone 到能用」）。

> **`home_backup` 那一列**（同族语义，四个码都用得上）：`0` 备份成了（读数给文件数/字节数与清单路径）；
> `1` **用法错**（`--to` 缺值 / 认不得的参数 / 目的地在家里面）；`2` 环境不可用（没有这个家 /
> **目的地已存在**（绝不覆盖））；`3` **需要你动手**（还有东西在跑 ⇒ 先 `down`；上次不是干净停的 ⇒
> 先开一次机让它收尾再干净关一次）；`4` 复制途中失败（报了是哪个文件，目的地留着半成品**没有清单**）。

> **`home_status` 那一列两句要记住的**：① 它的 `1` **只有"有东西没亮"这一种含义**——
> `home_status` **不解析旗标**（除了 `--serve` 那条另路），所以**没有"用法错返 1"那条路径**；
> ② 它的 `3`／`4`／`5` 不是它自己的判断，是**把 `agent_host_status`（Agent 那半边）的码原样透传**过来
> （只在"别的什么都没缺"时才透传；`5` = 模型凭据不可用，本表没给 5 那一行是因为家的三条命令自己不用它）。
> ⇒ **读这张表要按列读**：同一个数字在不同命令下说的是各自那件事（`1` 在 `home_up` 是用法错、
> 在 `home_status` 是"有东西没亮"）。

**关于关机**：Agent 空闲时关机最干净。如果你在 Agent**正跑着一次活动**（浏览器发消息之后那几十秒）的时候关机，
环境里会留下一个**未收尾的活动**——`home_down` 会当场告诉你（退出码 3），**但它不挡开机**：
下次 `node home.js up` 就开新的一段，旧的那一段留在历史里（见 §3 那条提示）。数据一个字都不会丢。

**Agent 的那些命令**（同一个家族，同一套读法）：

| 码 | `agent_host`（Agent 本人） | `agent_host_status`（只读看状态） | `agent_host_acknowledge`（显式确认） |
|---|---|---|---|
| 0 | 打印帮助后正常退出 | 全部收场（无需动作） | 确认成功 |
| 1 | 参数错 | 参数错 | 参数错 |
| 2 | 环境不可用（打不开 / 身份不符 / 已有写者） | 环境不可用 / 读不出来 | 环境不可用 |
| 3 | 需要你动手（**已暂停**） | 需要你看一眼（等待中 / 未收尾 / 已暂停） | 环境在暂停，但缺参数（需看清再确认） |
| 4 | 唤醒通道被终结 | — | **没有暂停可确认**（零写入） |
| 5 | 模型凭据不可用 | — | — |

**`agent_run`（手动跑一次活动）**：`0` 主体自己收场（**不是**任务完成证明）／`1` 参数错／
`2` 环境不可用／`3` 准入拒绝／`4` 启动被拒（资料根与授权）／`5` 服务凭据不可用／
`6` 保存未完整确认／`7` 系统终止（模型失败 / 结果无法确认 / 轮次用尽 / 取消 / 崩溃）／
`9` 停在等待（环境里留下一个未收尾的活动）。

## 跨机照看（另一台机器上的家）

Agent 搬去另一台机器（B 机）之后，你在这台机器（A 机）的浏览器里照样能看 Agent 的处境、改 Agent 的
模型配置 —— 前提是 B 机上的家口**开到网上**，并且你手里有 B 机发给你的**一把家钥匙**。

三件事，按这个顺序做（都在 **B 机**上）：

**① 发一把家钥匙**（决定"谁能进这台机器"）：

```powershell
node home.js issue-home-key
```

- 钥匙**只打印这一次**（`[home-key]` 那一行）；家里只留它的摘要（`<家>/home_key.sha256`）。
- 把那一串**抄进 A 机的浏览器**（下一步），家里不会再有第二份原文可查。
- **重跑这条命令 = 换一把新的**：旧钥匙**下一个请求就失效**（补救就是它 —— 钥匙泄了，
  重跑一次，所有已配的连接立刻断）。

**② 把家口开到网上**（B 机的 `home.conf` 里加这四行）：

```text
status_bind=0.0.0.0        ← 状态口（只读读数）绑到哪
config_bind=0.0.0.0        ← 模型配置门（能改配置）绑到哪
tls_cert=D:/certs/home.pem ← 证书（PEM）
tls_key=D:/certs/home.key  ← 私钥（PEM）
```

- **绑非本机地址 = 远程模式**：进门要家钥匙、且必须走 TLS。三条 fail-closed：
  没有钥匙摘要 ⇒ 拒绝启动；没有证书/私钥（或路径读不到）⇒ 拒绝启动；起不来的原因会
  当面说清缺什么。
- **证书自备**（我们不内置 ACME）：自签或 `mkcert` 都行；自签的证书浏览器第一次会拦，
  在浏览器里直接打开一次 `https://<地址>:<状态口>/healthz` 把它放行即可（**浏览器不认
  证书时，页面上的表现与"连不上"是同一句人话** —— 那句话里两种可能都写着）。
  想要**自动**证书：自己跑一个 caddy 让它签发，然后把它签出来的那两个文件路径
  （`*.crt` / `*.key`）填进上面的 `tls_cert` / `tls_key`。
- **不写反代姿势**：把钥匙注入在反代那一层，等于让口子的钥匙落在反代配置里 —— 那是坑，
  别那么干（要远程就按上面这套：口子自己带钥匙 + TLS）。
- 绑 `0.0.0.0` 时**本机也照旧能连**（A=B 机的情况走 `https://127.0.0.1:<端口>` + 钥匙）；
  绑某一个具体网卡地址时，本机请用那个地址。
- 改完 `home.conf` 重启那两个端面：`node home.js down` 再 `node home.js up`（或单独起：
  `node home.js doors`）。

**③ 在 A 机的浏览器里把它添进来**：「设置 → **家**」→ 「添加家」，填：

| 填什么 | 例子 |
|---|---|
| 名字 | `书房那台`（列表与 Agent 的主页上显示的就是它） |
| 家地址 | `https://192.168.1.20`（没写 `https://` 会自动补上） |
| 状态端口 / 配置端口 | 默认 `5190` / `5191`（改过 `home.conf` 就照改） |
| 家钥匙 | ① 里那一串（只存在这个浏览器里） |

添好之后：那一行会如实回答它上面住的是谁（**连不上、钥匙不对、证书没认** 各自一句人话，
不会只说"连接失败"）；Agent 的主页（运行 / 活动记录 / 模型三个房间）也会开始读**那台机器**的数据。

**要切回本机模式**（不再远程照看，回到"只在这台机器上用"）：把 ② 加的那四行
（`status_bind` / `config_bind` / `tls_cert` / `tls_key`）**删掉或改回 `127.0.0.1`**，再重启
那两个端面（`node home.js down` 再 `node home.js up`；或单独重启 `node home.js doors`）。

- **本机模式不看钥匙、也不看证书**：绑定是回环地址时，两个口**根本不读**它们（`resolveLaunch`
  直接判成 `local`，见 `scripts/home/home-key.js`）⇒ 摘要文件 `<家>/home_key.sha256` 与那两个
  证书文件**可以原样留着**，它们不参与任何判断；留着（以后想再开远程时省一步）或删掉都行。
- **想作废那把钥匙**（不再让任何已发出的钥匙能进这台机器）：重跑 `node home.js issue-home-key`
  换一把新的 —— 旧钥匙**下一个请求就失效**（换的就是它，没有"让旧会话过期"这回事）。
  要更彻底（连摘要都不留）：删掉 `<家>/home_key.sha256`；此后若再把口子绑到非本机地址，
  启动会**拒绝**（没有钥匙摘要 ⇒ fail-closed），得先重发一把。
- **A 机浏览器里那条远程家条目**：切回本机模式后它连不上了，页面会如实说「连不上这台机器」
  （地址/端口、证书两种可能各有一句人话）；不想留着就在「设置 → 家」里**删掉**它。
  **本机那条**（预置的第一条，走同源代转、没有钥匙、也没有"删除"）不受影响 —— 照旧能看
  Agent 的处境与模型配置。

**两句话要记住**：

- **家钥匙 ≠ 模型 key**。家钥匙是"进这台机器"的凭证（按机器发、可换）；模型 key 是模型
  供应商的钥匙（在「设置 → 模型配置」里）。两把不同的东西，谁也不替谁。
- **本机那条不用配**。「家」列表里第一条「本机」是预置的：它走同源代转，没有钥匙 ——
  行为与你没开远程时**一模一样**。

**这一刀没有做的**（别等的功能）：多把钥匙并存 / 钥匙轮换接口 / 限速 / 来源白名单 /
Agent 级授权表 / 反代姿势。钥匙只有一把、换就是换（重跑 ① 那条命令）。

`issue-home-key` 的退出码沿用家那一套：`0` 成功 ／ `1` 用法错 ／ `2` 家目录写不进去。

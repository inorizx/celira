# Celira —— 第一次用（桌面版）

这个包里有一个能双击的程序：**`celira-app.exe`**。它不是一个网页的快捷方式 —— 世界、执行端、
页面都在这个包里，**不需要装 Node.js、不需要命令行、不需要联网到别处**。

---

## 四步

### 1. 解压，双击 `celira-app.exe`

第一次打开时它会问你一件事：**「你自己的世界」** —— 选「在这台机器上开一个」。
它会在这台机器上开一个属于你的世界（IM 服务端 ＋ 页面 ＋ 两道只读/配置门），并铸一位主人
（显示名默认取这台机器的用户名），然后直接进到「消息」页。

> 这个家默认在 `D:\celira-home`（Windows）。它是一个**普通目录**：里面是你的世界历史、Agent 的
> 环境与笔记。删掉这个目录 = 从零开始；备份它 = 备份你和她的一切。

### 2. 建一支 Agent：左边「我的 Agent」→「创建第一个 Agent」

填一个名字，点「创建」。它会做两件事：在世界里建这支 Agent，**并自动把它接到这台机器上**
（建好它的环境、发凭据、把宿主进程起起来）。创建完那一行会写「已经在它这台机器上接好了，进程
也起来了」。

> **它要能回话，得有模型钥匙。** 面板上写着这句实话：这台机器上还没配好模型的话，接上了也暂时
> 不会回话。两种给法：
> - **这台机器的用户环境变量里有 `DEEPSEEK_API_KEY`** ⇒ 不用配，直接用；
> - 否则去「我的执行端 → 那台机器 → 模型」那一间，点「去配置模型」加一条（钥匙只留在这台机器上，
>   不上传、不回浏览器）。

### 3. 开一间房：左边「消息」→「新建会话」→ 点她 →「发起直聊」

一间房 = 一段关系：你和同一支 Agent **只有一间**私人房，开过一次就一直在。

### 4. 说一句话，按回车

她会自己醒过来、想一次、把话写回来。你不需要按"发送"以外的任何东西 —— 唤醒是自动的。

## 日常怎么用

| 想干什么 | 去哪 |
|---|---|
| 和她说话 | 「消息」→ 点左边那一间 |
| 看她/管她 | 「我的 Agent」→ 点那一行（公开资料、状态、模型） |
| 看这台机器在跑什么 | 「我的执行端」→ 运行 / 活动 / 模型 三间 |
| 让它停 / 退出 | 面板上的「全部停止」；点窗口的 × 只是**收起**（app 留在托盘，本机服务照旧跑），真退出在托盘菜单里 |
| 加联系人 / 建群 | 「联系人」／「新建会话」里的「创建群聊」 |

## 换一个新版本（更新）

**你装的东西和你的东西是两个地方**，所以更新只动前者：

| | 在哪 | 更新会碰它吗 |
|---|---|---|
| 程序（这个 app、世界、执行端） | 你解压出来的那个文件夹 | **会** —— 换来换去的就是它 |
| **你的东西**（世界历史、Agent 的环境与笔记、你和她的关系） | **家**（Windows 默认 `D:\celira-home`，app 第一次运行时建的） | **不会，一个字节都不动** |

怎么更新（今天）——**先问一句有没有新版，再换**：

```powershell
.\scripts\update.ps1 -Check     # 只问：最新是哪一版、产物在哪、这一版的 sha256
.\scripts\update.ps1            # 换：下载 → 校 sha256 → 停家 → 备份 → 解压到新文件夹
```

它问的是 GitHub Releases（读 atom 与那一版的附件页，**不用登录、不耗 API 额度、不需要 gh**）。
不放心就先看它要干什么：`.\scripts\update.ps1 -DryRun`。

换的时候顺序是硬的，不是流程洁癖：

1. **下载并校字节**（渠道给的 sha256 对不上就停；渠道没给哈希时也停，除非你明说 `-AllowUnverified`）；
2. **关掉 app**：托盘图标 → 退出（点窗口的 × 只是收起，服务照旧跑）；
3. `node home.js down` —— 停这个家的世界与住户；
4. `node home.js backup` —— **在新版本启动之前**。迁移只有上行：新版本的 im 服务端一旦落过 pending
   迁移，旧二进制会因为库里有一条它不认识的迁移而**拒绝启动** ⇒ **回退要把家换回去，不是只换文件夹**；
5. 解压到**一个新的文件夹**（绝不覆盖正在替换的那一份 —— 它也是回退的那一份）；
6. 停在这里：双击新文件夹里的 `celira-app.exe`。它读的还是同一个家，所以你还是你、她还是她、历史都在；
   旧的文件夹留着（出事时双击它就能回去），也可以删掉 —— **删文件夹不等于删数据**。

手边没有这个脚本时，手动那条就是上面去掉校验与备份的一半 —— **别省第 4 步**。

⚠ 今天**还没有**"app 自己发现新版本、点一下就更新"那一格：`-Check` 与 `update.ps1` 是命令行这一侧
（`scripts\update.ps1`，包里带的那份从 0.1.3 起）；app 里没有更新入口。
**"我在跑哪一版"在 app 里有**：设置 → 关于（读包里那份 `VERSION`；源码形态下它如实说那个号是编译期的）。

## 出问题了看哪里

- 这个 app 的日志：`%LOCALAPPDATA%\com.celira.desktop\logs\Celira.log`（发布版也写日志）；
- 本机世界的日志：`<家>\logs\im.out`；Agent 宿主的日志：`<家>\logs\agents\<支>\host.out`；
- 命令行形态（可选，本包也带了）：`node home.js status` 只读处境，`node home.js up` / `down` 起停。
  命令行**需要 Node.js**；上面四步不需要。

## 这个包和那个命令行形态的关系

同一个版本号、同一套二进制：`bin\` 里是世界（`celira-im`）与执行端（`agent_host*` / `agent_run`），
`celira-app.exe` 是它们的总控台（它启动并看着它们），`home.js` ＋ `scripts\` 是命令行那条路。
开发者或想自己部署的人，用拆分包（core / home / client）与 `scripts\HOME_MANUAL.md`。
